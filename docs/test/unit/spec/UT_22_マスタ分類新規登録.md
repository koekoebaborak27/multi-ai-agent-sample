# 単体テスト仕様書: マスタ分類新規登録（MST-08 / MST-09）

## 1. テスト対象
- 対象機能: マスタ分類新規登録（MST-08）・マスタ分類確認画面（MST-09・新規登録モード）

- 対象ファイル:

- 関連設計書: [`docs/specs/02_basic-design/master/22_マスタ分類新規登録.md`](../../../specs/02_basic-design/master/22_マスタ分類新規登録.md)、[`docs/specs/02_basic-design/master/00_共通.md`](../../../specs/02_basic-design/master/00_共通.md)（§3 権限）

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-010の権限確認用）
- 権限: 「新規登録」画面へのアクセスと登録実行はADMIN/OPERATORロールに限る（`canWrite`）。VIEWERロールは画面を直接開いても分類一覧へリダイレクトされる。
- 事前DB状態:
  - `MasterCategory` に「分類名重複確認用」という名称の分類が1件登録済みであること（TC-002・TC-003で使用）。
  - TC-004・TC-005で使う30文字ちょうどの分類名・31文字の分類名は事前に重複しないことを確認しておく。
- 使用するテストデータ:
  - 通常登録用の分類名（例: `テスト分類A`）
  - 前後に半角スペースを含む分類名（例: ` 空白除去確認分類 `）
  - 30文字ちょうどの分類名、31文字の分類名
  - 既存分類と同名の分類名（`分類名重複確認用`）

## 3. テスト観点
- 正常系: 入力→確認→実行で登録が完了し、詳細画面へ遷移して完了メッセージが表示される
- 異常系: 確認画面遷移時の名称重複、実行時点の名称重複、未入力
- 境界値: 分類名30文字（登録可）／31文字（拒否）
- 権限: VIEWERロールでの画面アクセス制御
- DB更新: `MasterCategory` への `name` / `createdBy` / `updatedBy` の登録
- 画面表示: 確認画面の表示項目、「入力内容を修正」での入力値保持、「キャンセル」での破棄

## 7. 補足
- TC-003（実行時点の重複）は、確認画面表示後に別の利用者が同名で登録した状況をブラウザの複数タブ操作では再現しにくいため、確認画面を表示したままDBを直接操作して重複行を挿入する手順とした。
- マスタ分類コードは登録後に自動採番されるため、本仕様書のテストケースでは分類名のみを確認対象とする（採番されたコードの表示確認はマスタ分類詳細（UT_21）で行う）。
