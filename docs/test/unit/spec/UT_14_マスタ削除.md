# 単体テスト仕様書: マスタ削除（MST-04 削除確認ダイアログ）

## 1. テスト対象
- 対象機能: マスタ削除（MST-04の削除確認ダイアログ）
- 対象画面またはAPI: `/master/{masterId}`（マスタ詳細画面の「削除」ダイアログ）
- 対象ファイル:
  - `src/modules/master/ui/master-delete-dialog.tsx`
  - `src/modules/master/actions.ts`（`deleteMasterAction`）
  - `src/modules/master/service.ts`（`deleteMaster`）
  - `src/modules/master/repository.ts`（`deleteMasterIfUnchanged`）
  - `src/modules/master/validation.ts`（`deleteMasterSchema`）
  - `src/shared/constants/messages.ts`（`MESSAGES.common.deleted`）
- 関連DBテーブル: `Master`
- 関連設計書: [`docs/specs/02_basic-design/master/14_マスタ削除.md`](../../../specs/02_basic-design/master/14_マスタ削除.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）
- 権限: 削除ボタン自体はADMIN/OPERATORロールにのみ表示される（`UT_12_マスタ詳細.md` TC-003で確認済みのため、本仕様書では削除の実行結果を対象とする）。
- 事前DB状態:
  - 削除対象マスタが1件登録済み（TC-001用）。
- 使用するテストデータ:
  - 削除対象マスタのマスタ分類・コード・内容

## 3. テスト観点
- 正常系: マスタ削除の完了
- 異常系: 同時更新エラー、確認ダイアログ表示後に別の利用者が先に削除済みの場合（`MASTER_NOT_FOUND`）
- DB更新: 削除成功時に `Master` の対象行が物理削除されること、削除失敗時にDBが変化しないこと
- 画面表示: 削除確認ダイアログの表示項目、「キャンセル」でのダイアログを閉じる動作、削除完了トースト（一覧画面での「削除しました」表示）

## 7. 補足
- 削除ボタン自体の権限表示制御（ADMIN/OPERATORのみ表示）は、マスタ詳細（`UT_12_マスタ詳細.md` TC-003）で確認済みのため、本仕様書では削除の実行結果を対象とする。
- 「削除したマスタと同じマスタ分類・同じマスタコードで再登録できる」（設計書§12.6）は、TC-001で削除した後、同じ分類・同じコードで新規登録できることを別途マスタ新規登録（UT_11）のテストデータ準備の中で暗黙に確認しているため、本仕様書では独立したテストケースとしては設けない。
- TC-002・TC-003は、ダイアログ表示後に別の利用者が操作した状況をブラウザの複数タブ操作では再現しにくいため、ダイアログを表示したままDBを直接操作する手順とした。
