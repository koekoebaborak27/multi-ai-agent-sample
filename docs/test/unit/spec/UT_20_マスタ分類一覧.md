# 単体テスト仕様書: マスタ分類一覧（MST-06）

## 1. テスト対象
- 対象機能: マスタ分類一覧（MST-06）
- 対象画面またはAPI: `/master/categories`（マスタ分類一覧画面）
- 対象ファイル:
  - `src/app/(main)/master/categories/page.tsx`
  - `src/modules/master/ui/master-category-table.tsx`
  - `src/modules/master/ui/master-export-button.tsx`
  - `src/modules/master/service.ts`（`listCategories`）
  - `src/modules/master/repository.ts`（`listCategoriesAndCount`）
  - `src/shared/api/pagination.ts`（`parseListQuery`）
  - `src/shared/constants/roles.ts`（`canWrite`）
- 関連DBテーブル: `MasterCategory`
- 関連設計書: [`docs/specs/02_basic-design/master/20_マスタ分類一覧.md`](../../../specs/02_basic-design/master/20_マスタ分類一覧.md)、[`docs/specs/02_basic-design/master/00_共通.md`](../../../specs/02_basic-design/master/00_共通.md)（§00.3 権限）

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール、OPERATORロール、VIEWERロールの各ユーザーが必要（TC-006で使用）。OPERATOR/VIEWERロールのユーザーは `prisma/seed.ts` に用意されていないため、別途用意する。
- 権限: 本画面の閲覧自体はログインしていればロールを問わない。「新規登録」ボタンの表示のみADMIN/OPERATORロールに限定される（`canWrite`）。検索条件は無く、全ロールが常に全件を対象に閲覧する。
- 事前DB状態:
  - `MasterCategory` が3件以上登録済みで、分類コード（`id` の採番順）・分類名・登録マスタ件数がそれぞれ異なる値で判別できること（並び替え確認用）。
  - `env.PAGE_SIZE`（既定30件）を超える件数の `MasterCategory` が登録済み（ページング確認用。31件以上）。
  - TC-005（0件表示）の実行時点では `MasterCategory` が0件であること。
- 使用するテストデータ:
  - 分類コード・分類名・登録マスタ件数の大小関係が判別できる `MasterCategory` を3件以上（うち31件以上はページング確認用に用意する）

## 3. テスト観点
- 正常系: 初期表示（分類コード昇順・総件数とページ表示）、詳細リンクでの画面遷移
- 異常系: マスタ分類が0件のときの表示
- 境界値: ページングの「前へ」「次へ」ボタンの活性・非活性が切り替わる境界（`env.PAGE_SIZE` = 30件）
- 権限: 「新規登録」ボタンの表示制御（ADMIN/OPERATORのみ表示、VIEWERは非表示）
- DB更新: なし（本画面は一覧表示のみで、DBを更新する操作を持たない。CSV生成処理は [`30_CSVダウンロード.md`](../../../specs/02_basic-design/master/30_CSVダウンロード.md) の管轄のため対象外）
- 画面表示: 並び替え見出し（分類コード/分類名/登録マスタ件数）の昇順・降順切り替え、CSVダウンロードボタンの非活性理由表示

## 7. 補足
- CSVダウンロードの生成・ダウンロード完了自体は [`30_CSVダウンロード.md`](../../../specs/02_basic-design/master/30_CSVダウンロード.md) の管轄のため、本仕様書では非活性理由の表示制御のみを対象とする。
- `MASTER_EXPORT_MAX_ROWS`（10,000件）超過時の非活性理由表示は、事前準備件数が大きくローカル環境での再現コストが高いため、本仕様書のテストケースには含めていない（`MasterExportButton` の実装はマスタ検索一覧（UT_10）と共通のため、そちらで確認済みの挙動と同一）。
