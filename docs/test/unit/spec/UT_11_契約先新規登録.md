# 単体テスト仕様書: 契約先新規登録（PTY-02 / PTY-03）

## 1. テスト対象
- 対象機能: 契約先新規登録（PTY-02）・契約先確認画面（PTY-03・新規登録モード）
- 対象画面またはAPI: `/parties/new`（契約先新規登録画面）
- 対象ファイル:
  - `src/app/(main)/parties/new/page.tsx`
  - `src/modules/party/ui/party-create-form.tsx`
  - `src/modules/party/ui/party-form-fields.tsx`
  - `src/modules/party/ui/party-confirmation.tsx`
  - `src/modules/party/actions.ts`（`createPartyAction`）

  - `src/modules/party/repository.ts`（`create`）
  - `src/modules/party/validation.ts`（`createPartySchema`）
  - `src/shared/constants/roles.ts`（`canWrite`）
- 関連DBテーブル: `Party`、`MasterCategory`、`Master`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/11_契約先新規登録.md`](../../../specs/02_basic-design/party-contract/11_契約先新規登録.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-011の権限確認用）
- 権限: 「新規登録」画面へのアクセスと登録実行はADMIN/OPERATORロールに限る（`canWrite`）。VIEWERロールは画面を直接開いても元の一覧画面へリダイレクトされる。
- 事前DB状態:
  - `MasterCategory`（`CONTRACT_COMPANY_TYPE`）配下にマスタが1件以上登録済み。
  - 契約分類（`CONTRACT_TYPE`）配下のマスタIDを1件、契約先分類とは異なる分類コードのマスタIDとして用意する（TC-005用）。
  - TC-012用に `MasterCategory`（`CONTRACT_COMPANY_TYPE`）配下のマスタが0件の状態を一時的に作れること。
- 使用するテストデータ:
  - 契約先名称（例: `新規登録確認商事`）、契約先分類、連絡先（例: `03-1234-5678`）
  - 200文字ちょうど／201文字の名称、500文字ちょうど／501文字の連絡先

## 3. テスト観点
- 正常系: 入力→確認→実行で登録完了
- 異常系: 名称未入力、存在しない契約先分類マスタID、別の分類コード配下のマスタID
- 境界値: 名称200文字（登録可）／201文字（拒否）、連絡先500文字（登録可）／501文字（拒否）
- 権限: VIEWERロールでの画面アクセス制御
- DB更新: `Party` への `name` / `companyTypeMasterId` / `contactInfo` / `createdBy` / `updatedBy` の登録
- 画面表示: 確認画面の表示項目（新規登録モード）、「入力内容を修正」での入力値保持、「キャンセル」での破棄、契約先分類0件時の案内表示
