# 単体テスト仕様書: トップ画面（ダッシュボード）

## 1. テスト対象
- 対象機能: トップ画面（ダッシュボード）
- 対象画面またはAPI: `/`
- 対象ファイル: `src/app/(main)/page.tsx`
- 関連DBテーブル: 無し（このファイル自体はDBを直接更新しない）
- 関連設計書: [`README.md`](../../../../specs/02_basic-design/dashboard/README.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: ADMIN、OPERATOR、VIEWERの各ロール。
- 権限: 閲覧は全ロールに許可される。
- 事前DB状態: 特になし（お知らせカードの中身に必要なデータは`news`機能側の仕様書で用意する）。
- 使用するテストデータ: 無し。

## 3. テスト観点
- 正常系: 見出し・お知らせカードの入れ物の表示
- 権限: 未ログイン時のリダイレクト、全ロールでの閲覧
- 画面表示: レイアウトの構成要素
- エビデンス取得: 各ケースの画面をPNGで保存する

## 7. 補足
- お知らせカードの中身（並び順・カテゴリごとの色分け・「さらに表示」による追加取得・0件時の表示等）は、お知らせ機能のテスト仕様書（[`news/UT_10_トップ画面お知らせ表示.md`](../news/UT_10_トップ画面お知らせ表示.md)）でテストする。本仕様書はトップ画面固有の見出し・カードの入れ物・ログイン制御のみを対象とする。
- 未ログイン時のリダイレクト先の判定ロジック自体（`route-guard.ts`）は、ログイン画面のテスト仕様書（[`auth/UT_10_ログイン画面.md`](../auth/UT_10_ログイン画面.md)）で扱う。本仕様書ではトップ画面（`/`）を開いたときの結果のみを確認する。
