# 単体テスト仕様書: マスタ新規登録（MST-02 / MST-03）

## 1. テスト対象
- 対象機能: マスタ新規登録（MST-02）・マスタ確認画面（MST-03・新規登録モード）
- 対象画面またはAPI: `/master/new`（マスタ新規登録画面）
- 対象ファイル:
  - `src/app/(main)/master/new/page.tsx`
  - `src/modules/master/ui/master-create-form.tsx`
  - `src/modules/master/ui/master-confirmation.tsx`
  - `src/modules/master/actions.ts`（`createMasterAction`）
  - `src/modules/master/service.ts`（`createMaster` / `assertCategoryExists` / `assertMasterCodeAvailable`）
  - `src/modules/master/repository.ts`（`createMaster`）
  - `src/modules/master/validation.ts`（`createMasterSchema`）
  - `src/shared/constants/roles.ts`（`canWrite`）
- 関連DBテーブル: `Master`、`MasterCategory`
- 関連設計書: [`docs/specs/02_basic-design/master/11_マスタ新規登録.md`](../../../specs/02_basic-design/master/11_マスタ新規登録.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-011の権限確認用）
- 権限: 「新規登録」画面へのアクセスと登録実行はADMIN/OPERATORロールに限る（`canWrite`）。VIEWERロールは画面を直接開いても元の一覧へリダイレクトされる。
- 事前DB状態:
  - `MasterCategory` が1件以上登録済み（TC-001〜TC-010用の登録先分類）。
  - 登録先分類に、マスタコード `DUP0001` を持つマスタが1件登録済み（TC-003・TC-004で使用）。
  - TC-012用に `MasterCategory` が0件の状態を一時的に作れること。
- 使用するテストデータ:
  - 登録先の分類、マスタコード（例: `NEWCODE1`）、マスタ内容（例: `新規登録確認内容`）
  - 8文字ちょうど／9文字のマスタコード、30文字ちょうど／31文字のマスタ内容
  - 英小文字・日本語・許可されない記号を含むマスタコード

## 3. テスト観点
- 正常系: 入力→確認→実行で登録完了
- 異常系: 確認画面遷移時のコード重複、実行時点のコード重複、マスタ分類未選択、マスタコード形式エラー（英小文字・日本語・不正記号）
- 境界値: マスタコード8文字（登録可）／9文字（拒否）、マスタ内容30文字（登録可）／31文字（拒否）
- 権限: VIEWERロールでの画面アクセス制御
- DB更新: `Master` への `categoryId` / `code` / `content` / `createdBy` / `updatedBy` の登録
- 画面表示: 確認画面の表示項目（新規登録モード）、「入力内容を修正」での入力値保持、「キャンセル」での破棄、マスタ分類0件時の案内表示

## 7. 補足
- TC-004は、確認画面表示後に別の利用者が操作した状況をブラウザの複数タブ操作では再現しにくいため、確認画面を表示したままDBを直接操作する手順とした。
- TC-012はマスタ分類が0件の状態を一時的に作る必要があるため、テスト実行時に既存のマスタ分類・マスタを退避してから空にし、確認後に元の状態へ復元する。
