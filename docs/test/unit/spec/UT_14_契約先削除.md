# 単体テスト仕様書: 契約先削除（PTY-04 の削除確認ダイアログ）

## 1. テスト対象
- 対象機能: 契約先削除確認ダイアログ、削除条件（紐づく契約が無いこと）、削除時の競合
- 対象画面またはAPI: `/parties/{partyId}` 上の削除確認ダイアログ
- 対象ファイル:
  - `src/modules/party/ui/party-delete-dialog.tsx`
  - `src/modules/party/actions.ts`（`deletePartyAction`）
  - `src/modules/party/service.ts`（`remove`）
  - `src/modules/party/repository.ts`（`deleteIfUnchanged` / `countContracts`）
  - `src/modules/party/validation.ts`（`deletePartySchema`）
- 関連DBテーブル: `Party`、`Contract`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/14_契約先削除.md`](../../../specs/02_basic-design/party-contract/14_契約先削除.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-007の権限確認用）
- 権限: 削除の実行はADMIN/OPERATORロールに限る。VIEWERロールには「削除」ボタンが表示されず（`UT_12_契約先詳細.md` TC-006で確認済み）、Server Actionの直接実行も拒否される。
- 事前DB状態:
  - 紐づく契約が0件の契約先を1件登録済み（TC-001用）。
  - 紐づく契約が1件以上ある契約先を1件登録済み（TC-002用）。
  - 存在しない契約先ID確認用に、削除対象とは別の契約先IDを用意する。
- 使用するテストデータ: 上記の契約先ID・`updatedAt`

## 3. テスト観点
- 正常系: 紐づく契約が無い契約先の削除完了
- 異常系: 紐づく契約が存在する場合の削除拒否、存在しない契約先の削除、同時更新競合
- 境界値: 該当なし
- 権限: VIEWERによるServer Actionの直接実行拒否
- DB更新: `Party` レコードの物理削除、`PARTY_HAS_CONTRACTS` 時にDBが変化しないこと
- 画面表示: 削除確認ダイアログの表示項目、削除完了メッセージ、削除後の404

## 7. 補足
- TC-003・TC-004は、確認ダイアログ表示後に別の利用者が操作した状況を再現するため、ダイアログを表示したままDBを直接操作する手順とした。
- TC-007はVIEWERロールでは削除ボタン自体が表示されないため（`UT_12_契約先詳細.md` TC-006）、通常の画面操作では再現できない。Server Actionを直接呼び出す確認方法とする（マスタ機能の単体テストと同様、自動テスト（`actions.test.ts`）での確認と組み合わせることも検討する）。
- 件数確認の直後に別の利用者が同じ契約先へ契約を登録し、外部キー制約違反（`P2003`）から`PARTY_HAS_CONTRACTS`へ変換される経路（`service.ts`のcatchブロック）は、Playwrightでのタイミング再現が難しいため本仕様書には含めない。**`src/modules/party/service.test.ts`を確認したところ、この経路は既存の自動テストでもカバーされていない。** テストされていない分岐として残っているため、対応要否（自動テストへのケース追加）は別途ユーザーに判断を仰ぐ。
