# 単体テスト仕様書: マスタ分類詳細（MST-07）

## 1. テスト対象
- 対象機能: マスタ分類詳細（MST-07）
- 対象画面またはAPI: `/master/categories/{categoryId}`（マスタ分類詳細画面）
- 対象ファイル:
  - `src/app/(main)/master/categories/[categoryId]/page.tsx`
  - `src/modules/master/ui/master-category-detail-view.tsx`
  - `src/modules/master/service.ts`（`findCategoryDetail`）
  - `src/modules/master/repository.ts`
  - `src/shared/constants/roles.ts`（`canWrite`）
- 関連DBテーブル: `MasterCategory`
- 関連設計書: [`docs/specs/02_basic-design/master/21_マスタ分類詳細.md`](../../../specs/02_basic-design/master/21_マスタ分類詳細.md)、[`docs/specs/02_basic-design/master/00_共通.md`](../../../specs/02_basic-design/master/00_共通.md)（§00.3 権限）

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系）、VIEWERロール（TC-003の権限確認用）
- 権限: 本画面の閲覧自体はログインしていればロールを問わない。「更新する」ボタンと「削除」ボタンの表示のみADMIN/OPERATORロールに限定される（`canWrite`）。
- 事前DB状態:
  - `MasterCategory` が1件以上登録済みで、登録日時・登録者・最終更新日時・最終更新者が確認できること。
  - TC-006用に `createdBy` / `updatedBy` が `null` の `MasterCategory` を1件用意する。
- 使用するテストデータ:
  - 表示確認用の分類名・登録者・更新者が判別できる `MasterCategory` 1件

## 3. テスト観点
- 正常系: 初期表示（全表示項目）、「一覧へ戻る」「更新する」ボタンでの画面遷移
- 異常系: 存在しない分類IDでの404表示
- 権限: 「更新する」「削除」ボタンの表示制御（ADMIN/OPERATORのみ表示、VIEWERは非表示）
- DB更新: なし（本画面は詳細表示のみで、DBを更新する操作を持たない）
- 画面表示: 登録直後・更新直後の完了メッセージ表示、登録者/更新者が不明（`null`）な場合の「—」表示
