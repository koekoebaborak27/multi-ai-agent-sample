# 単体テスト仕様書: 契約削除（CTR-04 の削除確認ダイアログ）

## 1. テスト対象
- 対象機能: 契約削除確認ダイアログ、削除時の競合
- 対象画面またはAPI: `/contracts/{contractId}` 上の削除確認ダイアログ
- 対象ファイル:
  - `src/modules/contract/ui/contract-delete-dialog.tsx`
  - `src/modules/contract/actions.ts`（`deleteContractAction`）
  - `src/modules/contract/service.ts`（`remove`）
  - `src/modules/contract/repository.ts`（`deleteIfUnchanged`）
  - `src/modules/contract/validation.ts`（`deleteContractSchema`）
- 関連DBテーブル: `Contract`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/24_契約削除.md`](../../../specs/02_basic-design/party-contract/24_契約削除.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-006の権限確認用）
- 権限: 削除の実行はADMIN/OPERATORロールに限る。VIEWERロールには「削除」ボタンが表示されず（`UT_22_契約詳細.md` TC-007で確認済み）、Server Actionの直接実行も拒否される。
- 事前DB状態:
  - 削除対象の契約が1件登録済み（契約先・契約分類が設定されているもの）。
- 使用するテストデータ: 上記の契約ID・`updatedAt`

## 3. テスト観点
- 正常系: 契約の削除完了、削除した契約が検索結果に含まれないこと
- 異常系: 存在しない契約の削除、同時更新競合
- 境界値: 該当なし
- 権限: VIEWERによるServer Actionの直接実行拒否
- DB更新: `Contract` レコードの物理削除
- 画面表示: 削除確認ダイアログの表示項目、削除完了メッセージ、削除後の404

## 7. 補足
- 契約の削除には契約先削除のような依存関係チェック（紐づく`ContractItem`の確認）が無い（§00.9.1、`ContractItem`を登録・参照する画面が存在しないため）。そのため契約先削除（`UT_14_契約先削除.md` TC-002）にある「紐づくレコードが存在する場合の削除拒否」に相当するテストケースは、本仕様書には設けない。
- TC-004・TC-005は、確認ダイアログ表示後に別の利用者が操作した状況を再現するため、ダイアログを表示したままDBを直接操作する手順とした。
- TC-006はVIEWERロールでは削除ボタン自体が表示されないため、通常の画面操作では再現できない。Server Actionを直接呼び出す確認方法とする。
