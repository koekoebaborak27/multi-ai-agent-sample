# 単体テスト仕様書: 契約先検索一覧（PTY-01）

## 1. テスト対象
- 対象機能: 契約先検索一覧（PTY-01）
- 対象画面またはAPI: `/parties`（契約先検索一覧画面）
- 対象ファイル:
  - `src/app/(main)/parties/page.tsx`
  - `src/modules/party/ui/party-search-form.tsx`
  - `src/modules/party/ui/party-table.tsx`
  - `src/modules/party/service.ts`（`list`）
  - `src/modules/party/repository.ts`（`listAndCount`）
  - `src/modules/party/validation.ts`（`partySearchQuerySchema`）
- 関連DBテーブル: `Party`、`MasterCategory`、`Master`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/10_契約先検索一覧.md`](../../../specs/02_basic-design/party-contract/10_契約先検索一覧.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMIN/OPERATORロール（「新規登録」ボタンの表示確認）、VIEWERロール（TC-009の権限確認用）
- 権限: 一覧の参照は全ロールで可能。「新規登録」ボタンの表示のみADMIN/OPERATORに限る。
- 事前DB状態:
  - `MasterCategory`（`CONTRACT_COMPANY_TYPE`）配下にマスタが2件以上登録済み。
  - `Party` が `env.PAGE_SIZE` を超える件数登録済み（ページング確認用）。名称に検索用のキーワード（例: `検索確認商事`）を含む契約先を1件以上含む。
  - 契約先分類が未設定（`companyTypeMasterId = null`）の契約先を1件以上含む。
- 使用するテストデータ:
  - 検索キーワード（例: `検索確認`）、契約先分類の選択肢1件

## 3. テスト観点
- 正常系: 名称・契約先分類による検索、AND条件、全件表示、ページング、並び替え
- 異常系: 該当なし（検索条件はいずれも任意項目で、不正な値もURL側で初期値へ丸められる仕様のため）
- 境界値: 該当なし（本画面固有の文字数上限等は無い）
- 権限: VIEWERでの一覧参照可・新規登録ボタン非表示
- DB更新: 該当なし（参照のみの画面）
- 画面表示: 検索結果0件時のメッセージ、分類未設定契約先の表示、条件をクリアの挙動
