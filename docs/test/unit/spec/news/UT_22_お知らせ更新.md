# 単体テスト仕様書: お知らせ更新（NEWS-02 / NEWS-03）

## 1. テスト対象
- 対象機能: お知らせ更新・更新内容確認（NEWS-02 / NEWS-03）
- 対象画面またはAPI: `/news` の行ごとの「編集」ポップアップ、`updateNewsAction`
- 対象ファイル: `src/modules/news/ui/news-edit-dialog.tsx`、`src/modules/news/ui/news-confirmation.tsx`、`src/modules/news/actions.ts`、`src/modules/news/service.ts`、`src/modules/news/repository.ts`、`src/modules/news/validation.ts`
- 関連DBテーブル: `News`
- 関連設計書: [`22_お知らせ更新.md`](../../../../specs/02_basic-design/news/22_お知らせ更新.md)、[`21_お知らせ登録.md`](../../../../specs/02_basic-design/news/21_お知らせ登録.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: ADMIN（TC-001〜TC-007）、VIEWER（TC-008）。
- 権限: ADMIN/OPERATORは更新可能。VIEWERの更新Server Actionは `FORBIDDEN` で拒否される。
- 事前DB状態: 更新対象の `News` が1件あり、タイトル・カテゴリ・本文・公開期間・公開トグル・`createdBy`・`updatedAt` が記録されている。
- 使用するテストデータ: 更新前後で判別できる全項目の値、200/201文字のタイトル、3000/3001文字の本文。

## 3. テスト観点
- 正常系: 初期値表示、全項目更新、値を変えない更新。
- 異常系: 入力エラー、同時更新、対象なし、VIEWERの直接実行拒否。
- 境界値: 登録と同じ文字数・公開期間の制約。
- 権限: Server Actionでの書き込み権限確認。
- DB更新: 更新値、`updatedBy`/`updatedAt`、`createdBy`維持。
- 画面表示: 更新確認画面は変更後の値だけを表示すること、修正・キャンセル。
- エビデンス取得: 確認画面、成功後一覧、エラー画面をPNGで保存する。

## 6. 未確定事項
- VIEWERのServer Action直接実行を画面テストで再現する方法と、DB直接操作に使う接続情報はテスト実行時に確認する。

## 7. 補足
- 同時更新・対象なしは、確認画面を開いた後に別操作が行われた状態を再現するため、画面テスト時はDB直接操作を用いる。
- 同一値での更新は許可される。確認画面に「変更なし」は表示しない設計である。
