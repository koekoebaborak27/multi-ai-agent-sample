# 単体テスト仕様書: お知らせ登録（NEWS-02 / NEWS-03）

## 1. テスト対象
- 対象機能: お知らせ登録・登録内容確認（NEWS-02 / NEWS-03）
- 対象画面またはAPI: `/news` の「新規登録」ポップアップ、`createNewsAction`
- 対象ファイル: `src/modules/news/ui/news-create-dialog.tsx`、`src/modules/news/ui/news-confirmation.tsx`、`src/modules/news/actions.ts`、`src/modules/news/service.ts`、`src/modules/news/repository.ts`、`src/modules/news/validation.ts`
- 関連DBテーブル: `News`
- 関連設計書: [`21_お知らせ登録.md`](../../../../specs/02_basic-design/news/21_お知らせ登録.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: ADMIN（TC-001〜TC-009）、OPERATOR（TC-010）、VIEWER（TC-011）。
- 権限: ADMIN/OPERATORは登録可能。VIEWERの登録Server Actionは `FORBIDDEN` で拒否される。
- 事前DB状態: 登録するタイトルと同じ `News` が存在しないことを確認できる状態。
- 使用するテストデータ: `NEWS-CREATE-001` を含むタイトル、本文、3カテゴリ、200/201文字のタイトル、3000/3001文字の本文、比較可能な公開開始・終了日時。

## 3. テスト観点
- 正常系: 入力、確認、実行による登録、任意日時の空欄、公開トグルOFF、OPERATORの登録。
- 異常系: 必須入力、文字数超過、公開期間の逆転、VIEWERの直接実行拒否。
- 境界値: タイトル200/201文字、本文3000/3001文字、開始・終了同時刻。
- 権限: 書き込み権限をServer Actionでも確認すること。
- DB更新: `News` の全登録値、`createdBy`/`updatedBy`。
- 画面表示: Dialog、確認画面、入力値保持、キャンセル、エラー文言。
- エビデンス取得: 確認画面、成功トースト、各エラー画面をPNGで保存する。

## 6. 未確定事項
- VIEWERのServer Action直接実行を画面テストで再現する方法と、各ロールのログイン情報はテスト実行時に確認する。

## 7. 補足
- `News` には一意制約がないため、同じタイトルでの重複登録は許可される。重複エラーのテストは対象外とする。
- 登録は `News` 1テーブルへの追加だけであり、外部キー制約を伴うテストは対象外とする。
