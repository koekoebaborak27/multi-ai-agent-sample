# 単体テスト仕様書: お知らせ管理一覧（NEWS-02）

## 1. テスト対象
- 対象機能: お知らせ管理一覧・検索・並び替え・ページング（NEWS-02）
- 対象画面またはAPI: `/news`
- 対象ファイル: `src/app/(main)/news/page.tsx`、`src/modules/news/ui/news-search-form.tsx`、`src/modules/news/ui/news-table.tsx`、`src/modules/news/validation.ts`、`src/modules/news/service.ts`、`src/modules/news/repository.ts`、`src/modules/auth/route-guard.ts`、`src/shared/layout/sidebar.tsx`
- 関連DBテーブル: `News`
- 関連設計書: [`20_お知らせ管理一覧.md`](../../../../specs/02_basic-design/news/20_お知らせ管理一覧.md)、[`00_お知らせ管理共通.md`](../../../../specs/02_basic-design/news/00_お知らせ管理共通.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: ADMIN、OPERATOR、VIEWERの各ロール。
- 権限: ADMINとOPERATORは `/news` を開ける。VIEWERは `/` へリダイレクトされる。
- 事前DB状態: 3カテゴリ、4公開ステータス（公開中・公開前・終了・非公開中）、タイトルまたは本文に `AB01` を含む行、0件検索用の文字列、`env.PAGE_SIZE + 1` 件以上の行を用意する。
- 使用するテストデータ: タイトル・カテゴリ・公開開始日時・公開終了日時が相違する行。登録者・更新者が判別できる行。

## 3. テスト観点
- 正常系: 初期表示、カテゴリ・文言・AND検索、ソート、ページング、条件クリア。
- 異常系: 0件検索、URLの不正な検索条件を初期値へ戻すこと。
- 境界値: ページング、同じ見出しの連続クリックによる昇順・降順切替。
- 権限: ADMIN/OPERATORの入場、VIEWERのメニュー非表示・URL直接アクセス制御。
- DB更新: 読み取り専用であること。
- 画面表示: 公開ステータス4値、空欄日時の「—」、検索結果件数。
- エビデンス取得: 各検索結果・権限制御をPNGで保存する。
