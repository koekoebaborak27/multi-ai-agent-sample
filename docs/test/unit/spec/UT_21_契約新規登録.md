# 単体テスト仕様書: 契約新規登録（CTR-02 / CTR-03）

## 1. テスト対象
- 対象機能: 契約新規登録（CTR-02）・契約確認画面（CTR-03・新規登録モード）
- 対象画面またはAPI: `/contracts/new`（契約新規登録画面）
- 対象ファイル:
  - `src/app/(main)/contracts/new/page.tsx`
  - `src/modules/contract/ui/contract-create-form.tsx`
  - `src/modules/contract/ui/contract-form-fields.tsx`
  - `src/modules/contract/ui/contract-confirmation.tsx`
  - `src/modules/contract/ui/party-combobox.tsx`
  - `src/modules/contract/actions.ts`（`createContractAction`）
  - `src/modules/contract/service.ts`（`create` / `assertPartyExists` / `assertCategoryValid`）
  - `src/modules/contract/repository.ts`（`create`）
  - `src/modules/contract/validation.ts`（`createContractSchema`）
  - `src/shared/constants/roles.ts`（`canWrite`）
- 関連DBテーブル: `Contract`、`Party`、`MasterCategory`、`Master`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/21_契約新規登録.md`](../../../specs/02_basic-design/party-contract/21_契約新規登録.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）、VIEWERロール（TC-013の権限確認用）
- 権限: 「新規登録」画面へのアクセスと登録実行はADMIN/OPERATORロールに限る。VIEWERロールは画面を直接開いても元の一覧画面へリダイレクトされる。
- 事前DB状態:
  - 契約先が1件以上登録済み。
  - `MasterCategory`（`CONTRACT_TYPE`）配下にマスタが1件以上登録済み。
  - 契約先分類（`CONTRACT_COMPANY_TYPE`）配下のマスタIDを1件、契約分類とは異なる分類コードのマスタIDとして用意する（TC-006用）。
  - TC-012用に `Party` が0件の状態を一時的に作れること。
- 使用するテストデータ:
  - 契約名（例: `新規登録確認契約`）、契約先、開始日・終了日、状態、契約分類
  - 200文字ちょうど／201文字の契約名

## 3. テスト観点
- 正常系: 入力→確認→実行で登録完了、必須項目のみでの登録
- 異常系: 契約先未選択、契約名未入力、存在しない契約先ID、存在しない契約分類マスタID、契約分類以外の分類コード配下のマスタID
- 境界値: 契約名200文字（登録可）／201文字（拒否）
- 権限: VIEWERロールでの画面アクセス制御
- DB更新: `Contract` への `partyId` / `title` / `startDate` / `endDate` / `status` / `categoryMasterId` / `createdBy` / `updatedBy` の登録
- 画面表示: 確認画面の表示項目（新規登録モード）、「入力内容を修正」での入力値保持、「キャンセル」での破棄、契約先0件時の案内表示
