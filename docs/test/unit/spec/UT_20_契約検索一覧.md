# 単体テスト仕様書: 契約検索一覧（CTR-01）

## 1. テスト対象
- 対象機能: 契約検索一覧（CTR-01）
- 対象画面またはAPI: `/contracts`（契約検索一覧画面）
- 対象ファイル:
  - `src/app/(main)/contracts/page.tsx`
  - `src/modules/contract/ui/contract-search-form.tsx`
  - `src/modules/contract/ui/contract-table.tsx`
  - `src/modules/contract/ui/party-combobox.tsx`
  - `src/modules/contract/service.ts`（`list`）
  - `src/modules/contract/repository.ts`（`listAndCount`）
  - `src/modules/contract/validation.ts`（`contractSearchQuerySchema`）
- 関連DBテーブル: `Contract`、`Party`、`MasterCategory`、`Master`
- 関連設計書: [`docs/specs/02_basic-design/party-contract/20_契約検索一覧.md`](../../../specs/02_basic-design/party-contract/20_契約検索一覧.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMIN/OPERATORロール（「新規登録」ボタンの表示確認）、VIEWERロール（TC-011の権限確認用）
- 権限: 一覧の参照は全ロールで可能。「新規登録」ボタンの表示のみADMIN/OPERATORに限る。
- 事前DB状態:
  - 契約先が2件以上登録済み。
  - `MasterCategory`（`CONTRACT_TYPE`）配下にマスタが2件以上登録済み。
  - `Contract` が `env.PAGE_SIZE` を超える件数登録済み（ページング確認用）。状態（`DRAFT`/`ACTIVE`/`TERMINATED`）・契約先・契約分類にばらつきを持たせる。
- 使用するテストデータ: 検索条件用の契約先1件、状態1件、契約分類1件

## 3. テスト観点
- 正常系: 契約先・状態・契約分類による絞り込み、複数条件のAND条件、全件表示、ページング、5列の並び替え
- 異常系: 該当なし（検索条件はいずれも任意項目で、不正な値もURL側で初期値へ丸められる仕様のため）
- 境界値: 該当なし
- 権限: VIEWERでの一覧参照可・新規登録ボタン非表示
- DB更新: 該当なし（参照のみの画面）
- 画面表示: 検索結果0件時のメッセージ、契約先コンボボックスでの名称絞り込み、条件をクリアの挙動
