# 単体テスト仕様書: メールアドレス変更確認（EML-02）

## 1. テスト対象
- 対象機能: メールアドレス変更の確認用URLを開いたときの確定処理と結果表示
- 対象画面またはAPI: `/settings/email/confirm/[token]`
- 対象ファイル:
  - `src/app/(main)/settings/email/confirm/[token]/page.tsx`
  - `src/modules/password-reset/service.ts`（`confirmEmailChange`）
- 関連DBテーブル: `EmailChangeToken`、`User`
- 関連設計書: [`docs/specs/02_basic-design/password-reset/20_メールアドレス管理.md`](../../../../specs/02_basic-design/password-reset/20_メールアドレス管理.md)（§20.3）

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: 申し込みを行った利用者本人（TC-001・TC-002）、申し込みを行っていない別の利用者（TC-003）
- 権限: ログイン済みであること（未ログインの場合はTC-004で確認）
- 事前DB状態:
  - ある利用者Aが `/settings/email` からメールアドレス変更を申し込んだ状態（`EmailChangeToken` が未使用・期限内）を用意する（TC-001用）
  - 期限切れ、または使用済みの `EmailChangeToken` を用意する（TC-002用）
  - TC-001と同じ申し込みを、利用者Aとは別の利用者Bでログインして開く（TC-003用。TC-001とは別に申し込みを用意する）
  - 利用者Cが変更先に指定したアドレスを、申し込み後に別の利用者Dが既に登録済みにしておく（TC-005用）
- 使用するテストデータ: 上記各利用者の確認用URL

## 3. テスト観点
- 正常系: 有効なURLを開いたときの確定・表示
- 異常系: 期限切れ・使用済みURL、申込者と異なる利用者でのアクセス、未ログイン、確定直前の重複
- 境界値: 該当なし
- 権限: 申込者本人以外は確定できないこと、未ログインでは開けないこと
- DB更新: `User.email` の書き換え、`EmailChangeToken.usedAt` の更新
- 画面表示: 成功時・失敗時の表示切り替え

## 7. 補足
- この画面はボタン操作を伴わず、URLを開いた時点（ページ表示のサーバ処理）で確定処理が実行される。Playwrightでの確認時は、ページ遷移が完了した時点のスクリーンショットで結果を確認する。
- 確認用URLの合言葉不一致・期限切れ・使用済み・申込者不一致の判定ロジック、変更前アドレスへの通知メール送信（変更前が未登録なら送らない分岐を含む）は `src/modules/password-reset/service.test.ts` で自動テスト済みのため、本仕様書では画面表示の確認に絞った。
