# 単体テスト仕様書: パスワード再設定（PWR-02）

## 1. テスト対象
- 対象機能: メールで届いた再設定用URLを開いて、新しいパスワードを設定する画面
- 対象画面またはAPI: `/reset-password/[token]`
- 対象ファイル:
  - `src/app/(auth)/reset-password/[token]/page.tsx`
  - `src/modules/password-reset/ui/reset-password-form.tsx`
  - `src/modules/password-reset/actions.ts`（`resetPasswordAction`）
  - `src/modules/password-reset/service.ts`（`canOpen` / `resetPassword`）
- 関連DBテーブル: `PasswordResetToken`、`User`
- 関連設計書: [`docs/specs/02_basic-design/password-reset/11_パスワード再設定.md`](../../../../specs/02_basic-design/password-reset/11_パスワード再設定.md)

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: 不要（ログインしていない状態で操作する）
- 権限: 誰でも開ける画面（`PUBLIC_PATHS` に `/reset-password` を含む）
- 事前DB状態:
  - 有効な再設定用URL（`PasswordResetToken`、`usedAt` 空・`expiresAt` が現在時刻より後）を1件発行済みにしておく（TC-001・TC-002・TC-007・TC-008用）
  - 期限切れの `PasswordResetToken`（`expiresAt` が過去）を1件用意する（TC-003用）
  - 使用済みの `PasswordResetToken`（`usedAt` に日時が入っている）を1件用意する、または存在しない合言葉のURLを用意する（TC-004用）
- 使用するテストデータ: 上記の再設定用URL（各状態ごとのtoken文字列）

## 3. テスト観点
- 正常系: 有効なURLでの画面表示、設定完了までの一連の流れ
- 異常系: 期限切れ・使用済み・不正なURL、パスワードの不一致、形式不備
- 境界値: 該当なし（文字数条件は自動テストでカバー済み。§7参照）
- 権限: 該当なし（ログイン不要画面）
- DB更新: `User.passwordHash` の更新、`PasswordResetToken.usedAt` の更新
- 画面表示: 通常時・開けない時の表示切り替え、利用者を特定できる情報が出ないこと

## 7. 補足
- パスワードの英字・数字混在チェック、期限切れ・使用済みの判定ロジック、失敗回数・ロックの解除、通知メール送信は `src/modules/password-reset/service.test.ts` で自動テスト済みのため、本仕様書では画面表示・遷移・エラー文言の確認に絞った。
- パスワード変更のお知らせメールの送信失敗時もパスワード変更自体は成立する仕様（設計書§11.4）だが、送信失敗を画面から意図的に再現する手段が無いため、本仕様書では確認しない（自動テストでカバー済み）。
