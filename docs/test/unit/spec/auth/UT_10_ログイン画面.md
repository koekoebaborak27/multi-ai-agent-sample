# 単体テスト仕様書: ログイン画面（LGN-01）

## 1. テスト対象
- 対象機能: ログイン画面（LGN-01）
- 対象画面またはAPI: `/login`、`loginWithCredentials`、`loginWithEntra`
- 対象ファイル: `src/app/(auth)/login/page.tsx`、`src/modules/auth/ui/login-form.tsx`、`src/modules/auth/actions.ts`、`src/modules/auth/service.ts`、`src/modules/auth/repository.ts`、`src/modules/auth/route-guard.ts`、`src/proxy.ts`
- 関連DBテーブル: `User`
- 関連設計書: [`10_ログイン画面.md`](../../../../specs/02_basic-design/login/10_ログイン画面.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: 未ログイン状態から開始する。必要に応じて既存のADMIN/OPERATOR/VIEWERユーザーを使う。
- 権限: ログイン画面自体はロール不問。ルートガードの確認ではADMIN以外・VIEWERのユーザーも用意する。
- 事前DB状態:
  - 通常ユーザー1件（`passwordHash`あり、`lockedAt`空、`failedAttempts=0`、ユーザーIDは64文字ちょうど）
  - `lockedAt`設定済み（ロック中）のユーザー1件
  - `mustChangePassword=true`のユーザー1件
  - ADMIN以外（OPERATOR/VIEWER）のユーザー、VIEWERのユーザーを各1件
- 使用するテストデータ: 正しいユーザーID・パスワードの組、誤ったパスワード、存在しないユーザーID

## 3. テスト観点
- 正常系: ID・パスワードでのログイン成功、Microsoft Entra IDログインボタンの表示切替、ログイン済みでの`/login`リダイレクト、パスワード再設定直後メッセージ
- 異常系: 未入力、ID/パスワード誤り、ロック済みアカウントでのログイン試行
- 境界値: ユーザーID64文字での成功、連続失敗によるロック発生
- 権限: ルートガードによる保護ページ・管理者専用ページ・お知らせ管理ページへのアクセス制御、初回パスワード変更への強制誘導
- DB更新: `failedAttempts`の増加とリセット、`lockedAt`の記録
- 画面表示: フォーム項目、エラーメッセージ、ボタンの活性制御
- エビデンス取得: 各ケースの画面をPNGで保存する

## 6. 未確定事項
- `env.MAX_ATTEMPTS`の実際の値（既定20）を画面テスト実行時に確認する。TC-009は失敗操作を繰り返すため、実行時間に注意する。
- Entra設定の有効/無効を切り替える環境変数の値と、ローカルでの切り替え手順は画面テスト実行時に確認する。

## 7. 補足
- Microsoft Entra ID ログインは、ボタンの表示切替（TC-002）までを確認範囲とする。実際のログイン完了・利用者の自動作成（`provisionEntraUser`）は、Azure側の実機設定を要するため本仕様書では確認しない。
- ユーザーID65文字以上は入力欄の`maxLength`属性により入力できないため対象外とする。
- セッション（JWTの有効期限90分等）は画面操作から直接検証できないため対象外とする。
- 保存処理（Server Action）呼び出し時は画面遷移の案内を行わない仕様（設計書§10.7）だが、ブラウザ操作からは直接観察しづらいため、画面表示時の挙動（TC-012・TC-014）で代替する。
