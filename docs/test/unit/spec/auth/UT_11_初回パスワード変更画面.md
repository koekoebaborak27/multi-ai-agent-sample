# 単体テスト仕様書: パスワード変更画面（LGN-02）

## 1. テスト対象
- 対象機能: パスワード変更画面（LGN-02）。初回ログイン時の強制誘導と、任意タイミングでの自主変更の両方を扱う。
- 対象画面またはAPI: `/settings/password`、`changePassword`
- 対象ファイル: `src/app/(main)/settings/password/page.tsx`、`src/modules/auth/ui/password-change-form.tsx`、`src/modules/auth/actions.ts`、`src/modules/auth/service.ts`、`src/modules/auth/validation.ts`
- 関連DBテーブル: `User`
- 関連設計書: [`11_初回パスワード変更画面.md`](../../../../specs/02_basic-design/login/11_初回パスワード変更画面.md)

## 2. 前提条件
- 実行環境: ローカル環境。本番URL・本番DBには接続しない。
- ログインユーザー: `mustChangePassword=false`の通常ユーザー1件、`mustChangePassword=true`のユーザー1件。
- 権限: ログイン必須。本人のパスワードのみ変更できる（ロールによる差は無い）。
- 事前DB状態: 上記2ユーザーとも`passwordHash`を持つ状態にしておく。
- 使用するテストデータ: 現在のパスワードと異なる新しいパスワード（英数字混在・8文字以上）、条件を満たさない新しいパスワードいくつか

## 3. テスト観点
- 正常系: 通常アクセスでの変更成功とログアウト、初回ログイン誘導時の案内表示
- 異常系: 各入力項目の未入力、新しいパスワードの条件未達、確認用パスワードの不一致、現在のパスワードの誤り、新しいパスワードが現在のパスワードと同じ、未ログインでのアクセス
- 境界値: 新しいパスワード8文字ちょうど・128文字ちょうど
- 権限: ログイン必須（未ログイン時はリダイレクト）
- DB更新: `passwordHash`の更新、`mustChangePassword`のリセット、`failedAttempts`のリセット
- 画面表示: 初回ログイン案内文の表示切替、ボタンの活性制御
- エビデンス取得: 各ケースの画面をPNGで保存する

## 7. 補足
- Microsoft Entra IDでログインした利用者（`passwordHash`を持たない）がこの画面を開いた場合の「このアカウントはパスワード変更の対象外です」（設計書§11.3-1）は、Entra実機ログインを前提にしないと状態を再現できず、Playwright操作だけでは再現できないため本仕様書のテストケースからは除外する。
- 新しいパスワードが129文字以上になる操作は、入力欄に上限が無いため技術的には送信できるが、業務上想定しない極端な入力のため本仕様書では確認しない。
