- 対象画面またはAPI: `/master/categories/{categoryId}`（マスタ分類詳細画面の「削除」ダイアログ）
- 対象ファイル:
  - `src/modules/master/ui/master-category-delete-dialog.tsx`

  - `src/modules/master/validation.ts`（`deleteMasterCategorySchema`）
  - `src/shared/constants/messages.ts`（`MESSAGES.common.deleted`）
- 関連DBテーブル: `MasterCategory`、`Master`
- 関連設計書: [`docs/specs/02_basic-design/master/24_マスタ分類削除.md`](../../../specs/02_basic-design/master/24_マスタ分類削除.md)、[`docs/specs/02_basic-design/master/14_マスタ削除.md`](../../../specs/02_basic-design/master/14_マスタ削除.md)（§14.1.2 ダイアログの仕様・§14.1.4 削除完了メッセージ）、[`docs/specs/02_basic-design/master/00_マスタ管理共通.md`](../../../specs/02_basic-design/master/00_マスタ管理共通.md)（[§00.5.1 マスタ分類の編集・削除・実行時の警告アラート](../../../specs/02_basic-design/master/00_マスタ管理共通.md#0051-マスタ分類の編集削除実行時の警告アラート)）

## 2. 前提条件
- 実行環境: ローカル環境（`pnpm dev` で起動した検証用サーバー。本番URL・本番DBには接続しない）
- ログインユーザー: ADMINロール（正常系・異常系の実行）
- 権限: 削除ボタン自体はADMIN/OPERATORロールにのみ表示される（TC-004でUT_21のTC-003にて確認済みのため、本仕様書では削除の実行結果を対象とする）。
- 事前DB状態:
  - 配下にマスタが0件の削除対象分類が1件登録済み（TC-001用）。
  - 配下にマスタが1件以上ある削除対象分類が1件登録済み（TC-002用）。
- 使用するテストデータ:
  - 配下マスタ0件の分類名（例: `削除対象分類（空）`）
  - 配下マスタ1件以上の分類名（例: `削除対象分類（マスタあり）`）とその配下マスタ1件

## 3. テスト観点
- 正常系: 配下マスタが0件の分類の削除完了
- 異常系: 配下にマスタが残っている分類の削除拒否（`MASTER_CATEGORY_HAS_MASTERS`）、同時更新エラー
- DB更新: 削除成功時に `MasterCategory` の対象行が物理削除されること、削除失敗時にDBが変化しないこと
- 画面表示: 削除確認ダイアログの表示項目、「キャンセル」でのダイアログ閉じる動作、削除完了トースト（一覧画面での「削除しました」表示）

## 7. 補足
- 削除ボタン自体の権限表示制御（ADMIN/OPERATORのみ表示）は、マスタ分類詳細（`UT_21_マスタ分類詳細.md` TC-003）で確認済みのため、本仕様書では削除の実行結果を対象とする。
- TC-003は、ダイアログ表示後に別の利用者が操作した状況をブラウザの複数タブ操作では再現しにくいため、ダイアログを表示したままDBを直接操作する手順とした。
