## 00.1.3 前提

作業を始める前に、次の 2 つを終えておいてください。

1. **自分の PC でアプリが動くこと。** 手順は [`README_SIMPLE.md`](../../../README_SIMPLE.md) にあります。本書の手順 3（データベースの初期化）で、PC 上のコマンドから本番データベースへ接続するため、`pnpm` などが使える状態が必要です。
2. **テンプレートのソースコードが手元にあること。** まだ Git 管理していない状態（フォルダにファイルがあるだけ）で構いません。手順 1 で GitHub へ登録します。

## 00.1.4 所要時間と費用

| 項目   | 目安                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------- |
| 所要時間 | 合計 3〜4 時間。うち Google Cloud Run（手順 4）が最も時間を要します                                                   |
| 費用   | **月額 0 円**。Cloud Run と Supabase の無料枠の範囲に収まる構成です。ただし Google Cloud はアカウント作成時に**クレジットカードの登録が必須**です |

> **無料枠**とは、各クラウドサービスが定めている「ここまでは無料で使ってよい」という上限です。Cloud Run は月あたり 200 万リクエスト・180,000 vCPU 秒・360,000 GiB 秒まで無料で、この上限を超えた分だけ課金されます。本書では上限を超えないための設定（[05.1.4](infra_design_05_CloudRun構築.md#0514-サービスの設定値)）を必ず入れます。

## 00.1.5 表記ルール

- **`<` と `>` で囲んだ部分はプレースホルダ**です。自分の環境の値に置き換えてください。
  例: `https://<プロジェクトref>.supabase.co`
- 実際に構築したときの値を「**このプロジェクトでの例**」として併記しています。そのまま入力するのではなく、置き換えの参考にしてください。
- コマンドは **Windows PowerShell** を前提としています。macOS / Linux の場合は、環境変数の設定方法（`$env:NAME='値'` → `export NAME='値'`）が異なります。

## 00.1.6 UIは資料と異なる可能性あり

**本書に記載した画面名・ボタン名・項目の並びは、2026 年 8 月時点のものです。クラウドサービスの管理画面は更新されるため、実際の画面と異なる場合があります。**

実際に、本テンプレートの構築時にも次の食い違いが発生しました。

- 事前に用意した手順書は「サービスを作成」ボタンを押す前提だったが、**そのボタンは存在しなかった**
- 公式ドキュメントを先に読んでいたが、それでも画面と一致しなかった

画面が本書と異なる場合は、次の順で対処してください（またはAI等で調査してください）。

1. **設定したい項目名で探す。** ボタンの位置や画面の構成が変わっても、設定項目そのもの（「リージョン」「インスタンスの最大数」など）の名前は残っていることが多いためです。
2. **各手順の「設定値の表」を基準にする。** 本書は「どのボタンを押すか」ではなく「何をどの値にするか」を表で示しています。画面が変わっても、この表の値をすべて設定できていれば結果は同じです。
3. **画面のスクリーンショットを撮り、AI エージェントに確認してもらう。** Claude Code などにスクリーンショットを渡し、「この項目はどこにありますか」「この設定値と一致していますか」と聞くと、項目名の言い換えや配置の違いを見つけやすくなります。
4. **公式ドキュメントを参照する。** [Cloud Run](https://cloud.google.com/run/docs) / [Supabase](https://supabase.com/docs)。
5. **本書を更新する。** 実際の画面と違っていた箇所は、次に構築する人のために本書へ反映してください。

## 00.2 用語集

本書に出てくる用語です。分からない語が出てきたらここへ戻ってください。

## 00.2.1 アプリの実行に関する用語

| 用語           | 意味                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| **コンテナ**     | アプリと、その実行に必要な設定・ライブラリをひとまとめにした実行環境。PC やサーバーへ直接インストールせずにアプリを動かせます                                               |
| **イメージ**     | コンテナの「型」にあたるファイル。イメージを起動したものがコンテナです。本テンプレートのイメージは [`docker/Dockerfile`](../../../docker/Dockerfile) の記述から作られます |
| **レジストリ**    | イメージの保管場所。Google Cloud では Artifact Registry が使われ、ビルドしたイメージが自動で保存されます                                           |
| **デプロイ**     | 作成したアプリを、実際に利用できる場所（本番環境）へ配置して動かすこと                                                                            |
| **リビジョン**    | Cloud Run におけるデプロイ 1 回分の記録。デプロイのたびに新しいリビジョンが作られ、**過去のリビジョンへ戻すこともできます**（[09.1.5](infra_design_10_構築後の運用.md#1015-以前の状態へ戻す切り戻し)）              |
| **コールドスタート** | アクセスがない間はコンテナを停止しておき、リクエストが来たときに起動する方式で発生する待ち時間。本構成では起動に数秒〜十数秒かかります。待機中の費用がかからない代わりの制約です                       |

## 00.2.2 サービスの名前

| 用語                    | 意味                                                                         |
| --------------------- | -------------------------------------------------------------------------- |
| **GitHub**            | ソースコードを保管し、変更履歴を管理するサービス                                                   |
| **GitHub Actions**    | GitHub 上で自動処理を実行する仕組み。本テンプレートでは**検査（CI）だけ**を行い、デプロイはしません                   |
| **Google Cloud Run**  | コンテナを動かすサービス。アクセスに応じて自動で起動・停止します                                           |
| **Cloud Build**       | Google Cloud 上でイメージを作る（ビルドする）サービス。GitHub への push を検知して自動で動きます              |
| **Developer Connect** | Google Cloud と GitHub を接続するための仕組み。Cloud Build が GitHub のソースコードを取得できるようにします |
| **Supabase**          | PostgreSQL データベースとファイルストレージを提供するサービス                                       |
| **Artifact Registry** | Google Cloud のイメージ保管場所（レジストリ）                                              |

## 00.2.3 設定・運用に関する用語

| 用語             | 意味                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| **環境変数**       | データベースの接続先やパスワードなど、**実行環境ごとに変わる設定値**。ソースコードに直接書かず、実行環境側に登録します                                                 |
| **マイグレーション**   | データベースの表（テーブル）や列の構造を、プログラムが期待する状態へ変更する処理。変更内容は [`prisma/migrations/`](../../../prisma/migrations/) に履歴として残ります |
| **seed（シード）**  | 動作に必要な初期データをデータベースへ登録する処理。本テンプレートでは初期管理者ユーザーを作ります                                                             |
| **リージョン**      | サービスを動かす地域（データセンターの場所）。利用者から遠いと通信に時間がかかります。なお、本資料では無料枠を利用するため意図的にリージョンを指定しています。                               |
| **サービスアカウント**  | 人ではなく**プログラムが使うアカウント**。Cloud Run のコンテナは、このアカウントの権限で動きます                                                       |
| **IAM**        | 「誰が何をしてよいか」を管理する Google Cloud の仕組み                                                                            |
| **コネクションプーラー** | データベースへの接続を再利用して、接続の作りすぎを防ぐ中継役。Supabase では接続方式の 1 つとして提供されます（[03.1.3](infra_design_03_Supabase作成.md#0313-接続文字列を取得する)）                           |
| **署名 URL**     | 一定時間だけ有効な、ファイル取得用の URL。非公開のファイルを、権限を持たないブラウザへ安全に渡すために使います                                                     |

## 00.3.1 構成図

```
   開発者のPC                    GitHub                        Google Cloud
┌─────────────────┐          ┌──────────────────────┐
│  ソースコード     │ ① push  │  作業用ブランチ        │
│  git / gh       ├─────────▶│  feature/xxx         │
└────────┬────────┘          └──────────┬───────────┘
         │                              │ ② Pull Request を作成
         │                              ▼
         │                   ┌──────────────────────┐
         │                   │  GitHub Actions      │
         │                   │  CI（検査のみ）        │
         │                   └──────────┬───────────┘
         │                              │ ③ CI 成功後にマージ
         │                              ▼
         │                   ┌──────────────────────┐   ④  ┌──────────────────────┐
         │                   │  main ブランチ        ├─────▶│  Cloud Build         │
         │                   └──────────────────────┘ 検知 │  イメージを作る        │
         │                                                 └──────────┬───────────┘
         │                                                            │ ⑤ デプロイ（自動）
         │                                                            ▼
         │                                                 ┌──────────────────────┐
         │                                                 │  Cloud Run           │
         │                                                 │  contract-app        │
         │                                                 └──────────┬───────────┘
         │  ⑥ マイグレーション / seed（PCから手動）                      │ 接続
         └────────────────────────────────────────────────────────────┤
                                                                      ▼
                                                           ┌──────────────────────┐
                                                           │  Supabase            │
                                                           │  PostgreSQL/Storage  │
                                                           └──────────────────────┘
```

①〜⑤ の流れは [00.3.3](#0033-デプロイの流れ) で説明します。

> **⑥ のマイグレーションと seed は手動です。** Cloud Run にはデプロイの前後に処理を挟む仕組みがないため、**開発者の PC から本番データベースへ直接実行します**（手順は [04.1 章](infra_design_04_本番データベース初期化.md#041-手順3-本番データベースを初期化する) と [09.1.2](infra_design_10_構築後の運用.md#1012-データベースの構造を変更する)）。自動化する場合は Cloud Run Jobs などの別の仕組みが必要です。

## 00.3.2 何がどこで動くか

| 役割           | 使うサービス                    | 補足                                                                         |
| ------------ | ------------------------- | -------------------------------------------------------------------------- |
| ソースコードの保管    | GitHub                    | private リポジトリ                                                              |
| コードの自動検査（CI） | GitHub Actions            | lint / 型チェック / テスト / ビルド。**デプロイはしない**                                      |
| イメージの作成      | Cloud Build               | `main` への push で自動実行                                                       |
| アプリの実行       | Cloud Run                 | Web 画面の配信                                                                  |
| データベース       | Supabase（PostgreSQL）      |                                                                            |
| ファイル保管       | Supabase（Storage）         | 非公開バケット。ブラウザへは署名 URL で渡す                                                   |
| ジョブワーカー      | Cloud Run（**現時点では動かさない**） | 将来的に Cloud Run 上で動かす想定。現時点では登録済みのジョブがないため起動しない。詳細は [09.1.7](infra_design_10_構築後の運用.md#1017-本番で動かさないもの) |

## 00.3.3 デプロイの流れ

[00.3.1 の構成図](#0031-構成図) の番号に対応します。

1. **①** 開発者が作業用ブランチで変更し、GitHub へ push する
2. **②** Pull Request を作成する。これをきっかけに GitHub Actions が検査（CI）を実行する
3. **③** CI が成功したら `main` へマージする
4. **④** `main` の更新を Cloud Build が検知し、イメージを作る（5〜10 分）
5. **⑤** Cloud Build が Cloud Run へ新しいリビジョンを**自動的にデプロイする**
6. 新しいリビジョンへアクセスが切り替わる

> **`main` が更新されると、本番へ自動的に反映されます。** 構築完了後は特に注意してください（[09.1.1](infra_design_10_構築後の運用.md#1011-本番へ反映する)）。
> 
> **問題のある内容を反映してしまった場合は、元の状態へ戻せます。** 手順は [10.1.5 以前の状態へ戻す（切り戻し）](infra_design_10_構築後の運用.md#1015-以前の状態へ戻す切り戻し) にあります。**復旧できることを先に知っておくと、落ち着いて対処できます。**

## 00.4 あとから変更できない項目

**この章は作業前に必ず読んでください。** 次の 5 項目は、あとから変更できません。変更するには作り直しが必要です。

| #   | 項目                          | どこで決めるか                             | 変更するには                                             |
| --- | --------------------------- | ----------------------------------- | -------------------------------------------------- |
| 1   | **Supabase のリージョン**         | [03.1.2](infra_design_03_Supabase作成.md#0312-プロジェクトを作成する)              | プロジェクトの作り直し（データの移行が必要）                             |
| 2   | **Google Cloud のプロジェクト ID** | [05.1.2](infra_design_05_CloudRun構築.md#0512-google-cloud-プロジェクトを作成する) | プロジェクトの作り直し                                        |
| 3   | **Cloud Run のサービス名**        | [05.1.4](infra_design_05_CloudRun構築.md#0514-サービスの設定値)                 | サービスの作り直し（URL が変わる）                                |
| 4   | **Cloud Run のリージョン**        | [05.1.4](infra_design_05_CloudRun構築.md#0514-サービスの設定値)                 | サービスの作り直し（URL が変わる）                                |
| 5   | **Supabase のデータベースパスワード**   | [03.1.2](infra_design_03_Supabase作成.md#0312-プロジェクトを作成する)              | 再生成は可能。ただし接続文字列を作り直し、**Cloud Run の環境変数も更新**する必要がある |

特に **1 と 4 は組み合わせが重要**です。Cloud Run の無料枠は米国リージョンが対象で、本書では `us-central1`（アイオワ）を使います。データベースが地理的に遠いと、すべての問い合わせで太平洋を横断することになり、画面表示が遅くなります。そのため **Supabase も米国東部（East US / North Virginia）を選びます。**

一方で、次の項目は**あとから変更できます**。迷って作業が止まるより、まず動かすことを優先してください。

| 項目                     | 変更方法               |
| ---------------------- | ------------------ |
| Cloud Run の環境変数        | 新しいリビジョンとして編集・デプロイ |
| Cloud Run のメモリ・インスタンス数 | 同上                 |
| Cloud Run のサービスアカウント   | 同上                 |
| Cloud Build のビルド設定     | トリガーの編集            |
