# 11.1 2 つ目以降のシステムを構築する

テンプレートを複製して別システムを作る場合の考え方と作業手順。

インフラ構築手順書の一部。全体の目次と進め方は [`README.md`](README.md) を見ること。


**このテンプレートを複製して、別のシステムをもう 1 つ作る場合**の考え方です。本書の手順 1〜5 をもう一度行うことになりますが、**すでに済んでいる作業と、新しく作るものを整理しておくと迷いません。**

## 11.1.1 何を新しく作るか

| 対象                      | 2 つ目以降         | 理由                                                      |
| ----------------------- | -------------- | ------------------------------------------------------- |
| GitHub アカウント            | **そのまま使う**     | 1 つのアカウントで複数のリポジトリを持てます                                 |
| Google Cloud アカウント      | **そのまま使う**     | 課金設定も引き継がれます                                            |
| Supabase アカウント          | **そのまま使う**     |                                                         |
| **GitHub リポジトリ**        | **新しく作る**      | システムごとにソースコードを分けます（[10.1.2](#1012-テンプレートを複製する)）            |
| **Supabase プロジェクト**     | **新しく作る**      | データベースを分離します（[10.1.3](#1013-supabase-と-google-cloud-の分け方)） |
| **Google Cloud プロジェクト** | **新しく作ることを推奨** | 費用と権限をシステムごとに分けられます                                     |
| **Cloud Run サービス**      | **新しく作る**      | サービス名が URL になります                                        |

## 11.1.2 テンプレートを複製する

複製の方法は 3 つあります。**どれを選んでも、以降の手順（本書の手順 1 以降）は同じです。**

| 方法                       | 手順                                                                                               | 向いている場合           |
| ------------------------ | ------------------------------------------------------------------------------------------------ | ----------------- |
| **テンプレートリポジトリ機能を使う**（推奨） | 元のリポジトリの Settings → General → **Template repository** を有効にしておき、`Use this template` から新しいリポジトリを作る | 今後も繰り返し複製する場合     |
| **コマンドで複製する**            | `gh repo create <新リポジトリ名> --private --template <ユーザー名>/<元リポジトリ名>`                                | 上と同じ結果をコマンドで得たい場合 |
| **フォルダごとコピーする**          | 元のフォルダをコピーし、**`.git` フォルダを削除**してから本書の [02.1.1](infra_design_02_GitHubリポジトリ.md#0211-コミットの署名を設定する) を実施する                              | 元の変更履歴を引き継ぎたくない場合 |

> **`.git` フォルダの削除を忘れないでください。** フォルダをコピーしただけでは元のリポジトリとの紐付けが残っており、**元のシステムへ push してしまう恐れがあります。**

### 複製したあとに変更する箇所

| 対象                      | 変更内容                                            |
| ----------------------- | ----------------------------------------------- |
| `package.json` の `name` | 新しいシステムの名前                                      |
| `README.md` / `docs/`   | システム名・説明                                        |
| **`AUTH_SECRET`**       | **必ず新しく生成する。** 使い回すと、片方の鍵が漏れたときに両方のシステムが影響を受けます |
| **初期管理者のパスワード**         | **必ず変える**（[04.1.5](infra_design_04_本番データベース初期化.md#0415-初期管理者を登録する)）                |
| Supabase の接続情報・キー       | 新しいプロジェクトの値                                     |
| Cloud Run のサービス名        | 新しい名前（URL になります）                                |

> **元のシステムの `.env` をコピーしないでください。** 接続先が元のシステムのデータベースのままになり、**別システムのつもりで既存データを書き換えてしまいます。** `.env.example` からコピーし直してください。

## 11.1.3 Supabase と Google Cloud の分け方

### Supabase

**システムごとにプロジェクトを分けてください。** データベースが混在すると、片方の作業がもう片方へ影響します。

> **無料枠で同時に稼働できるプロジェクト数には上限があります。** 上限に達した場合は、使わないプロジェクトを停止するか、有料プランを検討してください。最新の条件は [Supabase の料金ページ](https://supabase.com/pricing)で確認できます。

**リージョンは、対応する Cloud Run と近い場所を選びます**（[00.4 章](infra_design_00_概要と全体構成.md#004-あとから変更できない項目)）。1 つ目と同じ構成にするのであれば、East US (North Virginia) です。

### Google Cloud

| 方針                  | 内容                              | 判断の目安                                        |
| ------------------- | ------------------------------- | -------------------------------------------- |
| **プロジェクトを分ける**（推奨）  | システムごとに Google Cloud プロジェクトを作る  | 費用・権限・ログをシステム単位で分けられる。**案件ごとに担当者が違う場合は特に推奨** |
| 同じプロジェクト内にサービスを追加する | 1 つのプロジェクトに Cloud Run サービスを複数作る | 管理する画面が 1 つで済む。ただし費用の内訳が分かりにくくなる             |

> **どちらの方針でも、無料枠は「アカウント単位」ではなく利用量の合計に対して適用されます。** システムが増えるほど無料枠の消費は早くなるため、[05.1.4](infra_design_05_CloudRun構築.md#0514-サービスの設定値) のインスタンスの最大数は**システムごとに必ず設定してください。**

## 11.1.4 2 つ目以降の作業手順

本書の手順を、次のとおり読み替えて実施します。

| 手順                                             | 2 つ目以降                                                |
| ---------------------------------------------- | ----------------------------------------------------- |
| [手順1 GitHub](infra_design_02_GitHubリポジトリ.md#021-手順1-github-リポジトリを用意する)         | アカウント作成は不要。**リポジトリの作成から**実施（[10.1.2](#1012-テンプレートを複製する)） |
| [手順2 Supabase](infra_design_03_Supabase作成.md#031-手順2-supabase-を作成する)          | アカウント作成は不要。**プロジェクトの作成から**実施                          |
| [手順3 データベースの初期化](infra_design_04_本番データベース初期化.md#041-手順3-本番データベースを初期化する)        | **そのまま実施。** 接続文字列が新しいプロジェクトのものであることを必ず確認する            |
| [手順4 Cloud Run](infra_design_05_CloudRun構築.md#051-手順4-google-cloud-run-を構築する) | アカウント作成・課金の有効化は不要。**プロジェクトまたはサービスの作成から**実施            |
| [手順5 動作確認](infra_design_06_CloudRun動作確認.md#061-手順5-動作を確認する)                    | **そのまま実施**                                            |

> **接続先の取り違えが最も起こりやすい作業です。** 手順 3 でデータベースを初期化する際は、**接続文字列に含まれるプロジェクト ref が新しいものか**を必ず確認してください。誤ると、稼働中のシステムのデータベースを変更してしまいます。
