## 22.1 お知らせ更新（NEWS-02の行の「編集」）

### 22.1.1 ポップアップの開き方

一覧の行の「編集」ボタンを押すと、`ui/news-edit-dialog.tsx`が管理するDialogが開く。詳細画面を経由せず、一覧の行から直接開く点が、詳細画面から遷移するマスタ更新画面（MST-05）と異なる。ダイアログを開く際にサーバーへ問い合わせず、一覧が既に保持している行データ（タイトル・カテゴリ・本文・公開期間・公開トグル・`updatedAt`）を初期値として使う。

### 22.1.2 表示・入力項目

| 項目 | UI部品 | 編集可否 | 入力仕様 |
| --- | --- | :---: | --- |
| タイトル | テキストボックス | 可 | §21.1.2と同じ。初期値は現在のタイトル |
| カテゴリ | プルダウン | 可 | §21.1.2と同じ。初期値は現在のカテゴリ |
| 本文 | テキストエリア | 可 | §21.1.2と同じ。初期値は現在の本文 |
| 公開開始日時 | 日時入力 | 可 | §21.1.2と同じ。初期値は現在の公開開始日時（空欄の場合は空欄のまま） |
| 公開終了日時 | 日時入力 | 可 | §21.1.2と同じ。初期値は現在の公開終了日時 |
| 公開／非公開トグル | スイッチ | 可 | 初期値は現在の状態 |

**全項目を同時に変更できる。** 変更しない項目は現在値が初期表示されているため、触らずに済む。`updatedAt`はDialogを開いた時点の値を隠しフィールドとして保持し、実行時に送信する（§22.2）。

### 22.1.3 ボタン

| ボタン | 動作 |
| --- | --- |
| 確認する | 入力内容を検証し、問題がなければお知らせ確認（NEWS-03・更新モード）へ進む。データベースの更新は行わない |
| キャンセル | 入力内容を破棄してDialogを閉じる |

### 22.1.4 更新モードの実行処理（NEWS-03の「実行」）

1. 対象のお知らせが現在も存在することを確認する。存在しない場合は`NEWS_NOT_FOUND`。
2. Dialogを開いた時点の`updatedAt`と、データベースに保存されている現在の`updatedAt`を比較する。一致しない場合は`NEWS_CONCURRENT_UPDATE`（§22.2）。
3. 変更後の入力値をサーバー側で再検証する（§21.3）。
4. 全項目を更新し、`updatedBy`に実行した利用者のユーザーIDを設定する。`createdBy`は変更しない。
5. Dialogを閉じ、現在の検索条件・ページ番号・並び順を保持したままNEWS-02の一覧を再読み込みし、更新完了メッセージを表示する。

検証の順序は、存在 → 同時更新 → 入力検証の順とする（同時更新を先に確認することで、既に無い対象や古い前提に対して無駄な入力検証を行わない）。

一部の項目だけを変更した場合も、残りは変更前の値のまま同じ処理で更新する。項目ごとにServer Actionを分けない（マスタ更新と同じ方針。§13.3相当）。変更前と変更後の値が完全に同じ場合も実行を許可し、`updatedAt`と`updatedBy`だけが更新される。

## 22.2 更新時の競合

Dialogを開いた時点の`updatedAt`を、実行時に送信する。データベースに保存されている現在の`updatedAt`と一致しない場合は更新せず、以下のメッセージを表示する（マスタ更新と同じ楽観的排他制御。§13.2相当）。

```text
ほかの利用者によって更新されています。最新の内容を確認してから、もう一度操作してください。
```

要件定義には同時編集についての明記はないが、複数の管理者が同じお知らせをほぼ同時に編集する場面は起こり得るため、マスタと同じ方式で導入する（要件定義 §01.9）。

検証の順序は以下のとおりとする。

| 順序 | 検証内容 | 一致しない場合 |
| --- | --- | --- |
| 1 | 書き込み権限があるか | `FORBIDDEN` |
| 2 | 対象が存在するか | `NEWS_NOT_FOUND` |
| 3 | `updatedAt`が一致するか | `NEWS_CONCURRENT_UPDATE` |

## 22.3 更新

- タイトルだけを更新できる。
- カテゴリだけを更新できる。
- 本文だけを更新できる。
- 公開開始日時・公開終了日時だけを更新できる。
- 公開／非公開トグルだけを更新できる。
- 全項目を同時に更新できる。
- 変更後のタイトル・本文が文字数制限に違反する場合は拒否する（§21.4と同じ検証）。
- 変更後の公開終了日時が変更後の公開開始日時より前の場合は拒否する。
- 値を変えずに実行した場合も成功し、`updatedAt`と`updatedBy`だけが更新される。
- 存在しないお知らせの更新を拒否する（`NEWS_NOT_FOUND`）。
- `updatedAt`が異なる場合に同時更新エラーとなる（`NEWS_CONCURRENT_UPDATE`）。
- 権限・存在・同時更新・入力検証の順に検証される。
- 更新で`updatedBy`だけが更新され、`createdBy`は変わらない。
- 確認状態を表示しただけではデータベースが更新されない。
- `VIEWER`による更新用Server Actionの直接実行を`FORBIDDEN`で拒否する。
