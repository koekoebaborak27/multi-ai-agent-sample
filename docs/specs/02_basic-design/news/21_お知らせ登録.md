## 21.1 お知らせ登録（NEWS-02の「新規登録」）

### 21.1.1 ポップアップの開き方

一覧画面（NEWS-02）の「新規登録」ボタンを押すと、`ui/news-create-dialog.tsx`が管理するDialogが開く。マスタ機能のように別画面（`/news/new`のようなURL）へは遷移しない。参考実装は`src/modules/user/ui/user-edit-dialog.tsx`（Dialog + Server Action）だが、user-edit-dialogと異なり**確認状態を挟む**（§21.2）。

Dialogが開いている間の内部状態（入力中か確認中か）は`ui/news-confirmation.tsx`と共通のフォームコンポーネントが、マスタの`MasterFormState`と同じ考え方の`mode`（`"create"` / `"update"`）・`phase`（`"input"` / `"confirm"`）を持つ状態で管理する。「確認する」を押すたびにServer Actionを呼び、`phase`を`"confirm"`にして返す（サーバー側の再検証を経てから確認状態に入るため。§21.2.2で詳細）。

### 21.1.2 入力項目

| 項目 | UI部品 | 必須 | 入力仕様 |
| --- | --- | :---: | --- |
| タイトル | テキストボックス | 必須 | 1文字以上200文字以内 |
| カテゴリ | プルダウン | 必須 | 「障害情報」「メンテナンス」「お知らせ」の3択。初期値は未選択 |
| 本文 | テキストエリア | 必須 | 1文字以上3000文字以内。改行はそのまま保持する |
| 公開開始日時 | 日時入力（`datetime-local`） | 任意 | 空欄可。日付と時刻の両方を指定できる |
| 公開終了日時 | 日時入力（`datetime-local`） | 任意 | 空欄可。公開開始日時より前は不可（§21.3） |
| 公開／非公開トグル | スイッチ | — | 初期値はON |

### 21.1.3 ボタン

| ボタン | 動作 |
| --- | --- |
| 確認する | 入力内容を検証し、問題がなければお知らせ確認（NEWS-03・新規登録モード）へ進む。データベースへの登録は行わない |
| キャンセル | 入力内容を破棄してDialogを閉じる |

## 21.2 お知らせ確認（NEWS-03）

お知らせ確認は、Dialogを閉じずに同じポップアップの中身を切り替えて表示する。新規登録と更新で同じコンポーネント（`ui/news-confirmation.tsx`）を使い、処理モードに応じて表示項目・実行するServer Action・戻り先を切り替える（マスタの`master-confirmation.tsx`と同じ考え方）。

### 21.2.1 表示項目

| 項目 | 新規登録モード | 更新モード |
| --- | --- | --- |
| 処理内容 | 新規登録 | 更新 |
| タイトル | 入力したタイトル | 入力した変更後のタイトル |
| カテゴリ | 選択したカテゴリの表示名 | 選択した変更後のカテゴリの表示名 |
| 本文 | 入力した本文（改行を保持して表示） | 入力した変更後の本文（改行を保持して表示） |
| 公開開始日時 | 入力した値（空欄なら「未設定（登録した時点から公開）」） | 入力した変更後の値（空欄なら「未設定（登録した時点から公開）」） |
| 公開終了日時 | 入力した値（空欄なら「未設定（期限なし）」） | 入力した変更後の値（空欄なら「未設定（期限なし）」） |
| 公開／非公開トグル | 選択した状態 | 選択した変更後の状態 |

更新モードでは、実行する変更後の入力内容だけを表示する。変更前の値との比較や「変更なし」の表示はしない。

### 21.2.2 ボタン

| ボタン | 新規登録モード | 更新モード |
| --- | --- | --- |
| 実行 | 入力内容を再検証し、登録用Server Actionでお知らせを登録する | 入力内容・同時更新の有無を再検証し、更新用Server Actionでお知らせを更新する |
| 入力内容を修正 | 入力値を保持したまま入力状態（NEWS-02の登録ポップアップ）へ戻る | 入力値を保持したまま入力状態（NEWS-02の編集ポップアップ）へ戻る |
| キャンセル | 入力内容を破棄してDialogを閉じる | 入力内容を破棄してDialogを閉じる |

### 21.2.3 新規登録モードの実行処理

1. 入力値をサーバー側で再検証する（§21.3）。
2. お知らせを登録する。`createdBy`と`updatedBy`に実行した利用者のユーザーIDを設定する。
3. Dialogを閉じ、現在の検索条件・ページ番号・並び順を保持したままNEWS-02の一覧を再読み込みし、登録完了メッセージを表示する。

登録はお知らせ1行の挿入だけであり、複数テーブルにまたがる更新が無いため、明示的なトランザクションは不要である。一意制約が無いため、登録時にデータベース側の重複エラーは発生しない（マスタと異なり、コード等の一意な業務キーを持たないため）。

## 21.3 入力項目の検証

- **タイトル**：必須。前後の空白を除去したうえで1文字以上200文字以内。
- **カテゴリ**：必須。`INCIDENT` / `MAINTENANCE` / `NEWS` のいずれか。
- **本文**：必須。1文字以上3000文字以内。改行以外の前後の空白除去は行わない（本文中の意図した空白・字下げを壊さないため）。文字数はUnicodeコードポイント単位で数える。
- **公開開始日時・公開終了日時**：任意。指定する場合は妥当な日時であること。
- **公開終了日時が公開開始日時より前**：登録・更新を止め、公開終了日時の入力欄の下に赤字でエラーを表示する（要件定義 §01.4.2「入力の決まりごと」）。両方とも空欄、または片方だけが指定されている場合はこの検証を行わない。
- **公開／非公開トグル**：真偽値。未送信の場合はOFFとして扱う（HTMLのcheckbox/switchの標準的な送信仕様に合わせる）。

## 21.4 登録

- 全項目を入力して登録できる。
- 公開開始日時・公開終了日時を両方空欄のまま登録できる。
- タイトルが200文字の場合は登録でき、201文字の場合は拒否する。
- 本文が3000文字の場合は登録でき、3001文字の場合は拒否する。
- 公開終了日時が公開開始日時より前の場合は拒否し、公開終了日時の入力欄にエラーが表示される。
- 公開終了日時が公開開始日時と同じ日時の場合は登録できる（「より前」だけを拒否する。同時刻は許可する）。
- 公開／非公開トグルをOFFにしたまま登録できる。
- 確認状態を表示しただけではデータベースへ登録されない。
- 登録時に`createdBy`と`updatedBy`へ実行者のユーザーIDが設定される。
- `VIEWER`による登録用Server Actionの直接実行を`FORBIDDEN`で拒否する。
