## 23.1 お知らせ削除確認ダイアログ

一覧の行の「削除」ボタンを押したときに表示する確認ダイアログ。詳細画面が無いため、一覧の行の上に直接重ねて表示する（マスタ削除確認ダイアログが詳細画面の上に表示するのと同じ考え方だが、対象画面が詳細画面ではなく一覧の行である点が異なる）。参考実装は`src/modules/master/ui/master-delete-dialog.tsx`。

### 23.1.1 表示項目

| 項目 | 表示内容 |
| --- | --- |
| 見出し | 「お知らせを削除しますか？」 |
| タイトル | 削除対象のタイトル |
| カテゴリ | 削除対象のカテゴリの表示名 |
| 警告 | 後述の固定文言 |
| ボタン | 「キャンセル」および「削除する」 |

警告として、以下の固定文言を表示する。

```text
削除したお知らせは元に戻せません。
```

### 23.1.2 ダイアログの仕様

マスタ削除確認ダイアログ（[`../master/14_マスタ削除.md`](../master/14_マスタ削除.md#1412-ダイアログの仕様)）と同じ方式に従う。

- shadcn/uiの`AlertDialog`を使用する。
- 「削除する」ボタンは`variant="destructive"`とする。
- 警告は色だけで伝えず、アイコン（`TriangleAlert`）と文言を併用する。
- ダイアログを開く際にサーバーへ問い合わせない。表示に必要な値は一覧が既に保持しているものを使用する。
- 削除処理の実行中は「削除する」ボタンを無効化し、二重送信を防止する。処理中はダイアログを閉じられないようにする。
- 初期フォーカスは「キャンセル」ボタンに置き、Escapeキーで閉じられるようにする。

### 23.1.3 削除の実行処理

1. Server Actionで書き込み権限を検証する。
2. 対象のお知らせが現在も存在することを確認する。
3. 一覧を表示した時点の`updatedAt`と、データベースに保存されている現在の`updatedAt`を比較する。
4. 一致する場合、対象のお知らせを物理削除する。
5. 現在の検索条件・ページ番号・並び順を保持したままNEWS-02の一覧を再読み込みし、削除完了メッセージを表示する。

検証の順序は上記のとおりとし、権限 → 存在 → 同時更新の順に判定する。

## 23.2 削除時の競合

削除にも更新と同じ楽観的排他制御を適用する（§22.2）。一覧を表示した時点の`updatedAt`を、削除実行時に送信する。データベースに保存されている現在の`updatedAt`と一致しない場合は削除せず、§22.2と同じメッセージを表示する。

一覧を表示した後に別の利用者がお知らせを更新していた場合、利用者が確認した内容（一覧の表示）と実際に削除される内容が異なる可能性があるため、削除にも同時更新の確認を適用する。

検証の順序は以下のとおりとする。

| 順序 | 検証内容 | 一致しない場合 |
| --- | --- | --- |
| 1 | 書き込み権限があるか | `FORBIDDEN` |
| 2 | 対象が存在するか | `NEWS_NOT_FOUND` |
| 3 | `updatedAt`が一致するか | `NEWS_CONCURRENT_UPDATE` |

確認ダイアログを表示した後に別の利用者が同じ対象を削除していた場合、対象は既に存在しないため`NEWS_NOT_FOUND`となる。物理削除では「存在しない」と「既に削除された」を区別できないため、両者を同一のエラーとして扱う（マスタ削除と同じ扱い）。

## 23.3 削除

- 存在するお知らせを削除できる。
- 削除したお知らせは一覧の検索結果に含まれない。
- 削除したお知らせはトップ画面にも表示されない。
- 存在しないお知らせの削除を拒否する（`NEWS_NOT_FOUND`）。
- `updatedAt`が異なる場合に同時更新エラーとなる（`NEWS_CONCURRENT_UPDATE`）。
- 権限・存在・同時更新の順に検証される。
- 削除処理で削除対象のタイトルがログへ渡される（§00.6.1）。
- `VIEWER`による削除用Server Actionの直接実行を`FORBIDDEN`で拒否する。
