## 10.1 トップ画面（NEWS-01）

既存のダッシュボード（`src/app/(main)/page.tsx`）を拡張する。画面構成そのもの（見出し・カードのレイアウト）は変えず、お知らせ部分の表示内容と挙動を変更する。

### 10.1.1 表示対象

公開中のお知らせ（§01.1.6の判定を満たすもの）だけを表示する。過去に公開が終わったもの、公開開始前のもの、非公開中のものは表示しない。

### 10.1.2 並び順

§01.1.5のとおり、`ORDER BY category ASC, COALESCE(startAt, createdAt) DESC` で取得する。カテゴリの優先順位（障害情報→メンテナンス→お知らせ）は`category`の値の選定（§01.1.4）により、追加のロジックなしで実現される。

### 10.1.3 1件ごとの表示

| 項目 | 表示内容 |
| --- | --- |
| 1行目 | 「公開日時：タイトル」を太字で表示する。公開日時は `COALESCE(startAt, createdAt)` の実効値を使い、時刻まで含める（例：`2026-08-24 09:00`） |
| 2行目以降 | 本文を全文表示する。クリック等の操作は不要で、改行はそのまま反映する（`whitespace-pre-line`）。太字・リンク等の装飾はしない |

文字色はカテゴリに応じて出し分ける。

| カテゴリ | 文字色 |
| --- | --- |
| 障害情報（`INCIDENT`） | 赤字（`text-destructive`） |
| メンテナンス（`MAINTENANCE`） | 青字 |
| お知らせ（`NEWS`） | 黒字（既定の文字色。指定なし） |

本文はプレーンテキストとして扱い、HTMLタグ等をそのまま実行させない。Reactの標準のテキスト描画（`{body}`）を使う限り自動でエスケープされるため、`dangerouslySetInnerHTML`は使用しない。

0件の場合は「現在お知らせはありません」と表示する。

### 10.1.4 コンポーネント構成

| コンポーネント | 役割 |
| --- | --- |
| `src/app/(main)/page.tsx`（Server Component） | ログイン確認（既存のまま）、最新20件（`env.PAGE_SIZE`）の初回取得、`NewsFeed`への引き渡し |
| `ui/news-feed.tsx`（Client Component） | 取得済みのお知らせ一覧と「さらに表示」ボタンの表示・状態管理（§10.2） |
| `ui/news-item.tsx` | お知らせ1件分の表示（§10.1.3の1行目・2行目、カテゴリによる文字色） |

初回表示はこれまでどおりServer Componentが行う（`dynamic = "force-dynamic"` は維持する）。「さらに表示」以降の追加取得だけをクライアント側で行う。

## 10.2 さらに表示

### 10.2.1 挙動

- 初期表示は最新20件（`env.PAGE_SIZE`）。
- 「さらに表示」ボタンを押すと、画面遷移・全体再読み込みをせずに次の20件を取得し、表示済みの一覧の末尾に継ぎ足す。
- 繰り返し押すことができ、件数の上限は設けない。
- 公開中の全件を表示し終えたら「さらに表示」ボタンを非表示にする。
- 取得中はボタンを無効化し、二重押下による重複取得を防ぐ。

この挙動は、他の一覧画面（マスタ・契約先・契約等）が採用しているURLクエリでのページ切り替えとは異なる、本テンプレート初のクライアント側での追加取得パターンである（要件定義 §01.9）。トップ画面はページ番号や検索条件を持たない単純な新着表示であり、URLクエリを増やすよりも「押した分だけ増える」挙動の方が要件（「さらに表示」）に直接対応するため、この画面に限って採用する。他の一覧画面へこのパターンを広げることは意図していない。

### 10.2.2 実現方式

`ui/news-feed.tsx`が次の状態を保持する。

| 状態 | 内容 |
| --- | --- |
| `items` | 現在表示しているお知らせの配列。初期値はServer Componentから渡された初回取得分 |
| `offset` | 次に取得する位置。初期値は初回取得件数（`items.length`） |
| `hasMore` | 「さらに表示」ボタンを表示するかどうか。初回取得件数が`env.PAGE_SIZE`未満だった場合は`false` |
| `pending` | 取得中かどうか（ボタンの無効化に使う） |

「さらに表示」を押すと、`src/modules/news/actions.ts` に定義する読み取り専用のServer Action `loadMoreNewsAction(offset: number)` を呼び出す。

```text
loadMoreNewsAction(offset) の処理:
1. §01.1.6の判定を満たすお知らせを、§01.1.5の並び順で offset 件スキップして env.PAGE_SIZE 件取得する
2. 取得件数が env.PAGE_SIZE 未満なら hasMore=false、そうでなければ hasMore=true を一緒に返す
```

Server Actionは通常は書き込み処理（`actions.ts`）に使うものだが、この読み取り専用の呼び出しも同じファイルに置く。クライアントコンポーネントから直接呼び出せる関数として最も単純に実装できる形であり、Route Handlerを新設してAPIエンドポイントを増やす必要が無いためである（§00.7）。書き込み権限の確認は行わない（閲覧はログイン済みの全ロールに許可されており、`src/proxy.ts`がログイン確認を既に行っているため）。

`offset`は取得のたびに公開状態が変わる可能性があるお知らせを対象にしたページ送りであり、取得中に新しいお知らせが公開されたり非公開になったりした場合、まれに同じお知らせが重複して表示される、または表示されないまま飛ばされることがある。この挙動は許容する。トップ画面は最新の状況を素早く伝えるための表示であり、追加取得のたびに全件を再計算する厳密な一貫性は求められていない。
