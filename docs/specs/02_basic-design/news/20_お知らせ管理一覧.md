## 20.1 お知らせ管理画面（NEWS-02）

### 20.1.1 権限

`ADMIN`・`OPERATOR`だけが入場できる。`VIEWER`はナビゲーションメニューに項目が表示されず、URLを直接開いてもroute guardで`/`へリダイレクトされる（§00.3）。

### 20.1.2 検索条件

| 項目 | UI部品 | 必須 | 説明 |
| --- | --- |:---:| --- |
| カテゴリ | プルダウン | 任意 | 「障害情報」「メンテナンス」「お知らせ」「すべて」から1つを選択する。初期値は「すべて」 |
| 文言 | テキストボックス | 任意 | タイトルまたは本文を対象に部分一致検索する |

検索条件はURLクエリとして保持する。

```text
/news?category={カテゴリまたはall}&keyword={検索文字列}&sort={ソート列}&order={ascまたはdesc}&page={ページ番号}
```

`category=all` が「すべて」を表す。`keyword`の前後の空白は検索前に除去する。タイトル・本文のいずれかに大文字小文字を区別しない部分一致があれば検索結果に含める（マスタ検索と同じ`contains`条件）。カテゴリと文言の両方が指定された場合はAND条件とする。検索条件を変更して検索した場合、ページ番号を1へ戻す。

### 20.1.3 一覧

| 列 | 表示内容 | 並び替え |
| --- | --- | :---: |
| タイトル | タイトル | 可 |
| カテゴリ | カテゴリの表示名 | 可 |
| 公開開始日時 | `startAt`の値。`NULL`の場合は「—」を表示する（§01.1.5のとおり、実際の並び替えには`COALESCE(startAt, createdAt)`を使うが、表示には生の値を使う） | 可 |
| 公開終了日時 | `endAt`の値。`NULL`の場合は「—」を表示する | 可 |
| 公開ステータス | 「公開中」「公開前」「終了」「非公開中」のいずれか（§20.3） | 不可（計算値のため） |
| 登録者 | `createdBy`を表示名へ解決したもの | 不可 |
| 更新者 | `updatedBy`を表示名へ解決したもの | 不可 |
| 操作 | 「編集」「削除」ボタン | — |

並び替え対象を4列（タイトル・カテゴリ・公開開始日時・公開終了日時）に絞っているのは、公開ステータスがDBに保存されない計算値であること、登録者・更新者は画面には表示名で出す一方DB上は`User.id`だけを保持しており（外部キー無し）、表示名での並び替えにはテーブル結合相当の処理が別途必要になることの2点による（要件定義 §01.9）。

一覧仕様は以下のとおりとする。

- サーバー側で検索・並び替え・ページングを行う。
- 1ページの表示件数は既存の`env.PAGE_SIZE`を使用する。
- 初期の並び順は公開開始日時の新しい順（`COALESCE(startAt, createdAt) DESC`。§01.1.5）とする。
- 見出しを選択すると、検索結果全体をその列で昇順に並べ替える。同じ見出しを再度選択すると降順へ切り替える。
- ソート列はURLクエリの`sort`（`title` / `category` / `startAt` / `endAt`）、方向は`order`（`asc` / `desc`）へ保持する。列を切り替えた場合は昇順とし、ページ番号を1へ戻す。
- 「公開開始日時」列でのソートも§01.1.5の`COALESCE`を使う（「—」表示の行が常に末尾へ来る、という単純な並びにはならない点に注意）。「公開終了日時」列でのソートは`endAt`をそのまま使い、`NULL`は`NULLS LAST`として末尾に置く。
- 操作列はソート対象外とし、見出しに「操作」は表示しない。
- 一覧の上部に検索結果の総件数と現在のページを表示する。
- 検索結果が0件の場合は「該当するお知らせがありません」と表示する。
- 一覧は`@/shared/ui/table`のTableコンポーネント・`SortableTableHead`を使用する（マスタ一覧と同じ実装方針。要件定義 §01.9）。
- 公開期間外（公開前・公開終了後）や非公開中のものも含めて全件を対象とする（管理者は先の予定や過去の履歴も含めて編集できる必要があるため。要件定義 §01.4.5）。

### 20.1.4 ボタン

| ボタン | 動作 |
| --- | --- |
| 新規登録 | 登録ポップアップを開く（→ [`21_お知らせ登録.md`](21_お知らせ登録.md)） |
| 編集（行ごと） | 更新ポップアップを開く（→ [`22_お知らせ更新.md`](22_お知らせ更新.md)） |
| 削除（行ごと） | 削除確認ダイアログを開く（→ [`23_お知らせ削除.md`](23_お知らせ削除.md)） |

画面見出し「お知らせ管理」の右側に「新規登録」ボタンを配置する。

## 20.2 検索

- カテゴリだけで検索できる。
- 文言だけで検索できる（タイトル・本文のいずれかに部分一致すれば該当）。
- カテゴリと文言のAND条件で検索できる。
- 検索条件を指定しない場合は全件が対象になる。
- 検索結果が`env.PAGE_SIZE`件ごとにページングされる。
- 初期表示は公開開始日時（実効値）の新しい順に並ぶ。
- 検索条件を変更すると、ページ番号が1に戻る。

## 20.3 公開ステータスの判定

一覧の「公開ステータス」列は、`published`と公開期間（`startAt`・`endAt`）から次のように判定する（要件定義 §01.4.5）。DBには保存せず、一覧取得のたびに計算する。

```text
1. published が false                              → 「非公開中」
2. startAt が指定されていて、現在日時より後         → 「公開前」
3. endAt が指定されていて、現在日時より前           → 「終了」
4. 上記のいずれにも該当しない                       → 「公開中」
```

判定は`published`を最優先する。**トグルがOFFの場合、公開期間の状態に関わらず常に「非公開中」と表示する。** 公開期間中に一時的に非表示へ切り替えたお知らせも、公開期間外のお知らせも、管理者から見れば同じ「今は表示されていない」状態であるため、表示上は区別しない（内部の判定式は§01.1.6と共通）。
