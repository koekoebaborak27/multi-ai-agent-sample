# お知らせ管理機能 基本設計書

お知らせ（`News`モデル）の表示・登録・更新・削除の基本設計。要件定義は [`01_requirements/news/01_お知らせ管理.md`](../../01_requirements/news/01_お知らせ管理.md) を参照すること。

## ファイルの分け方

**機能ごとに1ファイル。** マスタ管理機能（[`../master/README.md`](../master/README.md)）と同じ粒度で分割している。

**見出し番号はファイル名の連番と揃えている。** 各ファイルの見出しは、そのファイル名の連番（`00`・`01`・`10`・`20`〜`23`）を先頭に持つ。他ファイルの節を指す `§20.1` のような参照は、対象ファイルの見出し番号を表す。

| ファイル | 内容 |
|---|---|
| [`00_お知らせ管理共通.md`](00_お知らせ管理共通.md) | 機能全体の前提。概要・用語・権限・画面一覧・画面遷移・エラー設計・モジュール構成・テスト方針・対象外。**最初に読む。** |
| [`01_データベース.md`](01_データベース.md) | `News`モデル（旧`Announcement`）の設計・制約・並び順の実現方法。全機能が参照する。 |
| [`10_トップ画面お知らせ表示.md`](10_トップ画面お知らせ表示.md) | トップ画面（全ロール）でのお知らせ表示と「さらに表示」による追加取得。 |
| [`20_お知らせ管理一覧.md`](20_お知らせ管理一覧.md) | お知らせ管理画面（`ADMIN`/`OPERATOR`）の検索・一覧・並び替え・ページング。 |
| [`21_お知らせ登録.md`](21_お知らせ登録.md) | 登録ポップアップと確認状態、入力検証。**確認状態の仕様はここが正本**で、更新（`22`）からも使う。 |
| [`22_お知らせ更新.md`](22_お知らせ更新.md) | 更新ポップアップと楽観ロック。確認状態は [`21_お知らせ登録.md`](21_お知らせ登録.md#212-お知らせ確認news-03) を参照する。 |
| [`23_お知らせ削除.md`](23_お知らせ削除.md) | 削除確認ダイアログ、削除時の競合、物理削除。 |
