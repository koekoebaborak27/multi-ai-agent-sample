## 11.1 画面

ルートは `/settings/password`（`src/app/(main)/settings/password/page.tsx`）。ログイン必須。**初回ログイン時の強制誘導先と、本人がいつでも任意に開ける自主変更画面を兼ねる**（画面・処理とも共通）。

| 状態 | 表示 |
|---|---|
| 通常（任意アクセス） | 見出し「パスワード変更」、現在のパスワード欄・新しいパスワード欄・確認用欄、「パスワードを変更」ボタン |
| `mustChangePassword = true`の状態で開いた場合 | 上記に加えて「初回ログインのため、パスワードの変更が必要です。」を赤字で表示 |

## 11.2 入力チェック

`validation.ts` の `passwordChangeSchema`。

| 項目 | 条件 | エラー文言 |
|---|---|---|
| 現在のパスワード | 必須 | 現在のパスワードを入力してください |
| 新しいパスワード | 必須・8文字以上128文字以内・英字を含む・数字を含む | （該当する条件のメッセージ） |
| 確認用パスワード | 必須・新しいパスワードと一致 | 確認用パスワードを入力してください／新しいパスワードが一致しません |
| 新しいパスワード | 現在のパスワードと異なること | 現在のパスワードと異なるものにしてください |

## 11.3 処理の流れ

Server Action（`changePassword`）で行う。`withOp`で包む。

1. ログイン中の利用者を取得する（取得できなければ「ログインが必要です」を返す）
2. 入力チェックを行う。誤りがあればその場でエラーを返す
3. `authService.changePassword`を呼ぶ
   1. 対象の利用者に`passwordHash`が無い（Entra専用）場合は「このアカウントはパスワード変更の対象外です」を返す
   2. 現在のパスワードを照合する。誤っていれば「ユーザーIDまたはパスワードが正しくありません」を返す
   3. 新しいパスワードをハッシュ化し、`authRepository.updatePassword`で`User.passwordHash`を更新する。このとき**`mustChangePassword`を`false`、`failedAttempts`を0へ同時にリセットする**（初回変更の解除と、それまでの失敗回数のクリアを1回の更新で行う）
4. 変更が成功したら、**その場でログアウトし`/login`へ遷移する**（引換券〈JWT〉に残る「変更が必要」の情報は変更後も古いままのため、次回ログイン時に作り直させる）

## 11.4 初回ログイン誘導との関係

- 誘導の判定自体はこの画面ではなく`src/proxy.ts`（→ [`10_ログイン画面.md` 10.7](10_ログイン画面.md#107-ルートガード)）が行う。`mustChangePassword`が`true`の利用者は、ログイン直後にどの画面を開こうとしてもこの画面へ差し戻される
- `mustChangePassword`を`false`に戻す更新は`authRepository.updatePassword`（→ [11.3](#113-処理の流れ)）で行う。変更後は自動ログアウトするため、次回ログイン時に発行されるJWTには最新の`mustChangePassword = false`が反映され、以後この画面への強制誘導は起きない
