## 14.1 削除条件

契約先は、**その契約先に紐づく契約が1件も存在しない場合にだけ**削除できる（要件定義で確定済み。マスタ分類の削除条件 [`master/24_マスタ分類削除.md` §24.1](../master/24_マスタ分類削除.md#241-削除条件) と同じ考え方）。

- 紐づく契約を一括削除する方式は採用しない。
- 紐づく契約が存在する場合は、先に契約側を削除する必要がある。

契約先詳細画面（PTY-04）には紐づく契約の一覧・件数を表示しない（§00.1）ため、利用者は「削除」ボタンを押すまで削除可否を把握できない。押下時に削除できない旨のエラーメッセージ（`PARTY_HAS_CONTRACTS`）で伝える。

## 14.2 契約先削除確認ダイアログ

契約先詳細画面（PTY-04）の「削除」ボタンを押したときに表示する確認ダイアログ。独立した画面ルートは作成せず、詳細画面の上に重ねて表示する。

### 14.2.1 表示項目

| 項目  | 表示内容              |
| --- | ----------------- |
| 見出し | 「契約先を削除しますか？」     |
| 名称  | 削除対象の契約先名称        |
| 分類  | 削除対象の契約先分類名（未設定の場合は「未設定」） |
| 警告  | 後述の固定文言            |
| ボタン | 「キャンセル」および「削除する」  |

警告として、以下の固定文言を表示する。

```text
削除した契約先は元に戻せません。
紐づく契約が1件でも存在する場合は削除できません。
```

### 14.2.2 ダイアログの仕様

`AlertDialog` の使用、二重送信防止、フォーカス制御は、マスタ削除確認ダイアログと同一とする（[`master/14_マスタ削除.md` §14.1.2](../master/14_マスタ削除.md#1412-ダイアログの仕様)）。

### 14.2.3 削除の実行処理

1. Server Actionで書き込み権限を検証する。
2. 対象契約先が現在も存在することを確認する。
3. 詳細画面を表示した時点の `updatedAt` と、データベースに保存されている現在の `updatedAt` を比較する。
4. 対象契約先に紐づく契約が0件であることを確認する。
5. 一致・条件を満たす場合、対象契約先を物理削除する。
6. 元の検索条件を復元した契約先検索一覧画面へ遷移し、削除完了メッセージを表示する。

検証の順序は上記のとおりとし、権限 → 存在 → 同時更新 → 紐づく契約の件数の順に判定する（マスタ分類削除と同じ順序。[`master/14_マスタ削除.md` §14.2](../master/14_マスタ削除.md#142-削除時の競合)）。

紐づく契約が残ったまま契約先が削除されないことは、最終的には `Contract.partyId` の外部キー制約が保証する。アプリケーションによる件数確認は、利用者へ理由を伝えるための事前確認と位置づける（マスタ分類削除と同じ考え方。[`master/24_マスタ分類削除.md` §24.3](../master/24_マスタ分類削除.md#243-削除の実行処理)）。

### 14.2.4 削除完了メッセージ

削除後は対象の詳細画面が存在しなくなるため、契約先検索一覧画面へリダイレクトしたうえで完了メッセージを表示する。方式はマスタ削除と同じ（[`master/14_マスタ削除.md` §14.1.4](../master/14_マスタ削除.md#1414-削除完了メッセージ)）。

```text
/parties?keyword={契約先名称}&companyTypeId={マスタIDまたはall}&sort={ソート列}&order={ascまたはdesc}&page={ページ番号}&deleted=1
```

## 14.3 削除時の競合

削除にも更新と同じ楽観的排他制御を適用する（§13.2）。検証の順序は次のとおりとする。

| 順序 | 検証内容               | 一致しない場合                |
| -- | ------------------ | ---------------------- |
| 1  | 書き込み権限があるか         | `FORBIDDEN`             |
| 2  | 対象が存在するか           | `PARTY_NOT_FOUND`       |
| 3  | `updatedAt` が一致するか | `PARTY_CONCURRENT_UPDATE` |
| 4  | 紐づく契約が0件か          | `PARTY_HAS_CONTRACTS`    |

確認ダイアログを表示した後に別の利用者が同じ対象を削除していた場合、対象は既に存在しないため `PARTY_NOT_FOUND` となる。

### 14.3.1 テスト方針

- 紐づく契約が無い契約先を削除できる。
- 紐づく契約が1件でも存在する場合は `PARTY_HAS_CONTRACTS` となり、拒否される。
- 存在しない契約先の削除を拒否する（`PARTY_NOT_FOUND`）。
- `updatedAt` が異なる場合に同時更新エラーとなる（`PARTY_CONCURRENT_UPDATE`）。
- 権限、存在、同時更新、紐づく契約の件数の順に検証される。
- 削除した契約先の詳細取得が404になる。
- VIEWERによる削除Server Actionの直接実行を拒否する。
