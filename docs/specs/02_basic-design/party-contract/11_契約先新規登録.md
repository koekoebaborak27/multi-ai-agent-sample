## 11.1 契約先新規登録画面（PTY-02）

### 11.1.1 入力項目

| 項目   | UI部品     | 必須 | 入力仕様                       |
| ---- | -------- |:--:| -------------------------- |
| 名称   | テキストボックス | 必須 | 1文字以上200文字以内（既存の `createPartySchema` のまま） |
| 分類   | プルダウン    | 任意 | 契約先分類配下のマスタから1件を選択する。未選択可（既存のまま） |
| 連絡先  | テキストボックス | 任意 | 500文字以内（既存のまま）             |

入力項目・検証は既存の `createPartySchema`（`src/modules/party/validation.ts`）をそのまま使う。契約先分類のマスタが0件の場合は、プルダウンの代わりに「未設定（契約先分類マスタが未登録です）」と表示する（既存の `PartyForm` の実装のまま）。この場合も「確認する」は無効化しない（分類は任意項目のため、マスタ機能の必須プルダウンとは事情が異なる）。

### 11.1.2 ボタン

| ボタン   | 動作                                       |
| ----- | ---------------------------------------- |
| 確認する  | 入力内容を検証し、問題があれば画面上にエラーを表示する。問題がなければ契約先確認画面へ新規登録モードで進む。データベースへの登録は行わない |
| キャンセル | 入力内容を破棄し、元の検索条件を復元した契約先検索一覧画面へ戻る          |

## 11.2 契約先確認画面（PTY-03）

契約先確認画面は、新規登録と更新で同じレイアウトを使用する。画面内部に「新規登録」と「更新」の処理モードを持ち、処理モードに応じて表示項目、実行するServer Actionおよび戻り先を切り替える（マスタ機能の確認画面と同じ方式。[`master/11_マスタ新規登録.md` §11.2](../master/11_マスタ新規登録.md#112-マスタ確認画面mst-03)）。

「確認する」ボタンはクライアント側の状態切り替えであり、ページ遷移やServer Actionの呼び出しは行わない。入力値はコンポーネントの状態として保持したまま、確認画面用の表示へ切り替える。

### 11.2.1 表示項目

| 項目       | 新規登録モード  | 更新モード     |
| -------- | -------- | --------- |
| 処理内容     | 新規登録     | 更新        |
| 現在の名称    | 表示しない    | 変更前の名称    |
| 登録・更新後の名称 | 入力した名称   | 変更後の名称    |
| 現在の分類    | 表示しない    | 変更前の分類名（未設定の場合は「未設定」） |
| 登録・更新後の分類 | 選択した分類名（未選択の場合は「未設定」） | 変更後の分類名（未選択の場合は「未設定」） |
| 現在の連絡先   | 表示しない    | 変更前の連絡先（未入力の場合は「-」） |
| 登録・更新後の連絡先 | 入力した連絡先（未入力の場合は「-」） | 変更後の連絡先（未入力の場合は「-」） |

**更新モードでは3項目すべてについて現在値と変更後の値を並べ、変更前と変更後で値が同じ項目には「変更なし」と併記する**（マスタ機能の確認画面と同じ理由。誤操作の唯一の砦となるため）。

### 11.2.2 ボタン

| ボタン     | 新規登録モード                                | 更新モード                                             |
| ------- | -------------------------------------- | --------------------------------------------------- |
| 実行      | 入力内容を再検証し、登録用Server Actionで契約先を登録する     | 入力内容・同時更新の有無を再検証し、更新用Server Actionで契約先を更新する         |
| 入力内容を修正 | 入力値を保持したまま契約先新規登録画面へ戻る                  | 入力値を保持したまま契約先更新画面へ戻る                                |
| キャンセル   | 入力内容を破棄し、元の検索条件を復元した契約先検索一覧画面へ戻る        | 入力内容を破棄し、対象契約先の詳細画面へ戻る                              |

### 11.2.3 新規登録モードの実行処理

1. 入力値をサーバー側で再検証する。
2. 選択された契約先分類マスタが、契約先分類（`CONTRACT_COMPANY_TYPE`）配下に現在も存在することを確認する（未選択の場合は確認不要。既存の `assertCompanyTypeValid` と同じ）。
3. 契約先を登録する。`createdBy` と `updatedBy` に実行した利用者のユーザーIDを設定する。
4. 登録した契約先の詳細画面へ遷移し、登録完了メッセージを表示する。

契約先の登録は名称・分類・連絡先の重複を禁止しない（既存のまま。マスタコードのような一意制約は無い）。

## 11.3 入力項目の検証

- 名称は必須とする。前後の空白は既存の `z.string().min(1)` のトリム挙動に従う。
- 名称は1文字以上200文字以内とする。
- 契約先分類は任意とする。指定された場合は、契約先分類（`CONTRACT_COMPANY_TYPE`）配下に存在することを検証する。存在しない場合は `MASTER_REFERENCE_INVALID` となる。
- 連絡先は任意、500文字以内とする。
- 確認画面を表示しただけではデータベースへ登録されない。

### 11.3.1 テスト方針

- 名称のみを入力して登録できる（分類・連絡先は未入力可）。
- 名称が未入力の場合は拒否する。
- 名称が200文字の場合は登録でき、201文字の場合は拒否する。
- 存在しない契約先分類マスタIDを指定した場合は `MASTER_REFERENCE_INVALID` となる。
- 契約先分類配下ではない（別の分類コード配下の）マスタIDを指定した場合も `MASTER_REFERENCE_INVALID` となる。
- 確認画面を表示しただけではデータベースへ登録されない。
- 登録時に `createdBy`・`updatedBy` に実行者のユーザーIDが設定される。
