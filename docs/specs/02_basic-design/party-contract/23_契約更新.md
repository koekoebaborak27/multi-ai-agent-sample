## 23.1 契約更新画面（CTR-05）

### 23.1.1 表示・入力項目

| 項目   | UI部品     | 編集可否 | 入力仕様                    |
| ---- | -------- |:----:| ----------------------- |
| 契約先  | 読み取り専用の表示（プルダウン・コンボボックスは置かない） | 不可 | 現在の契約先名称を表示するのみ。§21.3.2参照 |
| 契約名  | テキストボックス | 可    | §21.3と同じ。初期値は現在の契約名     |
| 開始日  | 日付入力     | 可    | §21.3と同じ。初期値は現在の開始日     |
| 終了日  | 日付入力     | 可    | §21.3と同じ。初期値は現在の終了日     |
| 状態   | プルダウン    | 可    | §21.3と同じ。初期値は現在の状態      |
| 契約分類 | プルダウン    | 可    | §21.3と同じ。初期値は現在の契約分類（未設定可） |

**契約先は登録時に決めたものから変更できない**（既存の `updateContractSchema` の仕様のまま。§21.2.1）。契約名・開始日・終了日・状態・契約分類の5項目は同時に変更できる。`updatedAt` と `updatedBy` はシステムが設定する。契約名以下4項目の入力欄は §21.1 の新規登録画面と共通のコンポーネント（`contract-form-fields.tsx`）を使う。

### 23.1.2 契約先を変更したい場合

この画面では扱わない。契約先を変更したい場合は、対象の契約を削除し、正しい契約先で新規登録し直す（要件定義の時点でも契約先の変更は対象に含まれていない。現行の `updateContractSchema` の制約を踏襲するだけであり、この設計で新たに制限するものではない）。

### 23.1.3 ボタン

| ボタン   | 動作                                          |
| ----- | ----------------------------------------------- |
| 確認する  | 入力内容を検証し、問題があれば画面上にエラーを表示する。問題がなければ契約確認画面へ更新モードで進む。データベースの更新は行わない |
| キャンセル | 入力内容を破棄し、対象契約の詳細画面へ戻る                        |

## 23.2 更新時の競合

入力画面を表示した時点の `updatedAt` を、実行時に送信する。データベースに保存されている現在の `updatedAt` と一致しない場合は更新せず、§13.2と同じメッセージを表示する。この楽観的排他制御は、契約更新（CTR-05）と削除（§24.2）の双方に同じ方式で適用する。

### 23.2.1 更新モードの実行処理

1. 対象契約が現在も存在することを確認する。存在しない場合は `CONTRACT_NOT_FOUND`。
2. 変更後の契約名・期間・状態・分類IDをサーバー側で再検証する。
3. 入力画面を表示した時点の `updatedAt` と、データベースに保存されている現在の `updatedAt` を比較する。一致しない場合は `CONTRACT_CONCURRENT_UPDATE`。
4. 変更後の契約分類マスタが現在も存在することを確認する（未選択の場合は確認不要）。存在しない場合は `MASTER_REFERENCE_INVALID`。
5. 契約名・期間・状態・分類IDを更新し、`updatedBy` に実行した利用者のユーザーIDを設定する。`createdBy` と契約先（`partyId`）は変更しない。
6. 対象契約の詳細画面へ遷移し、更新完了メッセージを表示する。

変更前と変更後の値が完全に同じ場合も実行を許可し、`updatedAt` と `updatedBy` だけが更新される。

### 23.2.2 テスト方針

- 契約名・期間・状態・契約分類をそれぞれ単独で更新できる。
- 5項目のうち契約先以外を同時に更新できる。
- 契約分類を未設定へ変更できる。
- 更新フォームから契約先を変更しようとしても無視される（サーバー側は既存の契約先IDのまま更新する）。
- 存在しない契約の更新を拒否する（`CONTRACT_NOT_FOUND`）。
- 存在しない契約分類マスタIDへの変更を拒否する（`MASTER_REFERENCE_INVALID`）。
- `updatedAt` が異なる場合に同時更新エラーとなる（`CONTRACT_CONCURRENT_UPDATE`）。
- 更新で `updatedBy` だけが更新され、`createdBy` は変わらない。
- 確認画面を表示しただけではデータベースが更新されない。
- 値を変えずに実行しても拒否されない。
