## 20.1 契約検索一覧画面（CTR-01）

### 20.1.1 検索条件の開閉

`<SearchConditionCard>` を使用し、開閉仕様はマスタ検索一覧・契約先検索一覧と同じとする（§10.1.1）。

### 20.1.2 検索条件

| 項目   | UI部品                | 必須 | 説明                                    |
| ---- | ------------------- | :--: | ------------------------------------- |
| 契約先  | コンボボックス（`party-combobox.tsx`） | 任意 | 登録済みの契約先から1件を選択する。入力して名称で絞り込める。「すべて」を選択した場合は全契約先を対象とする |
| 状態   | プルダウン                | 任意 | `DRAFT`（下書き）/`ACTIVE`（有効）/`TERMINATED`（終了）から1件を選択する。「すべて」を選択した場合は全状態を対象とする |
| 契約分類 | プルダウン                | 任意 | 契約分類（マスタ分類コード `CONTRACT_TYPE`）配下のマスタから1件を選択する。「すべて」を選択した場合は全分類を対象とする |

契約先・状態・契約分類はいずれも契約ごとの任意入力項目、または任意の絞り込み条件であるため、**初期値はすべて「すべて」とする**（§10.1.2の契約先分類と同じ考え方）。

検索条件はURLクエリとして保持する。

```text
/contracts?partyId={契約先IDまたはall}&status={状態値またはall}&categoryId={マスタIDまたはall}&sort={ソート列}&order={ascまたはdesc}&page={ページ番号}
```

### 20.1.3 検索仕様

- 契約先が指定された場合は、指定された契約先の契約だけを対象とする（完全一致。`Contract.partyId`）。
- 状態が指定された場合は、指定された状態の契約だけを対象とする（完全一致）。
- 契約分類が指定された場合は、指定された分類に属する契約だけを対象とする。
- 複数条件を指定した場合はAND条件とする。
- 検索条件を変更して検索した場合、ページ番号を1へ戻す。

### 20.1.4 ボタン

| ボタン    | 動作                                       |
| ------ | ---------------------------------------- |
| 検索     | 入力された検索条件で検索し、ページ番号を1へ戻す                 |
| 条件をクリア | 検索条件、ソート条件およびページ番号を初期状態（すべて「すべて」）へ戻す     |
| 新規登録   | 契約新規登録画面（CTR-02）へ遷移する。ADMINとOPERATORだけに表示する |

### 20.1.5 一覧

| 列    | 表示内容                                   |
| ---- | --------------------------------------- |
| 契約名  | 契約名                                     |
| 契約先  | 契約先名称                                   |
| 開始日  | 開始日。未定の場合は「未定」                          |
| 終了日  | 終了日。未定の場合は「未定」                          |
| 状態   | 状態の表示ラベル（下書き／有効／終了）                     |
| 契約分類 | 契約分類名。未設定・削除済みの場合は「未設定」                 |
| （見出しなし） | 契約詳細画面へ遷移する「詳細」リンク                     |

一覧仕様は以下とする（既存の `ContractTable` の並び替え・ページングを踏襲し、検索絞り込みを追加する）。

- サーバー側で検索、並び替えおよびページングを行う。
- 1ページの表示件数は既存の `env.PAGE_SIZE` を使用する。
- 初期の並び順は契約名の昇順（既存の `ContractSortField` の初期値と同じ）。
- 見出しによる並び替えは既存のとおり `title`・`partyName`・`startDate`・`endDate`・`status` の5列（契約分類は表示専用の解決値のためソート対象外。既存のまま変更しない）。
- 末尾の詳細リンク列はソート対象外とする。
- 一覧の上部に検索結果の総件数と現在のページを表示する。
- 検索結果が0件の場合は「該当する契約がありません」と表示する。
- 一覧は `@/shared/ui/table` のTableコンポーネントを使用する。
- **一覧に削除ボタンは置かない**。既存の `ContractTable` に埋め込まれている削除ボタンはこの変更で撤去する。

### 20.1.6 テスト方針

- 契約先で絞り込める。
- 状態で絞り込める。
- 契約分類で絞り込める。
- 複数条件のAND条件で絞り込める。
- 検索条件を指定しない場合に全件が対象になる。
- 検索結果が `env.PAGE_SIZE` 件でページングされる。
- 契約名・契約先名・開始日・終了日・状態の昇順・降順で並び替えられる。
- 検索条件を変更するとページ番号が1へ戻る。
- 「条件をクリア」ですべて「すべて」・ページ1へ戻る。
- VIEWERでも一覧を参照できるが、「新規登録」ボタンは表示されない。
