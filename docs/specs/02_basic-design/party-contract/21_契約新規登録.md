## 21.1 契約新規登録画面（CTR-02）

### 21.1.1 入力項目

| 項目   | UI部品                | 必須 | 入力仕様                                    |
| ---- | ------------------- | :--: | ---------------------------------------- |
| 契約先  | コンボボックス（`party-combobox.tsx`） | 必須 | 登録済みの契約先から1件を選択する。入力して名称で絞り込める            |
| 契約名  | テキストボックス            | 必須 | 1文字以上200文字以内（既存の `createContractSchema` のまま） |
| 開始日  | 日付入力                | 任意 | 既存のまま                                     |
| 終了日  | 日付入力                | 任意 | 既存のまま                                     |
| 状態   | プルダウン                | 必須 | `DRAFT`（下書き）/`ACTIVE`（有効）/`TERMINATED`（終了）から1件を選択する。初期値は `DRAFT`（既存のまま） |
| 契約分類 | プルダウン                | 任意 | 契約分類配下のマスタから1件を選択する。未選択可（既存のまま）           |

契約先の選択欄は、現行の「一覧の先頭 `env.PAGE_SIZE` 件だけを表示するプルダウン」から、**入力して契約先名称を絞り込めるコンボボックス**（`Command`）へ置き換える。登録済みの契約先が多くても目的の契約先を選べるようにするための変更である（§00.7）。

登録済みの契約先が0件の場合は、コンボボックスの代わりに「契約先が登録されていません。先に契約先を登録してください。」と表示し、契約先新規登録画面（PTY-02）へのリンクを置く。この状態では「確認する」ボタンを無効化する（契約先は必須のため、マスタ新規登録画面がマスタ分類0件のときに取る挙動と同じ）。

### 21.1.2 ボタン

| ボタン   | 動作                                    |
| ----- | ------------------------------------- |
| 確認する  | 入力内容を検証し、問題があれば画面上にエラーを表示する。問題がなければ契約確認画面へ新規登録モードで進む。データベースへの登録は行わない |
| キャンセル | 入力内容を破棄し、元の検索条件を復元した契約検索一覧画面へ戻る       |

「確認する」時点で、選択された契約先が現在も存在するか確認する。

## 21.2 契約確認画面（CTR-03）

契約確認画面は、新規登録と更新で同じレイアウトを使用する。画面内部に「新規登録」と「更新」の処理モードを持ち、処理モードに応じて表示項目、実行するServer Actionおよび戻り先を切り替える（§11.2と同じ方式）。

### 21.2.1 表示項目

| 項目         | 新規登録モード    | 更新モード      |
| ---------- | ---------- | ---------- |
| 処理内容       | 新規登録       | 更新         |
| 契約先        | 選択した契約先名称（新規登録・更新のどちらも表示するが、更新モードでは変更不可のため現在値のみ） | 現在の契約先名称（変更不可） |
| 現在の契約名     | 表示しない      | 変更前の契約名    |
| 登録・更新後の契約名 | 入力した契約名    | 変更後の契約名    |
| 現在の開始日・終了日 | 表示しない      | 変更前の開始日・終了日（未定の場合は「未定」） |
| 登録・更新後の開始日・終了日 | 入力した開始日・終了日（未定の場合は「未定」） | 変更後の開始日・終了日（未定の場合は「未定」） |
| 現在の状態      | 表示しない      | 変更前の状態の表示ラベル |
| 登録・更新後の状態  | 選択した状態の表示ラベル | 変更後の状態の表示ラベル |
| 現在の契約分類    | 表示しない      | 変更前の契約分類名（未設定の場合は「未設定」） |
| 登録・更新後の契約分類 | 選択した契約分類名（未設定の場合は「未設定」） | 変更後の契約分類名（未設定の場合は「未設定」） |

契約先は新規登録時に決めたら以後変更できない（既存の `updateContractSchema` が契約先を受け取らない仕様のまま。§23.1）。更新モードの確認画面でも契約先は変更前後の対比を行わず、現在の契約先名称のみを表示する。

**更新モードでは契約名・期間・状態・契約分類について現在値と変更後の値を並べ、変更前と変更後で値が同じ項目には「変更なし」と併記する**（§11.2.1と同じ理由）。

### 21.2.2 ボタン

| ボタン     | 新規登録モード                            | 更新モード                                        |
| ------- | ----------------------------------- | -------------------------------------------- |
| 実行      | 入力内容を再検証し、登録用Server Actionで契約を登録する | 入力内容・同時更新の有無を再検証し、更新用Server Actionで契約を更新する    |
| 入力内容を修正 | 入力値を保持したまま契約新規登録画面へ戻る               | 入力値を保持したまま契約更新画面へ戻る                          |
| キャンセル   | 入力内容を破棄し、元の検索条件を復元した契約検索一覧画面へ戻る     | 入力内容を破棄し、対象契約の詳細画面へ戻る                        |

### 21.2.3 新規登録モードの実行処理

1. 入力値をサーバー側で再検証する。
2. 選択された契約先が現在も存在することを確認する。存在しない場合は `PARTY_NOT_FOUND`。
3. 選択された契約分類マスタが、契約分類（`CONTRACT_TYPE`）配下に現在も存在することを確認する（未選択の場合は確認不要。既存の `assertCategoryValid` と同じ）。
4. 契約を登録する。`createdBy` と `updatedBy` に実行した利用者のユーザーIDを設定する。
5. 登録した契約の詳細画面へ遷移し、登録完了メッセージを表示する。

## 21.3 入力項目の検証

- 契約先は必須とする。指定された契約先IDが存在することを検証する。
- 契約名は必須、1文字以上200文字以内とする（既存のまま）。
- 開始日・終了日は任意とする（既存のまま。開始日と終了日の前後関係チェックは既存で行っていないため、この設計でも追加しない）。
- 状態は `DRAFT`/`ACTIVE`/`TERMINATED` のいずれかで必須とする（既存のまま）。
- 契約分類は任意とする。指定された場合は、契約分類（`CONTRACT_TYPE`）配下に存在することを検証する。存在しない場合は `MASTER_REFERENCE_INVALID` となる。
- 確認画面を表示しただけではデータベースへ登録されない。

### 21.3.1 テスト方針

- 契約先・契約名・状態のみを入力して登録できる（開始日・終了日・契約分類は未入力可）。
- 契約先が未選択の場合は拒否する。
- 契約名が未入力の場合は拒否する。
- 存在しない契約先IDを指定した場合は `PARTY_NOT_FOUND` となる。
- 存在しない契約分類マスタIDを指定した場合は `MASTER_REFERENCE_INVALID` となる。
- 確認画面を表示しただけではデータベースへ登録されない。
- 登録時に `createdBy`・`updatedBy` に実行者のユーザーIDが設定される。
