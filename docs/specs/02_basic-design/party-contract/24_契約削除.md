## 24.1 契約削除確認ダイアログ

契約詳細画面（CTR-04）の「削除」ボタンを押したときに表示する確認ダイアログ。独立した画面ルートは作成せず、詳細画面の上に重ねて表示する。

### 24.1.1 表示項目

| 項目  | 表示内容             |
| --- | ---------------- |
| 見出し | 「契約を削除しますか？」     |
| 契約名 | 削除対象の契約名         |
| 契約先 | 削除対象の契約先名称       |
| 警告  | 「削除した契約は元に戻せません。」 |
| ボタン | 「キャンセル」および「削除する」 |

ダイアログの仕様（`AlertDialog` の使用、二重送信防止、フォーカス制御）は §14.2.2 と同一とする。

### 24.1.2 削除の実行処理

1. Server Actionで書き込み権限を検証する。
2. 対象契約が現在も存在することを確認する。
3. 詳細画面を表示した時点の `updatedAt` と、データベースに保存されている現在の `updatedAt` を比較する。
4. 一致する場合、対象契約を物理削除する。
5. 元の検索条件を復元した契約検索一覧画面へ遷移し、削除完了メッセージを表示する。

検証の順序は権限 → 存在 → 同時更新の順とする。

### 24.1.3 削除完了メッセージ

```text
/contracts?partyId={契約先IDまたはall}&status={状態値またはall}&categoryId={マスタIDまたはall}&sort={ソート列}&order={ascまたはdesc}&page={ページ番号}&deleted=1
```

方式は§14.2.4と同じ。

## 24.2 削除時の競合

削除にも更新と同じ楽観的排他制御を適用する（§23.2）。検証の順序は次のとおりとする。

| 順序 | 検証内容               | 一致しない場合                  |
| -- | ------------------ | -------------------------- |
| 1  | 書き込み権限があるか         | `FORBIDDEN`                 |
| 2  | 対象が存在するか           | `CONTRACT_NOT_FOUND`        |
| 3  | `updatedAt` が一致するか | `CONTRACT_CONCURRENT_UPDATE` |

確認ダイアログを表示した後に別の利用者が同じ対象を削除していた場合、対象は既に存在しないため `CONTRACT_NOT_FOUND` となる。

### 24.2.1 テスト方針

- 存在する契約を削除できる。
- 削除した契約が一覧の検索結果に含まれない。
- 削除した契約の詳細取得が404になる。
- 存在しない契約の削除を拒否する（`CONTRACT_NOT_FOUND`）。
- `updatedAt` が異なる場合に同時更新エラーとなる（`CONTRACT_CONCURRENT_UPDATE`）。
- 権限、存在、同時更新の順に検証される。
- VIEWERによる削除Server Actionの直接実行を拒否する。
