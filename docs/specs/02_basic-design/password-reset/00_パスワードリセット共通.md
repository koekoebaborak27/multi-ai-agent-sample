## 00.1 概要

本機能は、**パスワードを忘れた利用者が、自分のメールアドレスを使って自分でパスワードを設定し直せるようにする**もの。あわせて、その前提となるメールアドレスの登録・変更と、メールを送る仕組みを用意する。

提供するものは次の4つ。

1. ログイン画面からの再発行の申請（メールアドレスのみを入力）
2. メールで届いた一度きりのURLからのパスワード再設定
3. メールアドレスの登録・変更（管理者による変更と、本人による変更＋確認）
4. メールを送る共通の仕組み（SMTP。テンプレートでは Gmail を使う）

**新しいパスワードをメールで送る方式は採用しない。** 理由は要件定義書 §01.1 を参照。

## 00.2 用語

> **再設定用URL**とは、パスワードを設定し直す画面を開くための、一度だけ使える専用のURLのこと。30分で期限切れになり、一度使うと開けなくなる。

> **確認用URL**とは、本人がメールアドレスを変更するときに、新しいアドレスへ送られるURLのこと。これを開いて初めて登録内容が変わる。有効期限と使い切りの扱いは再設定用URLと同じ。

> **合言葉**（トークン）とは、URLの末尾に付ける長い文字列のこと。これを知っている人だけが画面を開ける。データベースには元の文字列を保存せず、計算し直せない形（要約値）で保存する。

> **ロック**とは、ログインに続けて失敗した利用者が、それ以上ログインを試せなくなった状態のこと。失敗できる回数は `MAX_ATTEMPTS`（初期値20回）で決まる。

## 00.3 権限

| 画面・操作 | 必要な権限 |
|---|---|
| 再発行の申請（PWR-01） | **ログイン不要**（誰でも開ける） |
| パスワードの再設定（PWR-02） | **ログイン不要**（URLの合言葉が正しいこと） |
| 自分のメールアドレスの変更（EML-01・EML-02） | ログイン済みであること（役割は問わない） |
| 他人のメールアドレスの変更（利用者管理画面） | ADMIN のみ（既存の利用者管理と同じ） |

ログイン不要の画面は `src/proxy.ts` の認証ガードで**素通りさせる対象**に加える。対象は `/forgot-password` と `/reset-password/*`。

## 00.4 画面一覧

| ID | 画面 | ルート | ログイン |
|---|---|---|---|
| PWR-01 | パスワード再発行の申請 | `/forgot-password` | 不要 |
| PWR-02 | パスワードの再設定 | `/reset-password/[token]` | 不要 |
| EML-01 | 自分のメールアドレスの変更 | `/settings/email` | 必要 |
| EML-02 | メールアドレス変更の確認結果 | `/settings/email/confirm/[token]` | 必要 |

既存画面への追加は次の2つ。

| 既存画面 | 追加するもの |
|---|---|
| ログイン（`/login`） | 「パスワードを忘れた場合はこちら」のリンク |
| 利用者の登録・更新（`/admin/users`） | メールアドレスの入力欄（登録は必須・更新でも変更可） |

## 00.5 画面遷移

```
ログイン(/login)
  └「パスワードを忘れた場合はこちら」
      → PWR-01 申請(/forgot-password)
          └ 送信 → 同じ画面に受付完了を表示（メール送信は裏で行う）
                    ↓（メールのURL）
                  PWR-02 再設定(/reset-password/[token])
                    ├ 成功 → ログイン(/login) へ「変更しました」を伝えて戻す
                    └ 期限切れ・使用済み・不正 → 案内を出し PWR-01 へのリンクを見せる

設定(/settings/password の隣)
  └ EML-01 メール変更(/settings/email)
      └ 申し込み → 新しいアドレスへ確認用URLを送る
                    ↓
                  EML-02 確認(/settings/email/confirm/[token])
                    ├ 成功 → 登録を書き換え、変更前のアドレスへ知らせるメールを送る
                    └ 期限切れ・使用済み・不正 → 案内を出し EML-01 へのリンクを見せる
```

## 00.6 エラー設計

規約どおり、業務コードでは `throw new AppError(...)` するだけとし、ログは境界（`withOp` / `withRoute`）が一度だけ出す（`src/AGENTS.md`）。

| コード | HTTP | 画面に出す文言 | 使う場面 |
|---|---|---|---|
| `RESET_TOKEN_INVALID` | 400 | このURLは使用済みか、有効期限が切れています | 合言葉が見つからない・期限切れ・使用済み |
| `EMAIL_ALREADY_USED` | 409 | このメールアドレスは既に使われています | 重複するアドレスを登録・変更しようとした |
| `MAIL_SEND_FAILED` | 500 | メールの送信に失敗しました | メール送信サーバへの送信が失敗した（申請画面では画面に出さない。§10.4 参照） |

**申請（PWR-01）では、失敗を画面に出さない。** 登録済みのアドレスかどうかを外部に知られないようにするため、次のいずれの場合も**同じ受付完了の画面**を出す。

- そのアドレスの利用者が存在しない
- 24時間の送信回数の上限を超えている
- 利用者が削除済みである

いずれの場合もログには理由を残す（`reason` を付ける）。

## 00.7 モジュール構成

| 置き場所 | 役割 |
|---|---|
| `src/shared/mail/` | メールを送る共通の仕組み。`MAIL_TRANSPORT` で「画面（コンソール）へ出すだけ」と「Resend で実際に送る」を切り替える（→ [`02_メール送信.md`](02_メール送信.md)） |
| `src/modules/password-reset/` | 再発行の申請とパスワードの再設定（ログインしていない利用者が使う） |
| `src/modules/user/` | メールアドレスの登録・変更。管理者による変更（既存画面の拡張）と、本人による変更＋確認（→ [`20_メールアドレス管理.md`](20_メールアドレス管理.md)） |

`src/modules/password-reset/` の中身は標準ファイル構成（`ui/` / `actions.ts` / `service.ts` / `repository.ts` / `validation.ts` / `types.ts` / `index.ts`）に従う。合言葉の作成と要約値の計算は `service.ts` から使う小さな関数として `token.ts` に分ける。

**依存の向き。** `modules/password-reset` と `modules/user` は `shared/mail` を使う。モジュール同士は互いの内部を参照しない。

## 00.8 テスト方針

`TESTING.md` に従い、自動テストは次を対象にする。

| 対象 | 観点 |
|---|---|
| `token.ts` | 作った合言葉が毎回変わること、要約値が同じ入力で同じになること |
| `service.ts`（再発行） | 未登録アドレスでも同じ結果を返すこと、上限を超えたら送らないこと、発行時に古い未使用のURLを無効にすること |
| `service.ts`（再設定） | 期限切れ・使用済みで失敗すること、成功時に失敗回数とロックが解除されること |
| `validation.ts` | パスワードの条件（8文字以上・英字と数字）、メールアドレスの形式 |

画面操作テスト（Playwright）は製造後に別途、単体テスト仕様書を作って実施する。

## 00.9 対象外

- Microsoft アカウント（Entra ID）だけでログインする利用者への配慮（特別扱いをしない）
- 管理者がロックだけを解除する専用画面
- すでに登録されている利用者のメールアドレスを一括で埋める仕組み
- 再発行の履歴を画面で見る機能（記録はログにのみ残す）
