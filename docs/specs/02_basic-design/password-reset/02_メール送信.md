## 02.1 方針

- 送信の窓口は `src/shared/mail/` に1つだけ置き、機能側は「誰に・どの種類のメールを送るか」だけを指定する
- **開発中は実際に送らない。** `MAIL_TRANSPORT=console` のとき、宛先・件名・本文をログへ出すだけにする。ローカルでは既定でこちらを使う
- 実際に送るときは `MAIL_TRANSPORT=smtp`。**メール送信の共通規格である SMTP だけに対応し、特定の会社の独自の呼び出し方には対応しない。** こうすると、接続先の設定値を差し替えるだけで Gmail・Amazon SES・Resend のどれにでも繋がり、乗り換えのたびにコードを書き直さずに済む
- 送信は**文字だけの本文**（プレーンテキスト）とする。装飾したメールは作らない
- 送信には `nodemailer` を使う（Node.js から SMTP でメールを送るための定番の部品）

## 02.2 設定（環境変数）

`src/shared/config/env.ts` へ次を追加する。

| 名前 | 必須 | 初期値 | 説明 |
|---|---|---|---|
| `APP_BASE_URL` | いいえ | `http://localhost:3000` | メールに載せるURLの先頭部分。本番は Cloud Run のURL |
| `MAIL_TRANSPORT` | いいえ | `console` | `console`（ログへ出すだけ）または `smtp`（実際に送る） |
| `MAIL_FROM` | いいえ | なし | 送信元アドレス。Gmail を使う場合は `SMTP_USER` と同じ値にする |
| `MAIL_FROM_NAME` | いいえ | `契約管理システム` | 差出人の表示名 |
| `SMTP_HOST` | いいえ | なし | `MAIL_TRANSPORT=smtp` のときは必須。Gmail なら `smtp.gmail.com` |
| `SMTP_PORT` | いいえ | `587` | 接続してから暗号化に切り替える方式（STARTTLS）の 587 番を使う |
| `SMTP_USER` | いいえ | なし | `MAIL_TRANSPORT=smtp` のときは必須。Gmail なら送信に使う Gmail アドレス |
| `SMTP_PASSWORD` | いいえ | なし | `MAIL_TRANSPORT=smtp` のときは必須。Gmail ならアプリパスワード16文字。本番は Secret Manager の `smtp-password` から渡す |

**`MAIL_TRANSPORT=smtp` なのに `SMTP_HOST` / `SMTP_USER` / `SMTP_PASSWORD` のいずれかが無い場合は、起動時に設定の誤りとして知らせる**（実際に送る場面まで気付けないことを避ける）。

`MAIL_FROM` に `SMTP_USER` と違うアドレスを指定しても、Gmail は送信時に接続に使ったアカウントのアドレスへ自動的に書き換える。Gmail を使う間は両者を同じにしておく。

## 02.3 置き場所と使い方

```
src/shared/mail/
  index.ts      … 公開する窓口（sendMail）
  transport.ts  … console / smtp の切り替えと実際の送信
  templates.ts  … 送るメールの種類ごとの件名・本文の組み立て
```

- `sendMail({ to, template })` の形で呼ぶ。件名と本文は `templates.ts` が組み立てる。呼ぶ側は文面を持たない
- worker からは使わないため、`server-only` を付ける
- 送信の成否はログへ残す（`shared/observability` の仕組みに乗せる）。**本文とURLはログに出さない**（合言葉が残るため）

## 02.4 送るメールの文面

いずれも日本語・文字だけ。`{}` の部分は差し込み。

### 02.4.1 パスワード再設定のご案内

件名: **パスワード再設定のご案内**

```
{表示名またはユーザーID} 様

パスワードの再設定を受け付けました。
下記のURLを開き、新しいパスワードを設定してください。

{APP_BASE_URL}/reset-password/{合言葉}

このURLは30分で使えなくなります。また、一度使うと開けなくなります。
心当たりがない場合は、このメールを破棄してください。パスワードは変更されません。
```

### 02.4.2 パスワード変更のお知らせ

件名: **パスワードを変更しました**

```
{表示名またはユーザーID} 様

パスワードが変更されました。

心当たりがない場合は、システムの管理者へご連絡ください。
```

### 02.4.3 メールアドレス変更の確認

変更先のアドレスへ送る（→ [`20_メールアドレス管理.md`](20_メールアドレス管理.md)）。

件名: **メールアドレス変更の確認**

```
{表示名またはユーザーID} 様

メールアドレスの変更を受け付けました。
下記のURLを開くと、変更が完了します。

{APP_BASE_URL}/settings/email/confirm/{合言葉}

このURLは30分で使えなくなります。
心当たりがない場合は、このメールを破棄してください。変更は行われません。
```

### 02.4.4 メールアドレス変更のお知らせ

変更**前**のアドレスへ送る。

件名: **メールアドレスを変更しました**

```
{表示名またはユーザーID} 様

登録されているメールアドレスが変更されました。

心当たりがない場合は、システムの管理者へご連絡ください。
```

## 02.5 送信に失敗したときの扱い

| 場面 | 扱い |
|---|---|
| 再発行の申請（PWR-01） | **画面では成功と同じ表示にする。** 失敗はログにだけ残す。宛先が登録済みかどうかを知られないため |
| パスワード変更のお知らせ | 送信に失敗しても**パスワードの変更は取り消さない**。ログにだけ残す |
| メールアドレス変更の確認 | **画面にエラーを出す**（利用者自身が入力したアドレスなので、届かないことを伝えてよい） |

送信の再試行は行わない。失敗したら利用者にもう一度申し込んでもらう。

## 02.6 送信サービスの選び方と制約

### 02.6.1 このテンプレートでの既定は Gmail SMTP

**このテンプレートの動作確認は Gmail SMTP で行う**（2026-08-21 決定）。設定手順は [`docs/specs/99_infra/` §09.1](../../99_infra/infra_design_09_メール送信.md#091-手順8-メール送信を設定する)。

Resend や Amazon SES といったメール配信の専門サービスは、**送信元として自分が管理するドメインを登録しないと、他人宛にメールを送れない**（Resend の場合、ドメイン未登録の間は自分のアドレス宛にしか送れない）。ドメインの取得には年間の費用がかかる。

一方 Gmail SMTP は、**ドメインを持たなくても、無料で、誰宛にでも送れる**。パスワード再発行は「届かなければ機能が成立しない」ため、テンプレートの動作確認にはこちらを使う。

### 02.6.2 Gmail SMTP の制約

- **1日あたりの送信数の上限は約500通**（無料の Gmail アカウントの場合）。テンプレートの動作確認には十分だが、利用者数の多い案件では足りない
- **送信元は接続に使った Gmail アドレスになる。** 独自ドメインのアドレス（`info@会社名.co.jp` など）を差出人にはできない
- 送信専用の Google アカウントを作り、そのアカウントで発行した**アプリパスワード**を使う。個人の主要アカウントは使わない（鍵が漏れたときの影響を、このシステムの範囲に閉じ込めるため）
- Google の利用規約はこの使い方を明確には想定していない。**業務として本格的に運用する段階では、次の乗り換えを行う**

### 02.6.3 本格運用時の乗り換え

案件へ本格的に流用する際は、**Resend または Amazon SES へ乗り換える**。いずれも SMTP に対応しているため、**コードの変更は不要で、`SMTP_HOST` / `SMTP_USER` / `SMTP_PASSWORD` を差し替えるだけで移行できる**（これが §02.1 で SMTP だけに対応すると決めた理由）。

乗り換えに必要な作業は次のとおり。

1. 案件で使うドメインを用意する（既にドメインを持っているなら、その一部を切り出して使えるので追加費用はかからない）
2. DNS に、そのドメインからの送信を正当なものと証明する記録（SPF / DKIM）を登録する
3. 送信サービス側でドメインの認証を通す
4. `SMTP_*` と `MAIL_FROM` を差し替える
