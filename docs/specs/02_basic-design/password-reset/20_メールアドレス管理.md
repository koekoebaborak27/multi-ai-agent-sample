# メールアドレスの管理（EML-01・EML-02）

再発行の前提となるメールアドレスの登録・変更。管理者による変更と、本人による変更＋確認。

## 20.1 管理者による登録と変更

既存の利用者管理画面（`/admin/users`）を広げる。ADMIN のみが使える点は変わらない。

| 画面 | 変更内容 |
|---|---|
| 新規登録 | メールアドレスを**必須**にする（`createUserSchema` の `email` を必須へ変更） |
| 更新 | メールアドレスの入力欄を追加する（`updateUserSchema` に `email` を追加。現在は表示名と役割しか変更できない） |
| 一覧 | メールアドレスの列を表示する（未登録の利用者を見つけられるようにする） |

- 管理者が変更する場合は、**確認用URLを使わない**。その場で書き換える
- 保存前に小文字へ揃える
- すでに登録されている利用者でメールアドレスが空のものは、そのまま残してよい。更新画面から順に埋める

## 20.2 本人による変更（EML-01）

ルートは `/settings/email`。ログインしていれば役割を問わず使える。既存のパスワード変更画面（`/settings/password`）の隣に置き、同じ見た目に揃える。

| 項目 | 内容 |
|---|---|
| 表示 | 現在のメールアドレス（未登録なら「未登録」）、新しいメールアドレスの入力欄、「確認メールを送る」ボタン |
| 入力チェック | 必須・メールの形式・254文字以内・**現在のアドレスと同じでないこと** |

処理（Server Action `requestEmailChange`）の流れ。

1. 入力チェックを行う
2. 小文字へ揃える
3. **他の利用者が既に使っていないか**を確かめる。使われていれば `EMAIL_ALREADY_USED` を返す（→ [20.4](#204-重複したときの扱い)）
4. その利用者の未使用の申し込みをすべて無効にする
5. 合言葉を作り、変更先のアドレス・要約値・有効期限（現在時刻＋30分）を `EmailChangeToken` へ記録する
6. **変更先のアドレス宛**に「メールアドレス変更の確認」メールを送る（→ [`02_メール送信.md`](02_メール送信.md#0243-メールアドレス変更の確認)）
7. 「入力されたアドレスに確認用のURLをお送りしました。URLを開くと変更が完了します。」と表示する

**この時点では `User.email` を変えない。**

送信に失敗した場合は、画面にエラーを出す（自分で入力したアドレスなので、届かないことを伝えてよい）。

## 20.3 確認用URLを開いたとき（EML-02）

ルートは `/settings/email/confirm/[token]`。**ログインしている必要がある。**

> **なぜログインを求めるのか。** 変更先のアドレスにURLが届いた時点で本人確認はできているが、ログインを求めておくと、メールを盗み見た第三者が勝手に確定させることを防げる。

処理の流れ。**次の変更は1つのまとまりとして行う。**

1. 合言葉の要約値に一致する記録があり、未使用で、期限内であることを確かめる
2. その記録の利用者が、**いまログインしている利用者と同じ**であることを確かめる。違えば開けない扱いにする
3. 変更先のアドレスが**他の利用者に使われていないか**をもう一度確かめる（申し込みから確認までの間に登録された場合に備える）
4. `User.email` を変更先のアドレスへ書き換える
5. その記録の `usedAt` に現在時刻を入れ、同じ利用者の他の未使用の申し込みも無効にする

まとまりの外で、**変更前のアドレス宛**に「メールアドレスを変更しました」を送る（→ [`02_メール送信.md`](02_メール送信.md#0244-メールアドレス変更のお知らせ)）。変更前が未登録だった場合は送らない。

| 結果 | 表示 |
|---|---|
| 成功 | 「メールアドレスを変更しました。」と新しいアドレス。`/settings/email` へのリンク |
| 開けない | 「このURLは使用済みか、有効期限が切れています。」と `/settings/email` へのリンク |

## 20.4 重複したときの扱い

メールアドレスは1人に1つ。重複したときの文言はすべて次に揃える。

> このメールアドレスは既に使われています

| 場面 | どこで気付くか |
|---|---|
| 管理者が登録・変更する | 保存の直前に確認する。データベース側の一意制約でも二重に防ぐ |
| 本人が申し込む | 申し込みの時点と、確認用URLを開いた時点の**2回**確認する |

データベースの一意制約に引っかかった場合も、同じ文言で返す（`EMAIL_ALREADY_USED`）。
