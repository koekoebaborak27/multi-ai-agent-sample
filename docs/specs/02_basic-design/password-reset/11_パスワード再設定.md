## 11.1 画面

ルートは `/reset-password/[token]`。ログインしていなくても開ける。

**合言葉はURLの途中（パス）に置き、`?token=` の形にはしない。** 検索の条件として記録に残りにくくするため。

| 状態 | 表示 |
|---|---|
| 通常 | 見出し「新しいパスワードの設定」、「新しいパスワード」欄、「新しいパスワード（確認）」欄、「設定する」ボタン |
| 開けない | 見出し「このURLは使えません」、理由の説明、「再発行を申し込む」リンク（`/forgot-password`） |

**どの利用者のURLかを画面に出さない**（メールアドレスもユーザーIDも表示しない）。URLを手に入れた人に、誰のものかを知らせないため。

## 11.2 入力チェック

`validation.ts` の `resetPasswordSchema`。条件は既存のパスワード変更画面（`passwordChangeSchema`）と揃える。

| 項目 | 条件 | エラー文言 |
|---|---|---|
| 新しいパスワード | 8文字以上128文字以内 | 新しいパスワードは8文字以上にしてください |
| 新しいパスワード | 英字を含む | 英字を含めてください |
| 新しいパスワード | 数字を含む | 数字を含めてください |
| 確認用パスワード | 新しいパスワードと一致 | 新しいパスワードが一致しません |

**「今のパスワードと違うこと」は求めない。** 今のパスワードを覚えていない利用者が使う画面のため、比べる意味がない。

## 11.3 URLを開いたときの確認

画面を表示する時点で、次をすべて確かめる。1つでも欠ければ「開けない」表示にする。

1. 受け取った合言葉の要約値に一致する記録がある
2. まだ使われていない（`usedAt` が空）
3. 有効期限を過ぎていない（`expiresAt` が現在時刻より後）
4. 対象の利用者が存在し、削除済みでない

**確定するときにも同じ確認をやり直す。** 画面を開いたまま放置して期限が切れた場合に備えるため。

## 11.4 確定したときの処理

Server Action（`resetPassword`）で行う。`withOp` で包む。**次の変更は1つのまとまり（トランザクション）として行い、途中で失敗したらすべて元に戻す。**

1. [11.3](#113-urlを開いたときの確認) の確認をやり直す。だめなら `RESET_TOKEN_INVALID` を投げる
2. 新しいパスワードを Argon2id で変換して `User.passwordHash` へ保存する
3. `User.mustChangePassword` を解除する（次回ログイン時の変更強制を外す）
4. `User.failedAttempts` を 0 に戻す
5. `User.lockedAt` を空にする（**ロックされていた場合はこれで解除される**）
6. 使った `PasswordResetToken.usedAt` に現在時刻を入れる
7. その利用者の**他の未使用のURLもすべて無効**にする

まとまりの外で「パスワード変更のお知らせ」メールを送る（→ [`02_メール送信.md`](02_メール送信.md#0242-パスワード変更のお知らせ)）。**送信に失敗しても、パスワードの変更は取り消さない。**

処理が終わったら**ログイン画面へ移動**し、「パスワードを変更しました。新しいパスワードでログインしてください。」と表示する。**自動ではログインさせない。**

## 11.5 開けなかったときの表示

理由ごとに文言を変えない。いずれも次のように表示する。

> このURLは使用済みか、有効期限が切れています。お手数ですが、もう一度お申し込みください。

- 下に「再発行を申し込む」リンク（`/forgot-password`）を置く
- 合言葉が正しいかどうかで応答にかかる時間が大きく変わらないようにする
