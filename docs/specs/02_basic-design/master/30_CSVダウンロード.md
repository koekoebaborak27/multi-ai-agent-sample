## 30.1 CSVダウンロード

### 30.1.1 概要

マスタ検索一覧画面（MST-01）とマスタ分類一覧画面（MST-06）から、一覧の内容をCSVファイルとしてダウンロードできる。**出力専用の機能であり、CSVを取り込む手段は設けない**（一括登録・一括更新は §00.9.2 のとおり対象外）。

新しい画面は追加しない。既存の2画面へボタンが1つずつ増えるだけである。

**CSVの生成はappのリクエストの中で行う（同期方式）。** 検索・CSV組み立て・応答を1回のリクエストで完結させ、ジョブの登録・状態の問い合わせ・生成物の保管は行わない。採用した理由は §30.1.9 に記す。

利用者から見た動きは「ボタンを押すと、すぐダウンロードが始まる」だけである。ジョブの一覧やダウンロード履歴の画面は設けない。

### 30.1.2 ダウンロードの対象

| 起点画面   | 対象                    | 並び順        |
| ------ | --------------------- | ---------- |
| MST-01 | 現在の検索条件に一致するマスタ**全件** | §10.1.6 と同じ |
| MST-06 | マスタ分類の**全件**          | §20.1.1 と同じ |

- 検索条件（`categoryId` / `keyword`）は画面の指定をそのまま適用する。検索仕様は §10.1.4 と同一とする。
- **ページ番号は無視する。** 画面が2ページ目を表示していても、出力されるのは条件に一致する全件である。
- 画面と同じ並び順にすることで、一覧で見えているものとCSVの内容が対応する。

### 30.1.3 導線とボタン

- 配置は一覧領域の右上とし、MST-01 では「マスタ分類の管理」ボタンの隣、MST-06 では「新規登録」ボタンの隣に置く。
- ラベルは「CSVダウンロード」、`variant="outline"` の通常のリンク（`<a href>`）とする。全ロールに表示する（§00.3）。
- 次の場合はボタンを無効化する。
  - 対象が0件のとき。無効化に併せて理由を示す。
  - 対象件数が上限を超えるとき（§30.1.6）。
- 検索条件はクエリパラメータとして、リンク先のURL（§30.1.5）へ画面側（サーバーコンポーネント）で組み立てて渡す。クリックすると、ブラウザーの通常のダウンロード動作でファイルが保存される。専用の待機表示は持たない。

### 30.1.4 出力仕様

#### 30.1.4.1 ファイル形式

| 項目    | 仕様                                                    |
| ----- | ----------------------------------------------------- |
| 文字コード | UTF-8。先頭にBOM（U+FEFF）を付与する                             |
| 区切り文字 | カンマ                                                   |
| 改行コード | CRLF                                                  |
| 引用    | 値にカンマ・引用符・改行のいずれかを含む場合だけ `"` で囲む。値中の `"` は `""` へ置き換える |
| 先頭行   | ヘッダー行（日本語の列名）                                         |
| 生成    | 既存の依存である `papaparse` の `unparse` を使用する                |

BOMを付けるのは、付けない場合にMicrosoft ExcelがUTF-8と判定できず日本語が文字化けするためである。**`iconv-lite` は使用しない。** Shift_JISへ変換する方式では、変換できない文字（一部の漢字・絵文字）の扱いを別途決める必要があり、マスタ内容に任意の文字を許可している本設計（§11.5 は文字種を制限しない）と相性が悪い。

#### 30.1.4.2 ファイル名

| 起点画面   | ファイル名                                  |
| ------ | -------------------------------------- |
| MST-01 | `master_YYYYMMDDHHmmss.csv`            |
| MST-06 | `master_categories_YYYYMMDDHHmmss.csv` |

- 日時はCSVを生成した時刻（Asia/Tokyo）とする。
- ファイル名はASCII文字だけで構成する。日本語を含めると `Content-Disposition` でのエンコードが必要になり、ブラウザーごとの差異を抱えるためである。
- `Content-Type` は `text/csv; charset=utf-8`、`Content-Disposition` は `attachment; filename="<上記>"` とする。

#### 30.1.4.3 マスタの出力列

| 順 | 列名       | 値                              |
| - | -------- | ------------------------------ |
| 1 | マスタ分類コード | `MasterCategory.id` を4桁ゼロ埋めした値 |
| 2 | マスタ分類名   | `MasterCategory.name`          |
| 3 | マスタID    | `Master.id`                    |
| 4 | マスタコード   | `Master.code`                  |
| 5 | マスタ内容    | `Master.content`               |
| 6 | 登録日時     | `Master.createdAt`             |
| 7 | 登録者      | `Master.createdBy`。値が無い場合は空欄    |
| 8 | 最終更新日時   | `Master.updatedAt`             |
| 9 | 最終更新者    | `Master.updatedBy`。値が無い場合は空欄    |

マスタ詳細画面（MST-04）の表示項目7つに、マスタ分類コードと内部IDを加えた9列とする。

**内部ID（`Master.id`）を出力する。** §01.1.2 では内部識別子と位置づけているが、CSVを他システムやスプレッドシートへ取り込む際に行を一意に識別できる必要があり、参照側がマスタIDを保持するという規約（§01.1.4）とも整合する。マスタコードは変更され得る値であるため（§13.1）、突合のキーには使えない。

#### 30.1.4.4 マスタ分類の出力列

| 順 | 列名       | 値                                    |
| - | -------- | ------------------------------------ |
| 1 | マスタ分類コード | `MasterCategory.id` を4桁ゼロ埋めした値       |
| 2 | マスタ分類名   | `MasterCategory.name`                |
| 3 | 登録マスタ件数  | その分類に属するマスタの件数                       |
| 4 | 登録日時     | `MasterCategory.createdAt`           |
| 5 | 登録者      | `MasterCategory.createdBy`。値が無い場合は空欄 |
| 6 | 最終更新日時   | `MasterCategory.updatedAt`           |
| 7 | 最終更新者    | `MasterCategory.updatedBy`。値が無い場合は空欄 |

マスタ分類詳細画面（MST-07）の表示項目と同じ7列とする。マスタ分類コードが `MasterCategory.id` そのものであるため、内部IDの列は設けない。

#### 30.1.4.5 値の書式

- 日時は `YYYY/MM/DD HH:mm:ss` 形式とし、タイムゾーンは Asia/Tokyo に固定する。Excelが日時として解釈できる形式であり、画面の表示とも一致させる。
- `null` は**空欄**とする。画面では「—」を表示するが（§12.1.1）、CSVでは記号を出さない。取り込み側が値の有無を判定できるようにするためである。

### 30.1.5 処理の流れ

依頼から応答までを、Route Handler 1回のリクエストで完結させる。

```text
利用者                        app                      DB
  │                          │                          │
  ├─「CSVダウンロード」───────▶│                          │
  │                          ├─ 権限・件数上限を確認 ─────▶│
  │                          ├─ 検索・CSVを組み立て ──────▶│
  │◀── CSV（ダウンロード） ────┤                          │
```

| 用途           | メソッド | URL                                  |
| ------------ | ---- | ------------------------------------- |
| マスタのCSV      | GET  | `/api/master/exports/csv`             |
| マスタ分類のCSV    | GET  | `/api/master/categories/exports/csv`  |

いずれも `withRoute` でラップする。**`/api` は [`proxy.ts`](../../../../src/proxy.ts) の `matcher` から除外されており、middlewareの認証ガードがかからない。** ハンドラーの先頭で `getCurrentUser()` を呼び、未ログインなら `UNAUTHORIZED` を投げる。生成物を保管しないため、依頼した本人以外が受け取る余地自体が無く、本人確認の仕組みは不要である。

処理の内容は次のとおり（`service.ts` の `exportMasterCsv` / `exportCategoryCsv`）。

1. `getCurrentUser()` で利用者を取得する。未ログインなら `UNAUTHORIZED`。ロールによる制限は行わない（§00.3）。
2. マスタのCSVはクエリパラメータの検索条件を検証する（一覧と同じ `validation.ts` のスキーマを再利用する）。
3. 対象件数を数え、上限を超える場合は `MASTER_EXPORT_LIMIT_EXCEEDED`（§30.1.6）。
4. 保存されている条件（マスタは検索条件、マスタ分類は全件）で検索する。並び順は §30.1.2 のとおり。
5. `export.ts` でCSV文字列を組み立てる（§30.1.4）。
6. `Content-Type` / `Content-Disposition` を付けて、その場でファイルを返す（§30.1.4.2）。

ダウンロードはブラウザーの遷移で行う（リンク先URLへの通常の画面遷移）。ファイルの内容をJavaScriptで受け取ってから保存する方式は採らない。

### 30.1.6 件数上限

一度にダウンロードできる行数の上限を **10,000行** とする。モジュール定数 `MASTER_EXPORT_MAX_ROWS` として `types.ts` に置き、環境変数にはしない。案件ごとに変える値ではなく、変えるなら生成方式そのものを見直すべき値だからである。

同期方式のため、CSV全体をメモリ上で組み立てて応答する。上限を大きく超えると、リクエストのタイムアウトやappのメモリ不足につながる。行数を増やす場合は、上限の引き上げではなく分割出力やストリーミングの導入、あるいはworkerへの切り出し（§30.1.9）を検討する。

超過は2段階で防ぐ。

1. **画面側**: 一覧は既に総件数を表示している（§10.1.6・§20.1.1）。総件数が上限を超える場合はボタンを無効化し、「対象が *N* 件あります。10,000件以下になるよう検索条件で絞り込んでください」と表示する。
2. **サーバー側**: Route Handlerで件数を数え、上限を超える場合はCSVを組み立てず `MASTER_EXPORT_LIMIT_EXCEEDED` を返す。`context` には対象件数と上限を含める。

件数の確認から生成までの間にマスタが増え、生成時点で上限をわずかに超える可能性はある。同じリクエストの中で連続して行うため実害はほぼ無く、再確認は行わない。

マスタ分類（MST-06）にも同じ上限を適用する。分類が10,000件を超えることは想定しにくいが、経路ごとに仕様を変えない。

### 30.1.7 エラー

| 状況                | エラーコード                         | 画面の扱い                  |
| ----------------- | ------------------------------ | ---------------------- |
| 件数が上限を超える         | `MASTER_EXPORT_LIMIT_EXCEEDED` | CSVを作らずエラー画面を表示する      |
| 未ログインでURLを直接開いた   | `UNAUTHORIZED`                 | ログイン画面へ誘導する            |

同期方式のため、生成中に起きたその他の例外（DB接続エラー等）はそのままリクエストの失敗として扱われる。特別な状態管理は持たない。

### 30.1.8 ダウンロードの記録

CSVダウンロードは、絞り込みの有無にかかわらずマスタを一度に取得できる操作であるため、**誰がいつ実行したかを記録する**。記録は §00.6 と同じくアプリケーションログで行う。

[`withRoute`](../../../../src/shared/observability/with-route.ts) が実行者（`userId` / `role`）を含めてログへ記録するため、業務コード側で追加の記録は不要である。

### 30.1.9 同期方式を採用した理由

**当初は worker（pg-boss・Cloud Run Jobs）を使う非同期方式で設計・実装したが、本番での動作確認（[`docs/todo/history/`](../../../todo/history/README.md) 参照）で Cloud Run Jobs の起動待ちが毎回1〜3分かかることが判明し、appのリクエスト内で完結する同期方式へ作り直した。**

| 観点        | 同期方式（採用）                    | worker方式（当初の設計）                              |
| --------- | --------------------------- | ---------------------------------------- |
| 追加の部品     | 無し                          | 生成物を管理するテーブル、状態の問い合わせ、workerの本番構成          |
| 利用者の操作    | ボタンを押すとすぐダウンロードが始まる          | ボタンを押して待つ（自動でダウンロードが始まる）                 |
| リクエストの制限  | Cloud Run のリクエストタイムアウント内に収める必要がある | 受けない                                     |
| 実測した処理時間  | 数秒（件数上限10,000件でも数十秒程度と想定）     | CSV生成自体は同程度だが、Cloud Run Jobsの起動待ちが数分かかった |

**実際に計測すると、CSV生成そのものは1〜2秒で終わっており、非同期化のコストに見合わなかった。** 一方で「時間のかかる可能性がある処理はworkerへ寄せる」というテンプレートの方針自体は変えておらず、`src/worker/index.ts` の雛形と本番のCloud Run Jobs構成は、将来ここより時間のかかる処理のために残してある。その進め方（依頼 → 生成 → 受け取り）の見本が [`40_マスタ情報Excel取得.md`](40_マスタ情報Excel取得.md) §40.12であり、本節と対になる形で「なぜそちらでは非同期方式を採るか」を記している。

## 30.2 CSVダウンロード

CSV文字列の組み立て（`export.ts`）は純粋関数であり、テストの費用対効果が高い。次を確認する。

- 先頭にBOM（U+FEFF）が付く。
- ヘッダー行が §30.1.4.3 および §30.1.4.4 の列順どおりに出力される。
- 改行コードがCRLFである。
- 値にカンマ・引用符・改行が含まれる場合に引用符で囲まれ、値中の引用符が2つ重ねられる。
- マスタ分類コードが4桁ゼロ埋めで出力される。
- 日時が `YYYY/MM/DD HH:mm:ss` 形式・Asia/Tokyo で出力される。
- `createdBy` / `updatedBy` が `null` の場合は空欄になる（「—」を出さない）。
- 0件の場合もヘッダー行だけのCSVが生成される。

生成（`service.ts` の `exportMasterCsv` / `exportCategoryCsv`）について確認する。

- 対象件数が上限と等しい場合はCSVを生成できる。
- 対象件数が上限を1件超えた場合は `MASTER_EXPORT_LIMIT_EXCEEDED` となり、`context` に対象件数と上限が含まれる。CSVは組み立てない。
- 検索条件がCSVの内容へ反映される（マスタ分類・マスタ文字列のAND条件）。
- ページ番号に相当する絞り込みが行われず、条件に一致する全件が出力される。
- VIEWERが実行できる（書き込み権限を要求しない）。

Route Handlerについて確認する。

- 未ログインのリクエストが `UNAUTHORIZED` になる。
- 検索条件（分類・キーワード）がクエリパラメータから正しく組み立てられる。
- 生成したCSVがファイル名つきで返る。
