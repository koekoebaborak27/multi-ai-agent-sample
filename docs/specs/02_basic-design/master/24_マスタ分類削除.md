## 24.1 削除条件

マスタ分類は、**そのマスタ分類に属するマスタが1件も存在しない場合にだけ**削除できる。

- 配下のマスタを一括削除する方式は採用しない。
- 配下にマスタが存在する場合は、先に個々のマスタを削除する必要がある。

配下にマスタが存在する場合、「削除」ボタンは表示するが、押下時に削除できない旨のエラーメッセージ（`MASTER_CATEGORY_HAS_MASTERS`）を表示する。件数は [§21.1.1](21_マスタ分類詳細.md#2111-表示項目) に表示されているため、利用者は事前に削除可否を把握できる。

## 24.2 マスタ分類削除確認ダイアログ

| 項目       | 表示内容                 |
| -------- | -------------------- |
| 見出し      | 「マスタ分類を削除しますか？」      |
| マスタ分類コード | 削除対象のマスタ分類コード        |
| マスタ分類名   | 削除対象のマスタ分類名          |
| 警告       | 「削除したマスタ分類は元に戻せません。」に加え、「システムで利用されているコードのため、編集・削除には十分注意してください。」を併記する（[§00.5.1](00_マスタ管理共通.md#0051-マスタ分類の編集削除実行時の警告アラート)） |
| ボタン      | 「キャンセル」および「削除する」     |

ダイアログの実装仕様（`AlertDialog` の使用、二重送信防止、フォーカス制御）は [14_マスタ削除.md §14.1.2](14_マスタ削除.md#1412-ダイアログの仕様) と同一とする。

## 24.3 削除の実行処理

1. Server Actionで書き込み権限を検証する。
2. 対象マスタ分類が現在も存在することを確認する。
3. 詳細画面を表示した時点の `updatedAt` と、データベースに保存されている現在の `updatedAt` を比較する。
4. 対象マスタ分類に属するマスタが0件であることを確認する。
5. 対象マスタ分類を物理削除する。
6. マスタ分類一覧画面へ遷移し、削除完了メッセージを表示する。

配下マスタの件数確認と削除は、同じデータベーストランザクション内で行う。ただしPostgreSQLの既定の分離レベル（READ COMMITTED）では、件数確認から削除までの間に別の利用者が同じマスタ分類へマスタを登録する可能性を排除できない。

配下にマスタが残ったまま分類が削除されないことは、最終的には `Master.categoryId` の外部キー制約が保証する。マスタ分類の削除で外部キー制約違反が発生した場合は業務エラーへ変換し、`MASTER_CATEGORY_HAS_MASTERS` として扱う。アプリケーションによる件数確認は、利用者へ件数を伝えるための事前確認と位置づける（[§11.6](11_マスタ新規登録.md#116-登録変更時の重複) の登録時の重複と同じ考え方）。

削除完了メッセージの表示方法は [14_マスタ削除.md §14.1.4](14_マスタ削除.md#1414-削除完了メッセージ) と同じとし、リダイレクト先を `/master/categories?deleted=1` とする。
