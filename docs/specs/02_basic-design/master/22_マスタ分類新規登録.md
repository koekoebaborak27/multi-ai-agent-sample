## 22.1 マスタ分類新規登録画面（MST-08）

マスタ分類一覧画面（MST-06）の「新規登録」ボタンから遷移する。**マスタ分類を登録できる画面はこの画面だけである。**

### 22.1.1 入力項目

| 項目       | UI部品     | 必須  | 入力仕様                                   |
| -------- | -------- |:---:| ---------------------------------------- |
| マスタ分類コード | テキストボックス | 必須  | 1文字以上50文字以内。英大文字、数字、ハイフン、アンダースコアだけを許可する |
| マスタ分類名   | テキストボックス | 必須  | 1文字以上30文字以内                             |

マスタ分類コードの許可形式は以下の正規表現で表す（マスタコードと同じ文字種のルールで、桁数だけ長い）。

```text
^[A-Z0-9_-]{1,50}$
```

英小文字が入力された場合に自動で英大文字へ変換せず、入力エラーとして表示する。分類コードは登録後もマスタ分類更新画面（MST-10）から変更できる（§23.1.1）。

### 22.1.2 ボタン

| ボタン   | 動作                                                   |
| ----- | ---------------------------------------------------- |
| 確認する  | 入力内容を検証し、問題がなければマスタ分類確認画面へ新規登録モードで進む。データベースへの登録は行わない |
| キャンセル | 入力内容を破棄し、マスタ分類一覧画面へ戻る                                |

「確認する」時点で、同じ名称のマスタ分類が登録されていないか確認する。

## 22.2 マスタ分類確認画面（MST-09）

マスタ分類の新規登録と更新で共通利用する論理画面。独立した画面ルートは作成せず、新規登録の場合はMST-08、更新の場合はMST-10のコンポーネントを確認状態へ切り替えて表示する。

### 22.2.1 表示項目

| 項目           | 新規登録モード  | 更新モード          |
| ------------ | -------- | -------------- |
| 処理内容         | 新規登録     | 更新             |
| 現在のマスタ分類コード  | 表示しない    | 更新前のマスタ分類コード   |
| 登録・更新後の分類コード | 入力した分類コード | 更新後のマスタ分類コード   |
| 現在のマスタ分類名    | 表示しない    | 更新前のマスタ分類名     |
| 登録・更新後の分類名   | 入力した分類名  | 更新後のマスタ分類名     |
| 登録マスタ件数      | 表示しない    | その分類に属するマスタの件数 |

更新モードでは分類コード・分類名の両方について現在値と変更後の値を並べ、変更前と変更後で値が同じ場合は「変更なし」と併記する（§11.2.1と同様の考え方）。更新モードでは登録マスタ件数も表示し、影響範囲の大きさを実行前に把握できるようにする。

### 22.2.2 ボタン

| ボタン     | 新規登録モード                               | 更新モード                                          |
| ------- | ------------------------------------- | ---------------------------------------------- |
| 実行      | 入力内容を再検証し、登録用Server Actionでマスタ分類を登録する | 入力内容と同時更新の有無を再検証し、更新用Server Actionでマスタ分類名を更新する |
| 入力内容を修正 | 入力値を保持したままマスタ分類新規登録画面へ戻る              | 入力値を保持したままマスタ分類更新画面へ戻る                         |
| キャンセル   | 入力内容を破棄し、マスタ分類一覧画面へ戻る                 | 入力内容を破棄し、対象マスタ分類の詳細画面へ戻る                       |

### 22.2.3 新規登録モードの実行処理

1. 入力値をサーバー側で再検証する。
2. 同じ名称または同じ分類コードのマスタ分類が存在しないことを確認する。
3. マスタ分類を登録する。`createdBy` と `updatedBy` に実行した利用者のユーザーIDを設定する。
4. 登録したマスタ分類の詳細画面へ遷移し、登録完了メッセージを表示する。

確認画面の表示後に別の利用者が同じ名称・同じ分類コードを登録する可能性があるため、「実行」時にも重複を検査する。最終的な重複防止は `MasterCategory.name` および `MasterCategory.code` の一意制約で保証し、制約違反はそれぞれ `MASTER_CATEGORY_CONFLICT`・`MASTER_CATEGORY_CODE_CONFLICT` へ変換する。

### 22.2.4 更新モードの実行処理

1. 対象マスタ分類が現在も存在することを確認する。
2. 更新後のマスタ分類名・マスタ分類コードをサーバー側で再検証する。
3. 入力画面を表示した時点の `updatedAt` と、データベースに保存されている現在の `updatedAt` を比較する。
4. 更新後の名称・分類コードを持つ**別の**マスタ分類が存在しないことを確認する。対象マスタ分類自身は重複判定から除外する。
5. マスタ分類名・分類コードを更新し、`updatedBy` に実行した利用者のユーザーIDを設定する。`createdBy` は変更しない。
6. 対象マスタ分類の詳細画面へ遷移し、更新完了メッセージを表示する。

`updatedAt` が一致しない場合は更新せず、同時更新エラーを表示する。

マスタ分類名・分類コードは表示専用の値であり、マスタとの関連は `Master.categoryId` が保持している。したがって分類名・分類コードを変更しても、その分類に属するマスタとの関連は影響を受けない。ただしマスタ検索一覧画面（MST-01）を初期の分類順で表示している場合は（§10.1.6）、名称の変更によって一覧の並び順が変わる。

**契約先・契約の画面は分類コードを手がかりに対象マスタ分類を探す実装のため、初期データとして投入する「契約先分類」（`CONTRACT_COMPANY_TYPE`）・「契約分類」（`CONTRACT_TYPE`）の分類コードを変更すると、契約先・契約の登録画面がその分類を見つけられなくなり、選択肢が「未設定」扱いになる。** この画面では分類コードの変更可否を機能的に制限しない（誤操作の防止は確認画面の変更前後の並記に委ねる）。

## 22.3 マスタ分類名・マスタ分類コード（MST-08・MST-10）

### 22.3.1 マスタ分類名

- 必須とする。
- 前後にある空白は検証前に除去する。
- 1文字以上30文字以内とする。
- 文字数はUnicodeコードポイント単位で数える。
- 使用可能文字は制限しない。日本語を含む任意の文字を許可する。
- システム全体で重複を許可しない。
- 確認画面への遷移時と「実行」時の両方で重複を確認する。
- 更新（MST-10）の場合、重複判定から対象マスタ分類自身を除外する。

### 22.3.2 マスタ分類コード

- 必須とする。
- 前後にある空白は検証前に除去する。
- 1文字以上50文字以内とする。
- 使用可能文字は英大文字 `A-Z`、数字 `0-9`、ハイフン `-`、アンダースコア `_` とする。
- 英小文字、空白、日本語および上記以外の記号は許可しない。
- システム全体で重複を許可しない（マスタコードと異なり、分類コードは分類をまたいで一意である）。
- 確認画面への遷移時と「実行」時の両方で重複を確認する。
- 更新（MST-10）の場合、重複判定から対象マスタ分類自身を除外する。
- 登録後も更新できる（§23.1.1）。

## 22.4 マスタ分類の登録と更新

- マスタ分類を登録できる。
- マスタ分類名が30文字の場合は登録でき、31文字の場合は拒否する。
- マスタ分類コードが50文字の場合は登録でき、51文字の場合は拒否する。
- マスタ分類コードに英小文字、日本語、空白または許可されていない記号が含まれる場合は拒否する。
- 前後の空白が除去されてから検証・登録される。
- 同じ名称のマスタ分類の登録を拒否する（`MASTER_CATEGORY_CONFLICT`）。
- 同じ分類コードのマスタ分類の登録を拒否する（`MASTER_CATEGORY_CODE_CONFLICT`）。
- マスタ分類名・分類コードを更新できる。
- 更新後の名称が別のマスタ分類と重複する場合は `MASTER_CATEGORY_CONFLICT` となる。
- 更新後の分類コードが別のマスタ分類と重複する場合は `MASTER_CATEGORY_CODE_CONFLICT` となる。
- **名称・コードを変えずに更新を実行した場合、自分自身との重複で拒否されない。**
- 存在しないマスタ分類の更新を拒否する。
- `updatedAt` が異なる場合に同時更新エラーとなる。
- 分類名・分類コードを更新しても、その分類に属するマスタの `categoryId` は変わらない。
- 更新で `updatedBy` だけが更新され、`createdBy` は変わらない。
- 更新処理で、変更前のマスタ分類名・分類コードがログへ渡される。
- マスタ新規登録画面（MST-02）およびマスタ更新画面（MST-05）から、新しいマスタ分類を登録できない。
- マスタ分類名・分類コードを変更しても、マスタ更新画面（MST-05）で行う所属分類の付け替えとは別の操作として扱われる。
