## 01.1 目的と背景

このシステムでは、契約種別・都道府県・支払方法のように、業務上必要になる選択肢の集合をあらかじめ固定のコードとして持たせず、マスタ管理機能から登録・保守する前提になっている。マスタ管理機能（`/master`）は、この「用途ごとにまとめたコードと内容の組」を検索・登録・参照・更新・削除するための機能である。

マスタは「マスタ分類」と「マスタ」の2階層で管理する。マスタ分類は契約種別や都道府県といった用途のまとまりを表し、マスタは各分類に属する個々のコードと内容の組を表す。分類を増やす操作とマスタを増やす操作は別の画面に分けており、マスタを登録するつもりで分類が増えてしまう事故を防いでいる。

このほか、マスタ分類とマスタの情報をまとめて社外・別システムへ持ち出すための、CSVダウンロードとマスタ情報Excel取得の2つの出力手段を備える。

## 01.2 用語

| 用語 | 説明 | 例 |
| --- | --- | --- |
| マスタ分類 | マスタデータを用途ごとにまとめる分類 | 契約種別、都道府県、支払方法 |
| マスタ分類コード | 利用者が入力・変更できるマスタ分類のコード | `CONTRACT_TYPE`、`PAYMENT_METHOD` |
| マスタコード | 同じマスタ分類内でマスタデータを識別するコード | `CON00001`、`PREF0001` |
| マスタ内容 | マスタコードに対応する表示内容 | 月額契約、東京都 |

## 01.3 実現していること

### 01.3.1 マスタの検索・登録・詳細・更新・削除

- マスタ分類とマスタコード・マスタ内容の文字列でマスタを検索し、一覧で確認できる（[`10_マスタ検索一覧.md`](../../02_basic-design/master/10_マスタ検索一覧.md)）。
- 登録済みのマスタ分類を選び、マスタコードとマスタ内容を入力してマスタを新規登録できる。登録前に確認画面で入力内容を提示し、「実行」を押した時点で初めてデータベースへ反映される（[`11_マスタ新規登録.md`](../../02_basic-design/master/11_マスタ新規登録.md)）。**この画面から新しいマスタ分類を作ることはできない。**
- マスタ詳細画面で1件のマスタの内容と、登録・更新した日時・利用者を確認できる（[`12_マスタ詳細.md`](../../02_basic-design/master/12_マスタ詳細.md)）。
- マスタの所属分類・マスタコード・マスタ内容はいずれも更新できる。更新も確認画面を経て実行し、確認画面では変更前と変更後の値を並べて表示し、変わらない項目には「変更なし」と併記することで、意図しない変更に利用者が気づけるようにしている（[`13_マスタ更新.md`](../../02_basic-design/master/13_マスタ更新.md)）。
- マスタは確認ダイアログを経て削除できる（[`14_マスタ削除.md`](../../02_basic-design/master/14_マスタ削除.md)）。

### 01.3.2 マスタ分類の一覧・詳細・登録・更新・削除

- マスタ分類一覧画面で、登録済みの分類とそれぞれに属するマスタの件数を確認できる（[`20_マスタ分類一覧.md`](../../02_basic-design/master/20_マスタ分類一覧.md)）。
- マスタ分類を新しく登録できる画面はこのマスタ分類新規登録画面だけであり、マスタの登録画面から分類を増やす経路は無い（[`22_マスタ分類新規登録.md`](../../02_basic-design/master/22_マスタ分類新規登録.md)）。
- マスタ分類詳細画面で、分類コード・分類名・登録マスタ件数と、登録・更新した日時・利用者を確認できる（[`21_マスタ分類詳細.md`](../../02_basic-design/master/21_マスタ分類詳細.md)）。
- マスタ分類コード・マスタ分類名を更新できる（[`23_マスタ分類更新.md`](../../02_basic-design/master/23_マスタ分類更新.md)）。個々のマスタの所属分類を変更する操作ではなく、分類そのものの名称・コードを変更する操作である。マスタの所属分類を変更したい場合は、マスタ更新画面（§01.3.1）から行う。
- マスタ分類は、その分類に属するマスタが1件も残っていない場合にだけ削除できる（[`24_マスタ分類削除.md`](../../02_basic-design/master/24_マスタ分類削除.md)）。属するマスタが残っている場合は、先にマスタを削除する必要がある。

### 01.3.3 CSVダウンロード

- マスタ検索一覧画面・マスタ分類一覧画面それぞれから、一覧に表示している内容をCSVファイルとしてダウンロードできる（[`30_CSVダウンロード.md`](../../02_basic-design/master/30_CSVダウンロード.md)）。
- マスタのCSVは、画面で指定している検索条件（マスタ分類・マスタ文字列）に一致する全件が対象になる。表示中のページに関わらず、条件に一致するすべての行が出力される。
- ボタンを押すとその場でダウンロードが始まる、出力専用の機能である。CSVを取り込んでの登録・更新は行わない（→01.6）。
- 一度にダウンロードできる件数には上限があり、対象がそれを超える場合は検索条件で絞り込むよう案内する。

### 01.3.4 マスタ情報Excel取得

- マスタ分類とマスタの情報を1つのExcelファイルにまとめて取得できる、専用の画面（マスタ情報Excel取得画面）を持つ（[`40_マスタ情報Excel取得.md`](../../02_basic-design/master/40_マスタ情報Excel取得.md)）。
- 「Excelを作成する」を押すと、その場でファイルは完成させず、裏側の非同期処理（worker）へ作成を依頼する。画面は依頼の受付だけを即座に返し、作成には数分程度かかる場合がある。
- 依頼の状況は実行履歴一覧に「受付済み」「作成中」「完了」「失敗」として残り、一覧は自動的に最新の状態へ更新される。完成したファイルは履歴一覧の「ダウンロード」から取得する。
- 実行履歴は依頼した本人に限らず全利用者へ公開され、他の利用者が依頼したファイルも一覧からダウンロードできる。
- 作成したファイルは作成から一定期間だけ保持され、期限を過ぎるとダウンロードできなくなる（履歴の行自体は残る）。
- この機能は、時間のかかる可能性がある処理をworkerへ寄せるという方針の実装例としての位置づけも兼ねる（→01.7）。

## 01.4 権限

| 操作 | `ADMIN` | `OPERATOR` | `VIEWER` |
| --- | :---: | :---: | :---: |
| マスタの検索・一覧表示・詳細表示 | ○ | ○ | ○ |
| マスタの新規登録・更新・削除 | ○ | ○ | × |
| マスタ分類の一覧表示・詳細表示 | ○ | ○ | ○ |
| マスタ分類の新規登録・更新・削除 | ○ | ○ | × |
| CSVダウンロード | ○ | ○ | ○ |
| マスタ情報Excel取得の実行・履歴閲覧・ダウンロード | ○ | ○ | ○ |

`VIEWER`には新規登録・編集・削除のボタンを表示しない。CSVダウンロードとマスタ情報Excel取得は参照の範囲にとどまる操作として、全ロールへ開放している。

マスタコードの変更のようにマスタ内容の更新と性質の異なる操作であっても、権限は`ADMIN`・`OPERATOR`で統一しており、操作ごとに権限を細分化していない。

## 01.5 安全のために守っていること

- マスタおよびマスタ分類の削除は物理削除であり、画面上の復元手段は無い。削除した内容を確認する必要が生じた場合は、サーバー側の記録（ログ）を参照する運用とする。
- マスタ・マスタ分類の更新および削除では、画面を開いた時点の情報と、実行しようとしている時点の情報を突き合わせる。その間に他の利用者が先に更新・削除していた場合は処理を行わず、最新の内容を確認するよう促す（同時更新の検知）。
- 登録・更新・削除といった書き込みを伴う操作は、画面上でボタンを表示しないだけでなく、実際に処理を受け付ける側でも書き込み権限を必ず検証する。権限の無い利用者が画面を経由せずに操作を呼び出しても拒否される。
- 契約先・契約管理機能がコード上で固定的に参照しているマスタ分類を編集・削除しようとした場合、対象のコード・名称を示したうえで警告を表示する。ただし操作自体を禁止する仕組みは持たず、警告を確認したうえで利用者が判断して進める（→01.7）。
- CSVダウンロードは、絞り込みの有無にかかわらずマスタを一度に取得できる操作であるため、誰がいつ実行したかを記録する。

## 01.6 前提と制約

- マスタおよびマスタ分類に、利用者が任意に指定・保存できる表示順は持たない。一覧の並び順は、既定の列（分類名やコードなど）による昇順・降順の切り替えにとどまる。
- マスタおよびマスタ分類に、有効期間や有効・無効の状態は持たない。登録されているマスタはすべて有効として扱い、使わなくなったマスタは削除で対応する。
- 登録・更新・削除の変更履歴を参照する画面は持たない。追跡が必要な場合はサーバー側の記録（ログ）を確認する運用とする。
- CSVによる一括登録・一括更新は対象外とする。CSVはダウンロード（出力）専用であり、取り込みの手段は設けない。

## 01.7 関連機能との切り分け

| 隣接する範囲 | 扱い |
| --- | --- |
| 契約先・契約管理機能 | 契約先分類・契約分類として、マスタ分類コードを固定値でコード上から参照する。本機能側は該当分類の編集・削除時に警告を表示するにとどまり、参照側の画面がどう振る舞うかは契約先・契約管理機能の要件・設計に委ねる。 |
| マスタ情報Excel取得の非同期処理 | worker（Cloud Run Jobs）を使った依頼・生成・受け取りの仕組みで実現する。worker自体の実行基盤・本番構成は本機能固有の範囲を超えるため、インフラ側のドキュメントに委ねる。 |
| ログイン・権限の枠組み | ログインが必須である範囲、ロール（`ADMIN`/`OPERATOR`/`VIEWER`）自体の定義はログイン機能の要件に委ねる（[`docs/specs/01_requirements/login/01_ログイン.md`](../login/01_ログイン.md)）。本機能は既存のロールに対する操作可否（→01.4）だけを定める。 |

## 01.8 対象外・実装されていないもの

- マスタ・マスタ分類のCSVによる一括登録・一括更新（インポート）
- マスタ・マスタ分類の有効期間や有効・無効状態の管理
- 登録・更新・削除の変更履歴を参照する画面
- 一覧の並び順を任意に指定・保存する機能
- マスタ情報Excel取得の完成時のメール通知や、定期的な自動実行
