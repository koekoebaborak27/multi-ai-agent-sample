## 01.1 目的と背景

このシステムを使うには必ずログインが必要（未ログインで開ける画面は無い。→ [01.6](#016-関連機能との切り分け)の`about`を除く）。ログイン画面は、ID・パスワードによる認証と、案件によって有効化する Microsoft Entra ID（旧Azure AD）認証の2方式に対応し、ログイン後は権限（ロール）に応じて画面が出し分けられる土台になっている。

## 01.2 用語

> **ロール**とは、利用者に割り当てる権限区分のこと。`ADMIN`（管理者）・`OPERATOR`（担当者）・`VIEWER`（閲覧者）の3種類があり、ログイン時に発行する引換券（セッション）へ記録され、以降の画面表示・操作可否の判定に使われる。

> **初回パスワード変更**とは、管理者が新しい利用者を登録した直後の状態（`mustChangePassword = true`）で最初にログインした際、他の画面を使う前に強制的にパスワード変更画面へ案内される仕組みのこと。

> **Microsoft Entra ID**とは、Microsoftが提供するログイン基盤のこと。この案件で使う設定（クライアントID等の環境変数）が揃っている場合のみ、ログイン画面に選択肢として表示される。

## 01.3 実現すること

### 01.3.1 ログイン方法

| 方法                 | 表示条件                                           | 概要                                      |
| ------------------ | ---------------------------------------------- | --------------------------------------- |
| ID・パスワード           | 常に表示                                           | ユーザーID・パスワードを入力してログインする                 |
| Microsoft Entra ID | `AUTH_MICROSOFT_ENTRA_ID_*` 系の環境変数が揃っている場合のみ表示 | ボタン1つでMicrosoftのログイン画面へ移動し、認証後にこのアプリへ戻る |

2つの方法が両方表示される場合は、Entra ID のボタンを上、ID・パスワードの入力欄を下に配置し、間に「または」の区切りを入れる。

### 01.3.2 画面の構成（`/login`）

- 見出し「サンプル契約管理システム」、説明文「ログインしてください」
- ユーザーID欄（必須、最大64文字）・パスワード欄（必須、マスク表示）
- ログインボタン（送信中は「ログイン中...」に変わり、二重送信を防ぐ）
- 「パスワードを忘れた場合はこちら」リンク（→ `/forgot-password`。パスワードリセット機能の入口。詳細は [`docs/specs/01_requirements/password-reset/01_パスワードリセット.md`](../password-reset/01_パスワードリセット.md)）
- 「システム紹介」リンク（→ `/about`。別タブで開く）
- パスワード再設定の直後に遷移してきた場合（`?message=password-reset`）は、「パスワードを変更しました。新しいパスワードでログインしてください。」を追加表示する
- すでにログイン済みの利用者がこの画面を開いた場合は、トップ画面（`/`）へ自動的に移動させる

### 01.3.3 ログイン失敗時の表示

- ユーザーIDまたはパスワードが誤っている場合、**どちらが違うかを区別せず**「ユーザーIDまたはパスワードが正しくありません」と表示する（→ [01.4](#014-安全のために守っていること)）
- アカウントがロックされている場合は「アカウントがロックされています。管理者にお問い合わせください」と表示する

### 01.3.4 ログイン失敗回数によるロック

- 既定20回（環境変数 `MAX_ATTEMPTS`で変更可）連続でパスワードを誤ると、アカウントを自動的にロックする
- ロック済みのアカウントは、正しいパスワードを入力してもログインできない
- ロック解除は管理者による利用者情報の更新、またはパスワードリセット機能の再設定完了時に行われる（→ [`docs/specs/01_requirements/password-reset/01_パスワードリセット.md`](../password-reset/01_パスワードリセット.md)）
- ログインに成功すると、それまでの失敗回数はリセットされる

### 01.3.5 Microsoft Entra ID ログイン時の利用者作成

- 初めてEntra IDでログインした利用者は、このアプリの利用者情報が自動的に作られる（ロールは`VIEWER`固定。管理者が必要に応じて後から昇格させる）
- すでに削除済み・利用停止（ロック）中の利用者は、Entra ID経由でもログインできない

### 01.3.6 セッション（ログイン状態）

- ログイン状態はサーバー側に保存せず、JWT（引換券）にロール・初回パスワード変更要否・認証方式を埋め込んで保持する
- 有効期限は90分。切れると再度ログインが必要になる

### 01.3.7 初回ログイン時のパスワード変更誘導

- `mustChangePassword`が`true`の利用者がログインすると、他のどの画面を開こうとしても`/settings/password`（パスワード変更画面）へ自動的に案内される（保存処理の呼び出しは対象外。→ [01.4](#014-安全のために守っていること)）
- パスワード変更画面には「初回ログインのため、パスワードの変更が必要です。」という案内文を表示する
- 新しいパスワードは8文字以上・128文字以内で、英字と数字の両方を含み、現在のパスワードとは異なることを求める
- 変更が完了すると自動的にログアウトし、ログイン画面へ戻す（引換券に残る「変更が必要」の情報を新しいログインで作り直させるため）
- このパスワード変更画面は、初回だけでなく本人がいつでも任意にパスワードを変更する目的でも共用される（`/settings/password`への直接アクセス）

### 01.3.8 ログイン必須の範囲

- ログインしていない利用者は、`/login`・`/forgot-password`・`/reset-password`・`/about`以外のすべての画面・保存処理への到達を`/login`へ差し戻される
- ログアウトすると`/login`へ戻る

### 01.3.9 権限によるアクセス制御

- ログイン自体はロールを問わず全員が行える
- ログイン後の画面ごとのアクセス制御（管理者専用画面・お知らせ管理など）は、ログイン画面ではなく各機能の要件・設計に委ねる

## 01.4 安全のために守っていること

- ログイン失敗時のエラーメッセージは、IDとパスワードのどちらが誤りかを区別しない（存在するIDを探り当てる手がかりを与えないため）
- パスワードの総当たりを防ぐため、連続失敗回数を数えて既定回数でアカウントをロックする
- パスワード変更は、現在のパスワードの入力を必須にする（本人以外が勝手に変更できないようにするため）
- 初回パスワード変更が済むまでは、ログイン画面以外の画面・保存処理へ進めない（画面表示側だけでなく、リクエストを最初に受ける入口 `src/proxy.ts` でも確認する）
- 保存処理（Server Action）の呼び出し時は、画面遷移の案内（トップ画面への差し戻し等）を行わない。案内をそのまま処理要求へ適用すると、ログイン直後に画面同士を行き来し続けてしまうため

## 01.5 前提と制約

- Microsoft Entra ID ログインは、この案件で使う設定（環境変数）が揃っている場合のみ有効。揃っていない場合はID・パスワードのみで運用する（動作確認の位置づけは冒頭の注記を参照）
- パスワード変更画面（`/settings/password`）自体の詳細な要件は、この文書では初回ログイン誘導の到達先として触れるにとどめ、機能そのものの独立した要件定義は作成していない（TODOの棚卸し対象外）

| 隣接する範囲 | 扱い |

| パスワードを忘れた場合の再設定（`/forgot-password`・`/reset-password`） | パスワードリセット機能として別に要件定義・基本設計済み（[`docs/specs/01_requirements/password-reset/`](../password-reset/)・[`docs/specs/02_basic-design/password-reset/`](../../02_basic-design/password-reset/)） |
| メールアドレスの登録・変更 | パスワードリセット機能の一部として別に文書化済み（[`20_メールアドレス管理.md`](../../02_basic-design/password-reset/20_メールアドレス管理.md)） |
| ログイン後のトップ画面（ダッシュボード） | 別に要件定義・基本設計する（[`docs/specs/01_requirements/dashboard/`](../dashboard/)） |
| `/about`（システム紹介） | ログイン不要な公開ページ。この文書・TODOの棚卸し対象外 |

## 01.7 対象外・実装されていないもの

- パスワード以外の多要素認証（ワンタイムパスワード等）
- ログイン履歴・アクセスログの画面表示（サーバー側の観測性ログとしては別途記録している）
- 「ログイン状態を保持する」チェックボックス等によるセッション延長。セッションは常に90分固定
- IPアドレス等によるアクセス制限
