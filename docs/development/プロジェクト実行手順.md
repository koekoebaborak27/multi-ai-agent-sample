# プロジェクト実行手順

[`プロジェクトの導入手順.md`](プロジェクトの導入手順.md)で環境構築を終えた人向けの手順です。パソコンを閉じて、別の日に改めてこのプロジェクトを使うとき（起動してログインするところまで）と、作業を終えるときの手順をまとめています。

> **PowerShellの開き方**：この手順のコマンドはすべて、PowerShellを普通に開いて実行してください。「管理者として実行」は使用しません。

## 起動する

1. Docker Desktopを起動しておく（アイコンをダブルクリックし、起動完了まで待つ）
2. プロジェクトのフォルダで、次のコマンドを実行し、DB・アプリ・workerの起動を開始する

   実行場所：プロジェクトのフォルダ

   ```powershell
   docker compose -f docker/docker-compose.yml up -d
   ```

3. アプリの起動完了をログで確認する

   手順2のコマンドが終了しても、アプリが利用できる状態になるまでには時間がかかることがあります。続けて次のコマンドを実行してください。

   実行場所：プロジェクトのフォルダ

   ```powershell
   docker compose -f docker/docker-compose.yml logs -f app
   ```

   `Ready in ...`（起動完了）と表示されるまで待ってください。表示されたら、同じPowerShellで`Ctrl+C`を押してログの確認を終了し、手順4へ進んでください。`Ctrl+C`で終了するのはログの表示だけなので、アプリは動いたままです。

4. ブラウザで <http://localhost:3000> を開き、前回設定したログインID・パスワードでログインする

   > **補足**：開いたままのタブがある場合は、ハード再読み込み（`Ctrl + Shift + R`）してから操作してください。開いたままのページが前回起動時のサーバーを覚えていると、ログインなどの操作で「Failed to find Server Action」というエラーになることがあります。

## 終了する

実行場所：プロジェクトのフォルダ

```powershell
docker compose -f docker/docker-compose.yml stop
```

データは削除されないため、次回も同じデータで再開できます。次回起動するときは、上の「起動する」の手順2からやり直してください。

> **補足**：`stop`の代わりにDocker Desktopのアプリごと終了しても構いません。ただし、パソコンを再起動しただけではコンテナは自動で起動し直さないため、次回もあらためて手順2（`up -d`）の実行が必要です。

## Dockerを使わずパソコン上で直接動かしている場合

[「Dockerではなくパソコン上で直接動かす」](Dockerではなくパソコン上で直接動かす.md)の方法で構築した場合は、次のコマンドで起動・終了します。

起動（実行場所：プロジェクトのフォルダ、それぞれ別のターミナルで）：

```powershell
docker compose -f docker/docker-compose.yml up -d db   # PostgreSQL のみ起動
pnpm dev                                                # 開発サーバ
pnpm worker                                             # ジョブワーカー（使っている場合のみ）
```

終了：`pnpm dev`・`pnpm worker`はそれぞれのターミナルで`Ctrl+C`、データベースは`docker compose -f docker/docker-compose.yml stop db`です。

## うまく起動しないとき

[「プロジェクトの導入手順」のトラブルシューティング](プロジェクトの導入手順.md#トラブルシューティング)を参照してください。
