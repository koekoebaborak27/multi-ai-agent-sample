# プロジェクトの導入手順

このプロジェクトを**初めて使う人**向けの手順書です。非エンジニアの方でも迷わないように書いています。

## この手順書の読み方

- **【必須】**：全員が対応してください
- **【該当する場合のみ】**：自分に関係がある場合だけ対応してください
- **【不要】**：このプロジェクトでは使いません（対応不要）

## 全体の流れ

1. ソフトを準備する
2. プロジェクトのファイル一式を入手する
3. 初期設定をする
4. 起動して確認する
5. （該当する人だけ）使う場面が来たら入れるもの
6. （別ルート）本番環境をゼロから新しく作る場合

---

## ステップ1：ソフトを準備する

以下の4つは全員が対応してください。入れないとアプリが起動できません。

### Git 【必須】

ソースコードを取得し、変更履歴を管理するための基本ソフトです。

- **方法**：ダウンロード＋インストーラー実行（コマンドは不要）
- **入手先**：<https://git-scm.com/downloads>
- ダウンロードしたファイルをダブルクリックし、案内どおりに進めれば完了です。

### Docker Desktop 【必須】

アプリ・データベース・裏方処理をまとめて「箱（コンテナ）」の中で動かします。パソコンに直接データベースを入れる必要がなくなります。

- **方法**：ダウンロード＋インストーラー実行（コマンドは不要）
- **入手先**：<https://www.docker.com/products/docker-desktop/>
- ダウンロードしたファイルをダブルクリックし、案内どおりに進めれば完了です。

> **追加の注意（Windowsのみ・エラーが出た場合だけ対応）**
> Docker Desktopのインストーラーは「WSL2」という土台も自動で一緒に入れてくれることが多いです。もし起動時に `WSL 2 installation is incomplete` のようなエラーが出たら、PowerShellを「管理者として実行」し、次のコマンドを実行してパソコンを再起動してください。エラーが出なければ実行不要です。
>
> ```powershell
> wsl --install
> ```

### Node.js 22（LTS版） 【必須】

エディタの入力補完や、コードの間違いチェックをパソコン上で行うために使います。

**「22」でなければならない理由**：本番サーバー（Docker）が実際に動いているバージョンが22系だからです。プロジェクトの設定ファイル（`package.json`）は「22.12.0以上」であればインストール自体は通りますが、動作を確認しているのは22系だけです。23や24など新しいバージョンは本番やCIでは試していないため、「動くこともあるが保証はできない」バージョンにあたります。

- **方法**：ダウンロード＋インストーラー実行（コマンドは不要）
- **入手先**：<https://nodejs.org/dist/latest-v22.x/>（ファイル一覧ページ）
- nodejs.orgのトップページにある選択画面（Windows／バージョン／npm・pnpm／nvm・fnm・Dockerなどを選ばせるもの）は**使いません**。あちらは既定のバージョンが時期によって24などに変わり、かつ普通のインストーラーが用意されていないためです。
- 一覧の中から「`node-v22.x.x-x64.msi`」というファイルを探してクリックし、ダウンロードされたファイルをダブルクリックしてインストールしてください（`x`の部分は数字、`x64`はWindowsの通常のパソコン向けです）。

確認（任意・省略可。実行場所：どこでもOK）：

```powershell
node --version   # v22.x.x と表示されれば成功
```

### pnpm（バージョン10.15.1） 【必須】

このアプリが使う部品（ライブラリ）一式をまとめてダウンロード・管理する道具です。別サイトからのダウンロードは不要で、Node.jsに付属する機能で有効化します。

- **方法**：コマンドのみ（ダウンロードページは無し）

実行場所：どこでもOK（パソコンに1回だけ）

```powershell
corepack enable
corepack prepare pnpm@10.15.1 --activate
```

## ステップ2：プロジェクトのファイル一式を入手する

このプロジェクトのファイル一式を、自分のパソコンに持ってくる作業です。方法は2つありますが、**基本は方法A（Git clone）を使ってください**。

### 方法A：Git clone（基本はこちら） 【必須】

コードを直す・将来直すかもしれない人、チームで開発する人向けの方法です。GitHubと変更履歴がつながった状態でファイル一式を取得します。

実行場所：プロジェクトを置きたい場所（例：`C:\work\code` など）

```powershell
git clone https://github.com/koekoebaborak27/multi-ai-agent-sample.git
```

実行すると、そのフォルダの中に `multi-ai-agent-sample` という名前のフォルダが作られます。以降の手順は、この中のフォルダ（`README.md`がある場所）で行います。

### 方法B：フォルダを丸ごとコピー（補足・特別な事情がある人だけ）

コードを直さず、とりあえず動かして見るだけの人向けの簡易的な方法です。元のパソコン（またはUSB・共有フォルダ）から、プロジェクトのフォルダをそのままコピーします。

注意点：

- **`node_modules`フォルダはコピーしないでください。** パソコンごとに壊れやすい部品なので、コピー先で後述の「部品一式のインストール」をやり直すほうが安全です。
- **`.env`ファイルはそのままコピーされます。** そのため、このあとの「設定ファイル（.env）の作成」は不要です（すでにあるファイルの中身を確認するだけでOKです）。
- `docker-data`（データベースの中身）や`uploads`（アップロードしたファイル）も一緒にコピーされます。中身を引き継ぎたくない場合は、コピー後にこの2つのフォルダを削除してください。
- 将来コードを直して提出したくなった場合は、あらためて方法A（Git clone）でやり直すことをおすすめします。

## ステップ3：初期設定をする

ソフトのインストールではなく、フォルダの中で1回だけ行う準備です。

### 部品一式のインストール 【必須】

アプリが使うライブラリ一式を、プロジェクトのフォルダにダウンロードします。

実行場所：プロジェクトのフォルダ（`README.md`がある場所）

```powershell
pnpm install
```

### 設定ファイル（.env）の作成 【必須（方法Aの場合）】

データベースの接続先などの設定を保存するファイルです。パソコンごとの個人設定にあたるため、共有の履歴（Git）には含まれておらず、Git cloneした直後には存在しません。

> **ステップ2で方法B（フォルダを丸ごとコピー）を選んだ方へ**：`.env`はすでにコピーされているはずなので、この手順は不要です。プロジェクトのフォルダに`.env`というファイルがあることだけ確認してください。

実行場所：プロジェクトのフォルダ（PowerShell）

```powershell
Copy-Item .env.example .env
```

Docker Desktopでまとめて起動するだけなら、中身は初期値のままで問題ありません。

> **補足：`.env.local`ではなく`.env`である理由**
> Next.js自体は`.env.local`という名前のファイルも読み込めますが、このプロジェクトのDocker側（`worker`の起動スクリプト）は**ファイル名を`.env`と決め打ちで**読みに行く作りになっています。`.env.local`という名前で作ってしまうと、パソコン上で直接`pnpm dev`する分には動くのに、Docker一式で起動する`worker`だけ設定が読み込まれない、という分かりにくい不具合につながります。このプロジェクトでは`.env`で統一してください。

## ステップ4：起動して確認する

1. Docker Desktopを起動しておく（アイコンをダブルクリックし、起動完了まで待つ）
2. プロジェクトのフォルダで、次のコマンドを実行してアプリ一式を起動する

   実行場所：プロジェクトのフォルダ

   ```powershell
   docker compose -f docker/docker-compose.yml up -d
   ```

   初回はダウンロードとビルドのため数分かかります。

3. 起動が終わるまで待つ

   アプリの箱の中では、起動のたびに「部品をそろえる → データベースとやり取りする部品を作る → データベースにテーブルを作る → Webサーバーを起動する」を順番に自動実行しています。初回はここに数分かかります。

   次のコマンドで、`Ready in ...`（起動完了）と表示されるまで待ってください。表示されたら`Ctrl+C`で見るのをやめて構いません（アプリは動いたままです）。

   実行場所：プロジェクトのフォルダ

   ```powershell
   docker compose -f docker/docker-compose.yml logs -f app
   ```

4. （初回のみ）初期管理者などのデータを登録する

   実行場所：プロジェクトのフォルダ

   ```powershell
   docker compose -f docker/docker-compose.yml exec app pnpm prisma:seed
   ```

   > **補足**：テーブルを作る作業は手順3で自動実行済みですが、初期データの登録だけは自動実行されないため、初回のみ手で実行します。手順3の完了を待たずに実行すると「The table `public.User` does not exist」というエラーになります。

5. ブラウザで <http://localhost:3000> を開き、次の初期管理者でログインできれば完了です。

   | 項目 | 値 |
   |---|---|
   | ログインID | `admin` |
   | 初期パスワード | `Admin@123` |

   初回ログイン後はパスワード変更画面に案内されます。

   > **補足**：この後アプリを再起動する場面（`docker compose ... up -d`をやり直す等）があったときは、ブラウザ側もハード再読み込み（`Ctrl + Shift + R`）してから操作してください。開いたままのページが再起動前のサーバーを覚えていると、ログインなどの操作で「Failed to find Server Action」というエラーになることがあります。

## 使う場面が来たら入れるもの

全員には不要です。該当する作業をする人だけ対応してください。

### GitHub CLI（gh） 【該当する場合のみ】

コードを変更してチームに提出する人（プルリクエストを作る人）は入れてください。閲覧・動作確認だけの人は不要です。

- **方法**：AかB、どちらか一方だけでOK（両方やる必要はありません）
  - **A. ブラウザでインストール**：<https://cli.github.com/> を開き、インストーラーを実行するだけ（コマンド不要）
  - **B. コマンドでインストール**（実行場所：どこでもOK）

    ```powershell
    winget install --id GitHub.cli
    ```

- A・Bどちらの方法でインストールしても、そのあと下のコマンドで1回だけログインしてください（ここは共通で必須です）。

  実行場所：どこでもOK（初回のみ）

  ```powershell
  gh auth login
  ```

### Google Cloud CLI（gcloud） 【該当する場合のみ】

本番環境（Google Cloud）で、裏方処理（worker）用の特別な起動方法を手動で登録するときだけ使います。普段の開発や画面確認では一切使いません。

- **方法**：ダウンロード＋インストーラー実行（コマンド不要）
- **入手先**：<https://cloud.google.com/sdk/docs/install>
- インストール後、下のコマンドで1回だけログインしてください（インストールとは別の手順です）。

  実行場所：どこでもOK（初回のみ・本番作業をする人だけ）

  ```powershell
  gcloud auth login
  ```

### Playwrightのブラウザ本体 【該当する場合のみ】

実際にブラウザを自動操作して画面の動きを確認する「E2Eテスト」を動かすときだけ必要です。

- **方法**：コマンドのみ（ダウンロードページは無し）

実行場所：プロジェクトのフォルダ

```powershell
pnpm exec playwright install chromium
```

### VSCodeの拡張機能（ESLint／Prettier／Tailwind CSS／Prisma／Docker） 【該当する場合のみ】

コードの間違いや整形の乱れを、保存した瞬間にエディタが教えてくれるようになります。無くてもアプリは動きます。

- **方法**：VSCode内の拡張機能タブから検索してインストール（ブラウザでのダウンロードは不要）。左側の拡張機能アイコンをクリック→名前で検索→「インストール」ボタンを押すだけです。

### メール送信を試す（パスワード再発行など） 【該当する場合のみ】

このプロジェクトには「パスワードを忘れた」「メールアドレスを変更する」といった、メールを送る機能があります。通常のローカル開発では**実際にはメールを送らず、内容をログへ表示するだけ**（`.env`の`MAIL_TRANSPORT=console`が既定値）になっているため、多くの人はこの先の対応は不要です。**実際にメールが届くところまで確認したい人だけ**、以下を対応してください。

> 送信には無料のGmailアカウントを使います（このテンプレートの方針。理由は[`infra_design_09_メール送信.md`](../specs/99_infra/infra_design_09_メール送信.md#091-手順8-メール送信を設定する)を参照）。

#### 1. 送信専用のGoogleアカウントを新しく作る

**自分の個人用アカウントは使わないでください。** [Googleアカウント作成ページ](https://accounts.google.com/signup)で、確認用に新しいアカウントを作ります。

| 項目 | 入力する内容 |
|---|---|
| 用途 | 「個人で使用」を選ぶ（ビジネス用は有料版に誘導されるため避ける） |
| 名前 | 送信元として表示されてよいもの（例：`サンプル契約管理システム`） |
| メールアドレス | 用途がわかる名前（例：`案件名-mail@gmail.com`） |
| パスワード | 他で使っていない新しいもの |

> 途中で電話番号の確認を求められることがあります。既存のアカウントと同じ電話番号でも通常は登録できます。

#### 2. 2段階認証を有効にする

作ったアカウントでログインした状態で、[2段階認証プロセスの設定](https://myaccount.google.com/signinoptions/twosv)を開き、有効にします（電話番号へのSMSが手軽です）。

**なぜ必要か**：次の手順の「アプリパスワード」は、2段階認証が有効なアカウントでしか発行できません。この手順は省略できません。

> 別のGoogleアカウントでログイン中だと、そちらの画面が開くことがあります。画面右上のアイコンで、今回作った送信専用アカウントが選ばれているか確認してください。

#### 3. アプリパスワードを発行する

[アプリパスワードの発行ページ](https://myaccount.google.com/apppasswords)を開きます（Googleアカウントのメニューからは辿れないため、このリンクから直接開いてください）。

1. 「アプリ名」に案件名など（例：`サンプル契約管理システム`）を入力する
2. 「作成」を押す
3. **16文字のパスワードが表示されます。この画面を閉じると二度と表示されないので、必ず控えてください。**

表示は`abcd efgh ijkl mnop`のように4文字ずつ区切られていますが、**次の手順で設定するときは空白を詰めて`abcdefghijklmnop`と続けて書きます**（空白が残っていると認証に失敗します）。

#### 4. `.env`ファイルに書き込む

[ステップ3](#ステップ3初期設定をする)で作成した`.env`ファイルをテキストエディタで開き、次の項目を書き換えます（`MAIL_TRANSPORT`と`MAIL_FROM_NAME`以外はすでに空欄で存在しているはずなので、値を埋めるだけです）。

```
MAIL_TRANSPORT=smtp
MAIL_FROM=<手順1で作ったGmailアドレス>
MAIL_FROM_NAME=<差出人として表示したい名前>
SMTP_USER=<手順1で作ったGmailアドレスと同じもの>
SMTP_PASSWORD=<手順3で控えた16文字。空白は詰める>
```

| 項目 | 補足 |
|---|---|
| `MAIL_TRANSPORT` | `console`（既定値）のままだと送信せずログ表示だけになります。実際に送るので`smtp`に変更します |
| `MAIL_FROM` | `SMTP_USER`と同じ値にしてください。違う値を書いても、Gmailは送信時に実際のアカウントのアドレスへ書き換えます |
| `SMTP_HOST` / `SMTP_PORT` | すでに`smtp.gmail.com` / `587`が入っているので変更不要です |

書き換えたら、[ステップ4](#ステップ4起動して確認する)のコマンドでアプリを再起動してください（`.env`の変更はアプリの再起動後に反映されます）。

#### 5. 送れることを確認する（任意）

画面から「パスワードを忘れた」の申し込みを実際に行い、**手順1で作ったアカウントとは別の、自分が受信できるメールアドレス**宛に届くか確認してください。届かない場合や、うまくいかない場合の対処は[`infra_design_09_メール送信.md`の「うまくいかないとき」](../specs/99_infra/infra_design_09_メール送信.md#0919-うまくいかないとき)を参照してください。

## 不要（このプロジェクトでは使いません）

### SSH鍵の作成 【不要】

このプロジェクトはGitHubへ「パスワード方式（HTTPS）」で接続する設定です。SSH鍵を作らなくてもGitの操作ができます。

> 例外：会社用・個人用のGitHubアカウントを1台のパソコンで使い分けたい場合のみ、SSH鍵が必要になります。その場合は[`githubのSSH鍵作成手順.md`](githubのSSH鍵作成手順.md)を参照してください。

### PostgreSQLをパソコンへ直接インストール 【不要】

データベースはDocker Desktopの中で動かす設計です。パソコンに直接インストールする必要はありません。
